# 위상 60초 모델 (phase60)

> 상태: **EXPERIMENTAL** — 실행 코드와 체크포인트가 있으나 공식 pipeline 이 아니다.
> 실시간 경로(`realtime/`)는 모델 담당의 배포 체크포인트(`model_train/robust/model.pt`)를 쓴다.

60초 창의 **위상 잔차**로 `empty` / `static` / `motion` 을 가리는 3-class 모델이다. 배포
모델이 **진폭 30초**를 쓰는 것과 대비되는 구성이며, 둘 중 무엇을 쓸지는 모델 담당과 협의할
사안이다. 근거 비교는 [1D-CNN 파일럿 교차검증 보고서](../docs/model-training/archive/cnn1d-pilot-cv-report.md)와
[실시간 상태 판단](../../doc/realtime-inference.md) §2 에 있다.

## 체크포인트

| 파일 | 창 | 조정(9/19) | 봉인(9/20) | 최소 감지 사건 | 전환 지연 | 시퀀스 |
|---|---|---:|---:|---:|---:|---:|
| **`model_15sessions_v3.pt`** | **60초 10Hz** | 0.958 · 29/30 | **0.959 · 29/30** | 45초 | 31~34초 | **0.697** |
| `model_15sessions_v2.pt` | 90초 10Hz | **0.967** · 29/30 | **0.981** · 29/30 | 60초 | 59초 | 0.481 |
| `model_15sessions.pt` | 60초 5Hz | (60세션 0.948 · 58/60) | | **20초** | 32~33초 | 0.654 |
| `model_15sessions_30s.pt` | 30초 10Hz | 0.923 · 29/30 | — | 미감지 | 12~24초 | 0.728 |
| `model_60sessions.pt` | 60초 5Hz · 60세션 학습 | (15세션 0.877 · 14/15) | | — | — | — |

학습은 모두 9/16·17 15세션이다(`model_60sessions.pt` 만 9/19·20 60세션).

**쓰임이 갈린다.** 세 지표가 서로 맞바뀐다.

- **정확도만 보면 v2(90초).** 봉인 평가 0.981 로 가장 높다. 대신 60초 미만 사건을 못 보고
  전환 지연이 59초다. 상태가 수 분씩 이어지는 쓰임(재실 집계)에 맞다.
- **균형은 v3(60초 10Hz).** 정확도는 v2 보다 0.02 낮지만 전환 지연이 절반이고 90초 구간
  시퀀스 추적이 가장 낫다(0.697). 실시간 화면처럼 상태 변화를 따라가야 하면 이쪽이다.
- **짧은 사건을 봐야 하면 v1(60초 5Hz).** 20초짜리 움직임까지 잡는다. 같은 창인데도
  10Hz(v3)는 45초가 되어야 반응한다 — 시간 해상도를 올리면 긴 패턴에 더 의존하게 되는 것으로 보인다.

참고로 **배포 진폭 모델(창 30초)은 최소 감지 30초, 전환 지연 26초, 90초 구간 시퀀스 0.888**이다.
구간이 창보다 충분히 길면 가장 잘 따라오지만, 60초 구간에서는 0.656 으로 떨어진다.

반응성 수치는 모두 `transition_test.py` 를 같은 조건(90초 구간)으로 돌린 값이며, 한계는
아래 "반응성" 절에 적었다.

## 쓰는 법

```bash
# 체크포인트와 성능 보기
python model_train/phase60/predict.py --list

# 세션 하나 판단 (기본 모델 = model_15sessions_v3.pt)
python model_train/phase60/predict.py --session-dir mac_collector_output/raw/20260919/153454_empty_s1

# 모델 지정, 창 단위 득표까지
python model_train/phase60/predict.py --session-dir <세션> \
  --model model_train/phase60/model_60sessions.pt --details

# 봉인해 둔 날짜로 한 번만 평가 (학습 날짜가 섞이면 거부한다)
python model_train/phase60/evaluate.py --model model_train/phase60/model_15sessions_v2.pt \
  --dates 20260920 --tag holdout
```

세션의 `label` 은 읽지 않는다. 보드 식별자만 쓰므로 평가에 정답이 새지 않는다.

## 다시 학습하려면

```bash
python model_train/phase60/train.py --name 15sessions \
  --train 20260916 20260917 --eval 20260919 20260920
python model_train/phase60/train.py --name 60sessions \
  --train 20260919 20260920 --eval 20260916 20260917 --train-stride 60
python model_train/phase60/train.py --name 15sessions_v2 \
  --train 20260916 20260917 --eval 20260919 --window 9000 --downsample 10
python model_train/phase60/train.py --name 15sessions_v3 \
  --train 20260916 20260917 --eval 20260919 --window 6000 --downsample 10
python model_train/phase60/train.py --name 15sessions_30s \
  --train 20260916 20260917 --eval 20260919 --window 3000 --downsample 10

# 반응성 측정 (학습 불필요)
python model_train/phase60/transition_test.py --model model_train/phase60/model_15sessions_v3.pt
```

학습이 끝나면 평가까지 자동으로 하고 그 숫자를 체크포인트 안에 넣는다. 15세션은 약 27분,
60세션은 약 49분 걸린다(Apple MPS, seed 3개).

`cache/` 에는 세션별 위상 잔차가 쌓인다(세션당 약 35MB). git 에 올리지 않으며 지워도 된다 —
다음 실행에서 다시 만든다.

## 입력 계약

체크포인트를 열 때 아래가 다르면 **거부**한다. 잘못된 입력으로 돌려 조용히 틀리는 것을 막는다.

| 항목 | 값 |
|---|---|
| `feature_version` | `phase-residual-ls-v1` |
| `mode` | `P` (위상) |
| 창 / 판단 간격 | 체크포인트의 `window_frames` / `stride_frames` (v3 는 6000 = 60초 / 300 = 3초) |
| 다운샘플 | 체크포인트의 `downsample` (v3 는 10 = 10Hz, 600 step) |
| RX 순서 | `[101, 102, 103]` |
| raw 톤 순서 | `[38..63, 1..26]` — 52톤 × RX 3 = **156열** |
| 정규화 | 창 평균 차감만 |
| 앙상블 | seed 0·1·2 의 softmax 평균 |

위상 처리는 `features.py` 한 곳에 있고 학습·추론이 같은 함수를 쓴다. 주파수축으로 unwrap 한
뒤 직선 성분(상수 = CFO, 기울기 = 심볼 타이밍 오프셋)을 최소자승으로 뺀 잔차가 입력이다.

## 개선 기록 1 — 창을 늘리는 쪽 (2026-10-02 새벽)

v1(창 60초 5Hz)을 기준으로 6가지를 **하나씩만** 바꿔 9/19 30세션에서 비교했다.

| 바꾼 것 | 창 정답률 | 빈 방 | 정지 | 판정 |
|---|---:|---:|---:|---|
| **10Hz + 창 90초 (= v2)** | **0.9667** | **1.000** | **0.900** | 채택 |
| 10Hz (5Hz → 10Hz) | 0.9584 | 0.983 | 0.893 | 개선 |
| 창 90초 | 0.9545 | 1.000 | 0.863 | 차이 없음 |
| — 기준선 v1 | 0.9531 | 0.988 | 0.872 | — |
| 시간 차분 채널 | 0.9411 | 0.974 | 0.849 | 악화 |
| 증강(시간 뒤집기·게인 흔들기) | 0.9353 | 0.932 | 0.874 | 악화 |
| 정지 가중치 1.5 + 라벨 스무딩 | 0.9139 | 0.988 | 0.754 | 악화 |

- **시간 해상도가 가장 중요했다.** 0.2초 평균으로 뭉개면 정지 상태를 가리는 단서가 사라진다.
- **증강은 위상에 맞지 않는다.** 게인 흔들기는 진폭용 기법이고, 이미 상대값인 위상 잔차는
  곱셈 잡음에 왜곡되기만 한다.
- **정지 가중치는 역효과다.** 정지를 과하게 예측해 다른 클래스를 잃었다.

## 개선 기록 2 — 창을 줄이는 쪽 (2026-10-02 낮)

반응 지연을 줄이려면 창이 짧아야 한다. **창 30초에서 60초·90초만큼의 정확도를 낼 수 있는가**를
9가지로 시험했다. 전부 같은 조건(9/16·17 학습, 9/19 평가)이다.

| 설정 | 창 | 창 정답률 | 비고 |
|---|---|---:|---|
| 10Hz | 90초 | **0.9667** | 가장 높음 (= v2) |
| 10Hz | 60초 | **0.9584** | 반응성까지 보면 최선 (= v3) |
| 10Hz + 스펙트럼 | 60초 | 0.9407 | 악화 |
| 10Hz | **30초** | **0.9233** | 30초에서 가장 높음 |
| 인코더 폭 ×1.5 | 30초 | 0.9226 | 차이 없음 |
| 20Hz | 30초 | 0.9216 | 차이 없음 |
| 20 epoch | 30초 | 0.9021 | 과적합 |
| 다운샘플 표준편차 추가 | 30초 | 0.8989 | 악화 |
| 호흡 대역 스펙트럼 추가 | 30초 | 0.8662 | 악화 |
| 호흡 대역 스펙트럼만 | 30초 | 0.8320 | 악화 |
| RX별 묶음 | 30초 | 0.7615 | **크게 악화** |

**결론: 창 30초의 손해(약 0.035)는 구조·해상도·학습량·주파수 특징 어느 것으로도 메워지지
않았다.** 창 길이가 지배적인 변수다. 정지와 빈 방을 가르는 신호는 긴 맥락에서만 드러난다.

두 가지가 특히 분명했다.

- **RX별로 따로 요약하면 무너진다**(0.76, 사람 있음/없음 24/30). RX 를 구분하는 순간 모델이
  배치 지문을 쓸 수 있게 되고, 처음 보는 배치에서 바로 틀린다. 모든 시계열에 **같은 가중치**를
  쓰는 지금 구조가 일반화의 핵심이라는 반증이다.
- **호흡 대역을 직접 떠먹여도 소용없다.** 0.05~1Hz 로그 스펙트럼을 더하거나 그것만 쓰면
  오히려 나빠진다. 모델이 시간 축에서 이미 그 정보를 쓰고 있고, 묶음을 나누면 용량만 쪼개진다.

## 반응성 (2026-10-02 · 10-12 실측)

`transition_test.py` 로 **상태가 몇 초 이어져야 판단이 바뀌는지**와 **전환 지연**을 잰다.
한 상태 안에 다른 상태를 길이를 바꿔 끼우고, 끼운 구간과 겹치는 창만 본다. 같은 위치에서
끼우지 않았을 때와 비교해 기준(0.7)을 넘고 동시에 0.2 이상 올라야 감지로 센다.

### 동작별 유지 시간

| 모델 | 창 | 움직임 | 정지 | 빈 방 |
|---|---|---:|---:|---:|
| 배포 진폭 (`robust/model.pt`) | 30초 | **30초** | 측정 불가 | 측정 불가 |
| 위상 30초 | 30초 10Hz | 미감지 ※ | 측정 불가 | 측정 불가 |
| 위상 v1 | 60초 5Hz | **20초** | 측정 불가 | 측정 불가 |
| 위상 v3 | 60초 10Hz | **45초** | 측정 불가 | 측정 불가 |

**정지·빈 방은 이 방법으로 잴 수 없다.** 대조군(바탕과 **같은 클래스의 다른 세션**을 끼움)이
먼저 반응한다 — 행동이 아니라 이어 붙인 경계의 불연속을 잰 값이다. 네 모델 모두 같았다.
빈 방 안에 다른 빈 방을 5초 끼웠더니 배포 모델이 0.918 로 "정지"라고 했다. 실제 환경 급변
(문·가구 이동)에도 같은 오탐이 나는지는 전환 세션을 수집해야 가른다.

※ 위상 30초 모델은 바탕으로 쓴 정지 세션을 이미 0.981 로 움직임이라 보고 있어 상승을 잴 수
없었다. 그 모델의 유지 정확도가 가장 낮은 것(0.9233)과 같은 맥락이다.

### 전환 지연과 시퀀스 추종

| 모델 | 창 | 전환 지연 | 90초 구간 시퀀스 | 30초 대본 (5구간) |
|---|---|---:|---:|---:|
| 배포 진폭 | 30초 | 3~27초 | 0.901 | **2/5** |
| 위상 30초 | 30초 10Hz | **12~24초** | 0.728 | **2/5** |
| 위상 v1 | 60초 5Hz | 33초 | 0.662 | 1/5 |
| 위상 v3 | 60초 10Hz | 33~36초 | 0.690 | 1/5 |
| 위상 v2 | 90초 10Hz | 36~60초 | 0.481 | — |

**반응성을 가르는 것은 입력이 아니라 창 길이다.** 창 30초면 진폭이든 위상이든 30초 대본에서
2/5, 창 60초면 둘 다 1/5이다. 같은 30초 창에서 비교하면 전환 지연은 위상이 조금 빠르지만
(12~24초 대 3~27초) 유지 정확도는 60초 모델보다 낮다.

측정의 한계: 다른 세션에서 잘라 붙인 것이라 사람이 실제로 움직여 생기는 연속 변화와 다르다.
움직임 수치는 대조군이 깨끗해 **창 길이로 인한 희석**을 제대로 쟀다고 본다. 실제 지연은
전환 세션을 수집해야 확정된다 ([트러블슈팅](../../doc/troubleshooting/06-measurement-pitfalls.md)
2026-10-12 두 항목).

## 앙상블은 쓰지 않는다 (2026-10-12)

여러 모델의 세션 평균 확률을 평균해 봤다 (`model_train/analysis/ensemble_test.py` — 학습
불필요, 어느 모델이든 학습 날짜가 평가 날짜에 섞이면 거부한다).

| 평가 | 개별 | 합친 결과 |
|---|---|---|
| v1 + v3 + v2 → 9/19 30세션 | 셋 다 29/30 | **모든 조합 29/30** |
| 배포 진폭(30초) + `model_60sessions` → 9/16·17 15세션 | 12/15 · 14/15 | **14/15** |

이득이 없을 뿐 아니라 **오류가 겹친다.** 창 길이가 2~3배 다른 위상 모델 셋이 똑같은 한
세션(9/19 s12)에서만 틀리고, 진폭·위상 쌍도 더 나은 쪽의 유일한 오답(s33)을 공유한다. 오답이
모델 분산이 아니라 **세션 자체**에서 나온다는 뜻이라 평균·투표로는 고쳐지지 않는다. 특징 수준
결합(진폭+위상 한 입력)은 이미 나빠진다고 측정돼 있다(파일럿 사이클 8 — 진폭이 배치 지문을
다시 들여온다).

창 길이 9종·특징 11종·결합 2종이 모두 실패했다. **정확도는 데이터로 올려야 한다** — 전환
세션과 다른 피험자([realtime-inference.md](../../doc/realtime-inference.md) §6·§7).

## 한계

- **전환 구간과 장시간 운영은 검증하지 않았다.** 모든 평가 세션이 5분 동안 상태 하나만 담고 있다.
- **피험자 1명, 단일 방**이다. 방·사람 일반화는 주장하지 않는다.
- 15세션 모델은 학습 데이터가 적다. 60세션 모델이 더 많은 조건(배치 3주기, 서 있는 자세 등)을 봤다.
- **짧은 사건은 보고되지 않는다.** v3 기준 20초 미만 움직임은 창 안에서 희석된다. 활동량을
  재야 한다면 짧은 창 모델이 따로 필요하다 ([realtime-inference.md](../../doc/realtime-inference.md) §4).
- softmax 는 확률 보정을 거치지 않았다. 0.9 가 "90% 확률로 맞다"는 뜻이 아니다.
- 공식 전처리(`preprocess_3rx.py`)와 JSONL 은 진폭만 다룬다. 이 모델은 `.csi` 의 raw I/Q 를
  직접 읽으므로 공식 pipeline 에 넣으려면 [data-schema.md](../../doc/data-schema.md) 변경이 선행되어야 한다.
