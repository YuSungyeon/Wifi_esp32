# 진폭·위상 기반 3클래스 분류 실험 결과

> 상태: **SUPPORTING ANALYSIS — 9회 학습·최종 test 완료**
> 실행일: 2026-09-24 · 수집일: 2026-09-19·20
> 설계: [진폭·위상 분류 실험 설계](amplitude-phase-classification-design.md)
> 로컬 산출물: `model_train/analysis/output/20260924-phase-ablation/`

## 1. 결론

**진폭+위상(AP)은 진폭(A)보다 평균 session macro F1이 0.0512 높았지만,
empty–static 구분 문제는 해결하지 못했다. 위상 단독(P)은 가장 낮았다.**

| 입력 | Test session macro F1 평균 ± 표본 표준편차 | Test session accuracy 평균 | Test window macro F1 평균 |
|---|---:|---:|---:|
| A: 진폭 | 0.3258 ± 0.0785 | 35.56% | 0.3174 |
| P: 보정 위상 | 0.2063 ± 0.0678 | 23.33% | 0.2130 |
| AP: 진폭+보정 위상 | 0.3770 ± 0.0195 | 41.11% | 0.3366 |

각 행은 같은 test 30세션을 seed 0·1·2로 평가한 값의 평균이다. 표준편차는 seed 간
차이이며 여러 날짜·방에 대한 신뢰구간이 아니다. 서로 다른 90세션을 시험한 것도 아니다.

AP−A의 session macro F1 차이는 seed별 `−0.0596, +0.1258, +0.0875`다.
3개 중 2개 seed에서 개선됐지만, empty↔static 오분류는 평균 5.00건에서 5.33건으로
늘었다. 따라서 설계의 **평균 성능 개선 + 2/3 seed 개선 + empty↔static 오류 감소**
조건을 모두 충족하지 못했다. 이번 결과만으로 위상 결합을 최종 모델로 채택하지 않는다.

## 2. 실제 실행 조건

| 항목 | 실행값 |
|---|---|
| 모델 | 기존 `CNN1DClassifier` |
| 구조 | 시간축 Conv 3개, 채널 32/64/64, 커널 5/5/3, dropout 0.2 |
| 파라미터 | A/P/AP 모두 96,483개 |
| 입력 | `(batch, 300, 459)`; 진폭 153 + sin 위상 153 + cos 위상 153 |
| A/P 분리 | 정규화 후 사용하지 않는 모달리티 자리를 0으로 처리 |
| 서브캐리어 | RX당 51개: 원본 인덱스 38~63 → 2~26 |
| 위상 처리 | 허수·실수 순서 수정 → 두 연속 주파수 구간별 unwrap·최소제곱 직선 제거 → sin/cos |
| gap 처리 | 최대 5프레임; 위상 양 끝 차이가 어느 위치든 90° 이상이면 보간하지 않음 |
| 윈도우 | 300프레임, stride 30프레임; 100Hz 가정에서 3초/0.3초 |
| 정규화 | 공통 train 윈도우의 진폭 평균·표준편차; 위상 sin/cos 그대로 사용 |
| 학습 | Adam, lr 0.001, batch 32, class weight 없음 |
| 종료·선택 | 최대 50 epoch, patience 5; validation window macro F1 최대 checkpoint |
| 반복 | seed 0·1·2 × A/P/AP = 9회 |
| 장치 | Apple MPS, PyTorch 2.8.0, NumPy 2.0.2, Python 3.9.6 |
| 시간 | 9회 학습 합계 501.3초, 약 8분 21초; 전처리·test 시간 제외 |

같은 seed의 A/P/AP는 모델 초기 가중치 hash와 train 윈도우 목록 hash가 같음을
확인했다. 실제 입력 정보 수는 다르므로, 전체 파라미터 수가 같다고 활성 입력 연결
수까지 같다는 뜻은 아니다.

기존 192차원 공식 학습 CLI 대신 [별도 실험 runner](../../analysis/run_phase_experiment.py)를
사용하고, 기존 모델·학습·평가 함수를 재사용했다. 데이터는 세션별 배열과 윈도우
시작 위치로 저장해 중첩 부분의 디스크 복제를 줄였다.
[입력 계약 결정](../../../doc/adr-csi-phase-experiment.md)

기존 `cv_pilot.py`의 9/16·17 위상 파일럿과는 데이터, 모델, 윈도우와 위상 처리가
다르다. 그 파일럿의 결과나 캐시는 이번 비교에 섞지 않았다.

## 3. 세션 분할과 실제 사용량

| Split | 대상 | 세션 수 | 클래스별 세션 수 | 진폭 사용 가능 윈도우 | 공통 비교 윈도우 |
|---|---|---:|---:|---:|---:|
| train | 9/19 s1~s24, 기록된 RX 배치 P1 | 24 | 각 8 | 23,782 | 16,233 |
| validation | 9/19 s25~s30, P2 | 6 | 각 2 | 5,945 | 5,520 |
| test | 9/20 s31~s60, P2·P3 | 30 | 각 10 | 29,582 | 24,509 |
| 합계 | 60세션 | 60 | 각 20 | 59,309 | 46,262 |

모든 세션에서 공통 윈도우가 1개 이상 남았다. 한 세션을 여러 split으로 나누지 않았다.
위상 품질 규칙은 train·validation 진단 후에도 설계값 그대로 유지했고, 동일 규칙을
test에 적용했다. 9회 학습의 checkpoint를 모두 선택한 뒤 test 예측을 계산했다.

다만 **세션 수가 같아도 남은 데이터 양은 클래스별로 크게 달랐다.**

| Split | 클래스 | 공통 / 진폭 윈도우 | 유지율 |
|---|---|---:|---:|
| train | empty | 7,654 / 7,928 | 96.54% |
| train | static | 5,888 / 7,927 | 74.28% |
| train | motion | 2,691 / 7,927 | 33.95% |
| validation | empty | 1,981 / 1,981 | 100.00% |
| validation | static | 1,972 / 1,982 | 99.50% |
| validation | motion | 1,567 / 1,982 | 79.06% |
| test | empty | 9,735 / 9,868 | 98.65% |
| test | static | 8,694 / 9,805 | 88.67% |
| test | motion | 6,080 / 9,909 | 61.36% |

A/P/AP를 같은 공통 윈도우로 비교했으므로 입력 간 표본은 일치한다. 그러나 이 표본이
원래 수집한 상황 전체를 대표한다고 볼 수는 없다. class weight를 사후에 추가하거나
보간 기준을 느슨하게 바꿔 이번 test 결과를 다시 높이는 작업은 하지 않았다.

## 4. 원본·위상 품질 확인

180개 `.csi` 파일의 **5,285,143프레임 CRC가 모두 통과**했다. 파일 길이·v4 헤더·RX ID도
검사했다. RF 값은 모든 파일에서 `channel=11`, `rate=11`, `sig_len=47`, `raw_len=128`이었다.
명시적 boot ID 변화는 0건이며, 기존 순번 규칙에 따라 단일 손상 후보 레코드 5개를 제외했다.
CRC 통과는 위상 품질까지 보장하는 것은 아니다.

선택 구간의 고유 RX 프레임 기준으로, 51개 위치 중 진폭 0이 하나라도 있었던 프레임은
38,142개였다. 설계에 따라 해당 RX 패킷의 위상을 계산 불가로 처리했다.
위상 gap 중 양 끝 각도 차이로 보간을 거절한 구간은 6,203개, 길이가 5프레임을 초과한
구간은 378개였다. 여기서 gap은 RX별 누락 구간 수이며 제외 윈도우 수와 다르다.

| 영향이 큰 세션 | 클래스 | 공통 / 진폭 윈도우 | 유지율 |
|---|---|---:|---:|
| 9/19 s19 | motion | 5 / 990 | 0.51% |
| 9/19 s20 | motion | 36 / 991 | 3.63% |
| 9/19 s6 | motion | 58 / 991 | 5.85% |
| 9/19 s5 | motion | 102 / 991 | 10.29% |
| 9/19 s18 | static | 154 / 991 | 15.54% |
| 9/19 s4 | static | 174 / 991 | 17.56% |

s19 RX101에서는 고유 29,451프레임 중 2,616개가 진폭 0 위치를 포함했고, 각도 차이로
거절한 gap은 911개였다. 이 세션의 남은 5개 윈도우가 사용하는 **중복 제외 시간은
6.9초**였다. s20은 35.1초였다. 수집 자체가 그만큼 짧았다는 뜻은 아니다.

진단 그래프는 train·validation의 세션별 `rx101-phase.png` 등으로 저장했다. 주파수
방향 직선 성분이 제거되고 시간 방향 변동이 남는 것은 확인했지만, 남은 변화가
모두 사람의 움직임이고 제거된 변화가 모두 장비 오차라고 검증한 것은 아니다.

| P | 2 | 9 / 4 | 0.9943 | 0.1800 | 0.1905 | 0.2074 |

학습 세션에 잘 맞고 다른 세션에서 무너지는 과적합·일반화 부족의 양상이다.
다만 가구, RX 배치, 수집 시각, 전자기기 등 중 무엇이 주원인인지는 이 비교만으로
분리해 증명하지 못했다.

## 6. 무엇이 좋아졌고, 무엇이 남았는가

| 입력 | empty recall 평균 | static recall 평균 | motion recall 평균 | empty↔static 오분류 평균 |
|---|---:|---:|---:|---:|
| A | 13.33% | 60.00% | 33.33% | 5.00 / 30세션 |
| P | 46.67% | 6.67% | 16.67% | 9.00 / 30세션 |
| AP | 13.33% | 63.33% | 46.67% | 5.33 / 30세션 |

AP의 개선은 주로 motion recall에서 나타났다. **empty recall은 그대로 13.33%**다.
empty를 static으로 분류한 횟수도 줄지 않았다. 위상 단독은 empty recall이 높아졌지만
static·motion을 많이 놓쳐 전체 성능이 낮았다.

아래 혼동행렬은 동일한 30세션의 **3 seed 예측을 합한 90건**이다. 행은 실제,
열은 예측이며 순서는 `empty, static, motion`이다. 각 행의 30은 서로 다른
30개 해당 클래스 세션이 아니라 해당 클래스 10세션 × 3 seed다.

```text
A                       P                       AP
             E   S   M               E   S   M               E   S   M
empty        4  15  11   empty       14   8   8   empty        4  16  10
static       0  18  12   static      19   2   9   static       0  19  11
motion       2  18  10   motion       8  17   5   motion       2  14  14
```

AP에서 모든 seed가 틀린 세션은 다음과 같다. 모두 9/20 데이터다.

- empty: s45, s46, s48, s49, s50, s57, s59, s60.
- static: s41, s42, s44.
- motion: s31, s32, s35.

배치별 평균 session macro F1도 분리했다. P2는 12세션(클래스별 4), P3는
18세션(클래스별 6)이다. 배치번호가 같다고 가구·사람·전자기기 조건까지 같지는 않다.

| 입력 | Test P2 | Test P3 |
|---|---:|---:|
| A | 0.2202 | 0.3526 |
| P | 0.2018 | 0.2115 |
| AP | 0.2548 | 0.4476 |

validation에서 P2를 봤어도 다음 날짜의 P2 test 성능은 낮다. RX 위치 하나로
성능 차이를 설명할 수 없다는 관측이며, 환경 요인의 원인을 확정한 것은 아니다.

## 7. 진폭 전체 test 윈도우와 비교

A checkpoint를 공통 24,509개 대신 진폭만으로 가능한 test 29,582개 전체에도 평가했다.
이는 **공통 train으로 학습한 같은 모델의 평가 범위만 넓힌 결과**다. 진폭 전체 train으로
새로 학습한 모델의 성능은 아니다.

| seed | A 공통 test session F1 | A 진폭 전체 test session F1 |
|---:|---:|---:|
| 0 | 0.4141 | 0.4141 |
| 1 | 0.2637 | 0.2259 |
| 2 | 0.2997 | 0.2670 |

남기는 윈도우에 따라 세션 예측도 바뀐다. 따라서 공통 윈도우 비교의 AP 점수를
원래 모든 수집 구간을 사용하는 실서비스 성능으로 해석하지 않는다.

## 8. 환경 사진 반영

사용자 설명에 따라 `image/`를 RX 배치·실험 환경 기록으로 등록했다.
57세션에서 사진 167개를 확인하고 경로·hash를 inventory에 저장했다.
사진이 없는 세션은 **9/19 s1, s5, s6**이었다. 사진 누락만으로 CSI를 제외하지 않았다.

모델에는 사진, 파일명, 배치번호, 수집 시각과 환경 메모를 입력하지 않았다.
라벨은 각 세션의 `session.json`에서 읽었다.

직접 확인한 환경 사진 예시는 다음과 같다. 167개 전체를 시각적으로 검토한 것은 아니다.

| 사진 | 관찰 |
|---|---|
| `20260919/203923_empty_s22/image/env.jpeg` | 가운데 책상 주변의 좌·우 의자가 보이며, 왼쪽 의자에 가방이 있다. |
| `20260919/215648_empty_s29/image/env.jpeg` | 가운데 책상 뒤·아래에 의자가 모여 있으며, s22 사진과 의자 배치가 다르다. |

사진은 환경 차이를 확인하는 근거가 된다. 다만 이 두 사진의 차이가 특정 예측 오류의
원인이라고 결론 내리거나, 사진에 보이지 않는 휴대폰 사용 여부 등을 추정하지 않는다.

## 9. 검증·산출물·재현

- 새 단위 테스트 11개, 기존 전처리 테스트 26개와 CNN 테스트 3개 통과.
- 9개 checkpoint가 validation window macro F1 최대 epoch인지 재검산했다.
- test 예측 **24,509 × 9 = 220,581행**의 윈도우 순서·정답·확률 합·argmax를 확인했다.
- 저장 확률에서 날짜+세션별 예측을 다시 계산해 보고된 session 지표와 일치함을 확인했다.
- 원본 파일 hash, 실제 실행 소스 복사본, 미커밋 변경 patch, 설정·가중치 hash를 보존했다.

핵심 파일:

| 경로 | 내용 |
|---|---|
| `inventory.json` | 원본·환경 사진 목록과 hash |
| `manifest.json`, `split.json`, `phase-quality.json` | 입력·분할·정규화·제외 사유 |
| `sessions/<날짜-s번호>/` | 정렬 배열, 공통/진폭 윈도우 시작 위치, 진단 PNG |
| `runs/<A\|P\|AP>-seed<0\|1\|2>/` | 소스·설정·history·checkpoint·validation/test 확률 |
| `comparison.json`, `verified-summary.json` | 최종 지표와 재검증 결과 |
| `report.md` | 자동 생성한 seed별 지표 및 60세션의 윈도우 유지율 |

위 경로의 기준은 `model_train/analysis/output/20260924-phase-ablation/`이다.
이 디렉터리는 기존 저장소 규칙에 따라 Git에서 제외되는 로컬 산출물이다.

새 결과 디렉터리로 재실행할 때 다음 순서를 사용한다. 기존 결과 경로는 전처리가
덮어쓰지 않는다. development 진단 후 품질 규칙을 바꾸면 이번 결과와 다른 실험으로
기록하고, test 확인 이후 바꾼 규칙의 최종 평가는 새 데이터로 진행한다.

```bash
RUN_DIR=model_train/analysis/output/phase-reproduction
.venv/bin/python model_train/analysis/prepare_phase_experiment.py --output "$RUN_DIR" --stage development
.venv/bin/python model_train/analysis/run_phase_experiment.py validate --dataset "$RUN_DIR"
.venv/bin/python model_train/analysis/prepare_phase_experiment.py --output "$RUN_DIR" --stage test
.venv/bin/python model_train/analysis/run_phase_experiment.py train --dataset "$RUN_DIR" --device mps
.venv/bin/python model_train/analysis/run_phase_experiment.py test --dataset "$RUN_DIR" --device mps
.venv/bin/python model_train/analysis/summarize_phase_experiment.py --dataset "$RUN_DIR"
```

환경 버전과 실측 변동도 함께 기록한다.

## 10. 후속 작업

1. **위상 품질 규칙의 표본 손실부터 재검토한다.** 51개 중 하나의 진폭 0만으로 RX
   패킷 전체를 버리는 현재 규칙이 motion을 많이 제외했다. 위치별 유효성 표시 등
   대안은 train·validation에서 별도 비교하고, 이번 test 점수를 보고 임계값을 맞추지 않는다.
2. **empty 오분류와 환경 조건을 대조한다.** 계속 틀리는 empty 세션의 사진·메모와
   CSI를 함께 확인한다. 배치번호는 RX 위치로만 사용하고 가구 조건은 따로 기록한다.
3. **검증 조건을 늘린다.** validation은 클래스별 2세션뿐이다. 같은 환경에서 세 클래스를
   짝지어 수집하고 여러 날짜·RX 배치에서 검증할 데이터를 확보한다. 최종 확인에는 새 날짜를 쓴다.

이번 실험의 결론은 “현재 보정·선별·CNN 조건에서 위상 결합은 평균 지표를 조금
높였지만, 충분한 일반화 성능이나 empty–static 개선은 확인하지 못했다”이다.
