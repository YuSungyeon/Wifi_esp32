# 쉽게 읽는 3분류 모델 실험 설계

> 상태: **SUPPORTING ANALYSIS — 완료된 실험 설계를 쉽게 풀어쓴 문서**
> 정확한 설정과 판정 기준은 [원래 설계 문서](robust-three-class-design.md)가 기준이다.
> 실제로 나온 결과는 [쉬운 결과 설명](robust-three-class-report-easy.md)에 있다.

이 문서는 **실험을 시작할 때 무엇을 비교하고, 어떻게 합격 여부를 판단하기로
했는지** 설명한다. 아래 방법이 가장 좋다는 결과를 미리 주장하는 문서는 아니다.

## 무엇을 알아보려고 했나

모델은 방의 상태를 세 가지 중 하나로 고른다.

- `empty`: 사람이 없음
- `static`: 사람이 있지만 가만히 있음
- `motion`: 사람이 움직임

앞선 3초 모델은 다른 날짜의 자료에서 특히 `empty`와 `static`을 잘 구분하지
못했다. 그래서 한 번에 보는 시간을 늘리고, 신호의 절대 크기보다 **시간에 따른
변화**를 보게 하면 나아지는지 시험하기로 했다. 단순히 학습 자료를 외운 모델이
아닌지도 날짜와 수신기 배치를 바꿔 확인하기로 했다.

## 어떤 자료를 썼나

9월 19일과 20일에 수집한 **60세션**을 썼다. 하루에 30세션씩 있고,
각 날짜에는 세 상태가 각각 10세션씩 있다. 한 세션은 하나의 상태로 기록된
약 5분짜리 수집이다. 각 세션에는 수신기 3대의 신호가 있다.

세션을 30초짜리 **윈도**로 잘라 모델에 넣는다. 예를 들어 30초 윈도를
15초씩 옮기면 `0~30초`, `15~45초`, `30~60초`처럼 서로 겹친다.
**윈도가 1,000개여도 독립적인 수집 1,000번은 아니다.** 같은 세션에서 나온
윈도는 함께 학습하거나 함께 평가한다. 한 세션의 윈도를 양쪽에 섞지 않는다.

모델 입력에는 신호만 쓴다. 날짜, 세션 번호, 파일명, 사진, 수신기 배치 정보,
정답 이름을 입력으로 주지 않는다. 정답 이름은 예측과 비교해 학습하거나 점수를
계산할 때만 쓴다.

## 무엇을 비교하기로 했나

1. **보는 시간:** 3·5·10·20·30초 윈도. 각 길이에서 윈도 길이의 절반만큼
   옮긴다. 예를 들어 30초 윈도는 15초 간격이다.
2. **신호 종류:** 진폭만(A), 위상만(P), 둘 다(AP). 최종 선택이 정해지기
   전에는 세 가지 모두 후보였다.
3. **판단 방법:** 신호의 요약값을 계산해 사용하는 기존 분류기들과, 신호의
   시간 흐름을 직접 읽는 작은 CNN을 비교한다. 기존 분류기 조합은 180개,
   CNN 조합은 `10/30초 × A/P/AP`의 6개를 시험한다.

CNN은 수신기마다 고른 신호 17개, 총 51개에 **같은 시간 검사기**를 반복해
적용한다. 실제 신호를 어떻게 300개 시간값으로 바꾸는지는
[전체 흐름 설명](robust-three-class-pipeline.md)을 보면 된다.

## 학습과 평가를 어떻게 나누기로 했나

| 단계 | 학습에 쓰는 세션 | 점수를 확인하는 세션 | 이유 |
|---|---|---|---|
| 후보 고르기 | 9/19의 24개 | 9/19의 6개 | 나누는 조합을 5번 바꿔 후보 비교 |
| 날짜 확인 1 | 9/19의 30개 | 9/20의 30개 | 다른 날짜에서도 맞는지 확인 |
| 날짜 확인 2 | 9/20의 30개 | 9/19의 30개 | 학습·평가 방향을 바꿔 확인 |
| 배치 확인 | 나머지 세션 | P1·P2·P3 중 한 배치 전체 | 특정 수신기 배치만 외웠는지 확인 |

처음 후보를 고르는 5번의 분할에서는 각 상태의 세션 2개씩, 총 6개를 평가에
놓는다. 남은 24개가 그 차례의 학습 자료다. 모든 후보를 이 같은 방식으로
비교한다. 평가용 세션의 답을 모델에 알려주지 않는다.

다만 9/19는 **처음 후보를 고를 때 이미 살펴본 날짜**다. 따라서 표의
“날짜 확인 2”는 새로운 날짜를 처음 본 독립 테스트가 아니다. 이 선택 영향을
더 확인하려고, 평가할 날짜나 배치를 먼저 숨기고 **나머지 학습 세션 안에서만**
후보를 다시 고르는 검증도 별도로 하기로 했다. 이것을 원래 문서에서는
“중첩 검증”이라고 부른다.

## 무엇을 합격으로 보기로 했나

실험 후 점수에 맞춰 기준을 바꾸지 않도록, 다음을 먼저 정했다.

- 날짜를 바꾼 양쪽 평가에서 약 5분 세션의 **macro F1이 각각 0.80 이상**.
- 세 상태 중 어느 하나도 심하게 놓치지 않도록, 각 상태의 **재현율이
  각각 0.70 이상**.
- 날짜를 바꾼 평가에서 30초 윈도 하나하나의 **macro F1이 0.75 이상**.
- 수신기 배치 P1·P2·P3를 각각 제외한 평가에서 세션 **macro F1이 0.70 이상**.
- 같은 설정을 시작값만 달리해 세 번 학습해도 세션 점수가 크게 흔들리지 않고,
  원본·정답·분할·계산을 다시 확인했을 때 문제가 없을 것.

**재현율**은 실제로 그 상태였던 것 중 모델이 찾아낸 비율이다. **macro F1**은
세 상태의 분류 성적을 각각 계산한 뒤 똑같이 중요하게 평균한 점수다.
둘 다 1에 가까울수록 좋다. 이 기준을 통과해도 실제 세상에서 100% 맞는다는
뜻은 아니다.

## 최종 파일은 언제 만들기로 했나

위 비교와 검증을 마친 뒤 선택한 방법으로 **60세션 전체를 다시 학습**해
사용 후보 파일을 만든다. 이렇게 하면 저장한 파일은 자료를 최대한 사용하지만,
그 60세션 안에는 더 이상 이 파일만을 위한 미사용 테스트 세션이 남지 않는다.
실제 사용 성능은 **새 날짜·새 조건에서 새로 수집한 세션**으로 확인해야 한다.

이 실험은 기존 공식 192차원 모델을 자동 교체하거나 GUI에 실시간 모델을
연결하는 작업은 아니다. 실제로 무엇이 선택되고 얼마나 맞았는지는
[쉬운 결과 설명](robust-three-class-report-easy.md)으로 이어진다.
