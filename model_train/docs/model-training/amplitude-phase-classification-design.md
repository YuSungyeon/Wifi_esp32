# 진폭·위상 기반 3클래스 분류 실험 설계

> 상태: **PLANNED** — 설계만 작성했으며 위상 진단·전처리·학습은 아직 실행하지 않았다.
> 작성일: 2026-09-23
> 실행 착수: 2026-09-24 — 아래 기준을 고정하고 별도 실험 runner로 구현·검증 중
> 대상: 2026-09-19·20에 수집한 60세션, RX101·102·103, `empty / static / motion`
> 기준: [현재 전처리 계약](../preprocessing/design.md) · [수집 프로토콜](../../../doc/collection-protocol.md)

## 1. 목적과 판단할 질문

기존 진폭 입력에 위상 정보를 추가했을 때, **학습에 사용하지 않은 세션의 3클래스
분류가 좋아지는지** 확인한다. 특히 `empty ↔ static` 오분류가 줄어드는지 본다.

- **진폭**: 각 서브캐리어에서 측정한 신호의 크기.
- **위상**: 각 서브캐리어에서 측정한 신호의 각도.
- **위상 보정**: 장비 오차의 영향을 줄이기 위해 위상의 공통 각도·기울기 등을 제거하는 처리.
- **비교 실험**: 나머지 조건을 맞추고 입력 정보만 바꿔 결과를 비교하는 실험.

위상은 전파 경로 변화에 관한 정보를 추가할 가능성이 있다. 그러나 주변 환경이나
장비 상태도 반영하므로, 위상 추가만으로 과적합이나 세션 간 환경 차이가 해결된다고
가정하지 않는다. 이 실험의 목표는 분류이며 좌표·거리·인체 메시 복원은 포함하지 않는다.

### 2.2. 먼저 해결할 두 가지

**실수·허수 순서.** ESP32-S3 원시 CSI의 바이트 순서는 `허수, 실수`다. 현재
`complex_csi()`는 첫 바이트를 실수로 해석한다. 위상 실험 구현 시 이를 바로잡고
기존 호출부를 확인한다. 두 값을 바꿔도 `sqrt(실수² + 허수²)`는 같으므로, 이 순서
문제로 기존 진폭 계산값이 달라지지는 않는다. [ESP-IDF의 CSI 형식](https://docs.espressif.com/projects/esp-idf/en/v5.2.2/esp32s3/api-guides/wifi.html#wi-fi-channel-state-information)

**첫 4바이트의 유효 여부.** ESP32-S3는 `first_word_invalid`가 참이면 CSI 첫
4바이트가 유효하지 않다. 현재 RX 펌웨어와 저장 헤더는 이 플래그를 보존하지 않아
기존 파일에서 패킷별 참·거짓을 복원할 수 없다. 따라서 이번 실험에서는 첫 두
복소수 위치인 배열 인덱스 `0, 1`을 항상 제외한다. 모든 패킷의 해당 위치가 실제로
손상됐다고 단정하는 것은 아니다. [공식 하드웨어 제약](https://docs.espressif.com/projects/esp-idf/en/v5.2.2/esp32s3/api-guides/wifi.html#wi-fi-channel-state-information)

## 3. 위상 보정 설계 — PLANNED

### 3.1. 처리 단위와 한계

보정은 **RX 한 대가 받은 패킷 한 개 안에서**, 서브캐리어별 위상을 대상으로 한다.
RX101·102·103은 각각 처리한다. 서로 다른 보드의 원시 위상을 직접 빼지 않는다.

같은 `tx_seq`는 같은 송신 패킷이라는 뜻이다. 각 RX의 시계와 위상 기준까지 같다는
뜻은 아니다. Espressif도 위상 활용을 위한 공통 클록 구성을 별도로 설명한다. [Espressif의 공통 클록 구성](https://docs.espressif.com/projects/esp-techpedia/en/latest/esp-friends/solution-introduction/esp-csi/esp-csi-solution.html)

아래의 직선 제거는 장비 오차뿐 아니라 실제 전파 경로의 선형 위상 성분도 제거할
수 있다. 결과를 **복원된 참 위상**이나 **실제 이동 거리**라고 부르지 않는다.

### 3.2. 사용할 서브캐리어와 순서

현재 `LLTF_DATA_IDX`는 배열 인덱스 `1~26, 38~63`의 52개 위치다. §2.2에 따라
인덱스 1을 추가로 제외해 **RX당 51개**를 사용한다. 진폭·위상 비교에 같은 위치를 쓴다.

| 원본 배열 인덱스 | 실제 서브캐리어 번호 k | 사용 |
|---|---|---|
| 0 | 0, DC | 제외 |
| 1 | +1 | 첫 4바이트 유효 여부를 알 수 없어 제외 |
| 2~26 | +2~+26 | 사용, 25개 |
| 27~37 | 가드 영역 | 제외 |
| 38~63 | −26~−1 | 사용, 26개 |

위상 처리는 **원본 배열 인덱스 `38~63 → 2~26`**, 즉 실제 주파수가 증가하는
순서로 한다. 51개 위치를 임의의 `1~51`로 바꿔 직선의 가로축에 넣지 않는다.
ESP32-S3 LLTF의 저장 순서는 공식 문서를 따른다. [서브캐리어 순서](https://docs.espressif.com/projects/esp-idf/en/v5.2.2/esp32s3/api-guides/wifi.html#wi-fi-channel-state-information)

51개 사용은 기존 파일의 제약에 따른 실험 선택이며, 기존 52개 진폭 계약을
일괄 변경하는 결정이 아니다.

### 3.3. 원본에서 진폭·위상 계산

각 RX·패킷·서브캐리어에 대해 다음을 계산한다. 계산 전에 signed int8을 float으로
변환해 제곱 시 정수 범위를 넘지 않게 한다.

```text
실수 I = raw[1::2]
허수 Q = raw[0::2]
복소 CSI H = I + jQ             # j는 제곱하면 −1이 되는 허수 단위
진폭 A = sqrt(I² + Q²)
원시 위상 θ = atan2(Q, I)       # 단위 radian, 약 −π~+π
```

`π radian = 180°`다. 설명에는 도(degree)를 쓰고, 실제 계산·저장에는 radian을 쓴다.
진폭이 0인 위치의 위상은 정의되지 않으므로 정상 위상 0으로 취급하지 않는다.
진폭의 gain 보정 배율은 현재 `amplitude()` 기본값과 같이 적용하지 않는다.

### 3.4. 위상 끊김 연결 — unwrap

`170°, 179°, −175°`처럼 각도 표현의 경계에서 끊긴 값을
`170°, 179°, 185°`처럼 이어 표현한다. **한 패킷의 주파수 방향**으로 수행한다.
전체 세션을 시간 방향으로 이어 붙이는 처리는 초기 실험에 넣지 않는다.

이번 설계는 빠진 DC 주변을 억지로 이어 붙이지 않도록 `k=−26~−1`과
`k=+2~+26`의 **두 연속 구간에서 각각 unwrap**한다. 두 구간 사이의 360° 차이를
추정하지 않는다. 구간 안에서도 인접 위상의 실제 차이가 180° 이상이면 일반적인
unwrap이 잘못 연결할 수 있다. 진폭이 작거나 잡음이 큰 경우를 진단에서 확인한다.

### 3.5. 공통 각도와 기울기 제거

두 구간 **각각**에 대해, unwrap한 위상에 가장 잘 맞는 직선 `a×k+b`를 최소제곱으로
구하고 뺀다. 최소제곱은 측정값과 직선 값의 차이를 제곱해 더한 값이 가장 작아지는
직선을 고르는 방법이다.

```text
보정 위상 ψ[k] = unwrap한 위상 θ[k] − (a × k + b)

k: 실제 서브캐리어 번호
a: 서브캐리어 번호가 1 증가할 때 직선이 올라가는 양
b: 직선 전체의 높이, 즉 공통 각도 성분
```

가로축은 시간이나 세션 번호가 아니라 **서브캐리어 번호**다. 각 RX·패킷·구간마다
새 직선을 계산한다. 초기 방식은 모든 사용 위치에 같은 가중치를 준다.

아래는 계산 설명용으로 서브캐리어 3개만 사용한 예다.

| k | unwrap한 위상 | 직선 값 `10×k+30` | 보정 위상 |
|---:|---:|---:|---:|
| 1 | 42° | 40° | 2° |
| 2 | 46° | 50° | −4° |
| 3 | 62° | 60° | 2° |

주파수 방향의 선형 성분 제거는 PhaseFi 등의 위상 처리에서 사용한 원리를
참고했다. **두 구간에 별도 직선을 적용하는 것은 이 데이터에 대한 본 설계의 선택**이며,
논문의 절차를 그대로 재현한 것은 아니다. 이 방식은 구간 간 상대 각도·기울기
정보도 버리므로, 성능이 나쁘면 그 손실도 원인 후보로 남긴다. [PhaseFi 논문, Phase Sanitization](https://eng.auburn.edu/~szm0001/papers/IoT-0845-2016.final.pdf)

### 3.6. 모델에는 sin·cos로 표현

각 보정 위상에서 `sin(ψ), cos(ψ)` 두 값을 만든다. 같은 각도를 360° 차이로
표현해도 같은 입력이 되며, −180°와 +180°가 서로 먼 값처럼 보이는 문제를 줄인다.
진폭을 곱하지 않아 위상 입력에 진폭 크기를 직접 섞지 않는다.

초기 실험에는 시간 평활화, 시간 미분, RX 간 위상 차, empty 세션을 기준으로 한
차감, 세션별 평균 차감은 넣지 않는다. 효과가 확인된 뒤 각각 별도 비교 대상으로 둔다.

## 4. 누락·품질·윈도우 처리 — PLANNED

### 4.1. 공통 시간 구간

원본을 파일 순서대로 읽고 CRC·헤더·RX 식별을 검사한다. 재부팅·손상 레코드 판정,
정상 구간 선택과 `tx_seq` 정렬은 [현재 전처리 규칙](../preprocessing/design.md)을
재사용한다. 역행한 순번을 정렬해서 정상인 것처럼 만들거나 재부팅 경계를 보간하지 않는다.

기본값은 현재와 같은 공통 구간 27,000프레임 이상, RX별 실제 관측률 0.85 이상,
300프레임 윈도우, stride 30프레임이다. 100Hz 가정에서 각각 3초·0.3초에 해당한다.

### 4.2. 위상 유효성 및 보간

초기 규칙을 다음과 같이 고정하고, 실제 통과율은 구현 후 보고한다.

1. 선택한 51개 중 진폭 0 또는 계산 불능 값이 하나라도 있으면 해당 RX의 패킷을
   위상 계산 불가로 표시한다. 이 엄격한 초기 규칙 때문에 버려지는 비율도 기록한다.
2. 진폭이 작지만 0은 아닌 위치는 진폭 분위수와 위상 변동을 함께 진단한다. 임계값을
   추가한다면 train·validation에서만 정하고 test 평가 전에 확정한다.
3. 수신 누락 또는 위상 계산 불가로 생긴 **내부 gap 1~5프레임**만 보간 후보로 삼는다.
   정상 관측 패킷에서 먼저 보정하고, 그 결과 사이를 보간한다.
4. 진폭은 기존처럼 선형 보간한다. 위상은 양 끝의 `(cos ψ, sin ψ)` 벡터를 선형
   보간한 뒤 길이를 1로 맞추고, 저장 순서 `(sin ψ, cos ψ)`로 배치한다.
5. 양 끝 위상의 짧은 방향 각도 차이가 어느 위치에서든 90° 이상이거나, 보간한
   벡터 길이가 `1e-6` 이하이면 해당 RX의 gap은 채우지 않는다. 빠진 동안 실제로
   몇 바퀴 회전했는지는 알 수 없다.
6. 세션 앞뒤의 누락, 5프레임보다 긴 gap, 보간 불가 값이 남은 윈도우는 제외한다.

90°와 `1e-6`은 보간이 불확실한 구간을 제외하기 위한 **본 실험의 초기 기준**이다.
ESP32 공식 품질 기준이나 현재 데이터에서 검증된 수치가 아니다. 위상 오차를
숨기기 위해 무조건 0으로 채우지 않는다.

### 4.3. 비교할 윈도우를 동일하게 유지

진폭 단독·위상 단독·진폭+위상은 **세 방법 모두 사용 가능한 윈도우의 교집합**으로
학습·평가한다. 교집합은 예측 결과를 보기 전에 확정한다. 위상 처리 때문에 어려운
윈도우만 빠져 성능이 좋아지는 상황을 구분하기 위해 다음도 함께 보고한다.

- 원래 진폭 전처리의 사용 가능 윈도우 수와 공통 비교 윈도우 수.
- 세션·클래스·RX별 위상 계산 불가율, 보간율, 제외 사유와 윈도우 유지율.
- 진폭만으로 사용 가능한 전체 윈도우에서의 진폭 기준 성능.

어떤 split에서든 한 클래스가 사라지면 3클래스 비교를 진행하지 않는다. 평가 세션에
공통 윈도우가 하나도 없으면 제외 사실과 사용 불가 세션 수를 명시한다. 남은 세션의
점수만으로 전체 데이터의 성능이 좋아졌다고 결론 내리지 않는다.

## 5. 비교할 입력과 모델 — PLANNED

### 5.1. 세 가지 입력

RX 순서는 `101 → 102 → 103`, 각 RX의 위치 순서는 §3.2를 따른다.

| 실험 | 실제 사용하는 정보 | 시점당 정보 개수 |
|---|---|---:|
| A | 진폭 | 3 RX × 51 = 153 |
| P | 보정 위상의 sin·cos | 3 RX × 51 × 2 = 306 |
| AP | 진폭 + 보정 위상의 sin·cos | 459 |

세 모델의 전체 파라미터 수를 맞추기 위해 실제 신경망 입력은 모두 `(N, 300, 459)`로
한다. `N`은 윈도우 수다. 입력 순서는 다음과 같다.

```text
[진폭 153개 | sin(보정 위상) 153개 | cos(보정 위상) 153개]
A : [진폭      | 0                | 0               ]
P : [0         | sin              | cos             ]
AP: [진폭      | sin              | cos             ]
```

사용하지 않는 자리는 **정규화 후** 정확히 0으로 둔다. 전체 구조·초기 가중치를
맞추더라도 실제로 학습에 기여하는 입력 연결 수까지 같아지는 것은 아니다.
총 파라미터 수와 실제 입력 정보 수를 모두 보고한다.

진폭은 train 윈도우의 위치별 평균·표준편차로 표준화하고 A·AP가 같은 통계를 쓴다.
초기 비교에서는 현재 전처리와 같이 train 윈도우에 포함된 모든 행을 집계한다
(겹치는 프레임은 반복 반영됨). 현재 설정과 같은 `std < 1e-6`이면 분모를 1로 저장한다.
위상의 sin·cos는 이미 −1~1이므로 그대로 사용한다. validation·test 통계로
재정규화하거나 세션마다 별도 평균을 빼지 않는다.

저장하는 정규화 벡터도 459차원으로 맞춘다. 진폭 153개 자리는 train 통계,
sin·cos 306개 자리는 평균 0·분모 1로 기록해 위상 값을 그대로 통과시킨다.
A·P의 사용하지 않는 자리를 0으로 만드는 처리는 그 다음에 적용한다.

기존 64개 진폭 입력과 비교하는 A64 실험은 별도 참고 항목이다. A64와 AP의
차이에는 서브캐리어 수·입력 구조 변화도 있으므로, 위상의 효과는 **A와 AP**로 판단한다.

### 5.2. 학습 조건

1차 비교에는 현재 1D-CNN을 사용한다. 채널 `(32, 64, 64)`, 커널 `(5, 5, 3)`,
dropout `0.2`, batch size `32`, 학습률 `0.001`, 최대 `50 epoch`, patience `5`를
세 입력에 동일하게 적용한다. optimizer 등 나머지 값도 기존 CNN 공통 runner에서
상속한 정확한 설정을 실행 manifest에 기록한다.

- seed는 `0, 1, 2`: A·P·AP 각각 3회, 총 9회 학습한다.
- 같은 seed끼리는 동일 모델 초기 가중치와 학습 윈도우 순서를 사용한다.
- 초기 비교는 class weight `none`으로 고정한다. 가중치 비교를 추가하면 모든 입력에
  똑같이 적용하고, train 라벨로만 계산한다.
- checkpoint는 현재 runner와 같이 validation **window macro F1** 최대값으로
  선택하고, 동률이면 먼저 나온 epoch를 유지한다. 최종 주 지표는 session macro F1이다.
- 위상이 도움이 된 뒤 LSTM 재검증을 추가할 수 있다. 모델과 위상 처리법을 동시에
  여러 가지 바꿔 최초 결과의 원인을 흐리지 않는다.

현재 runner의 입력 검증에는 `192`가 고정되어 있으므로 기존 명령으로 이 설계를
바로 실행할 수 없다. 입력 계약·정규화·checkpoint 검증을 함께 확장해야 한다.

## 6. 세션 분할과 평가 — PLANNED

### 6.1. 기본 분할안

세션 번호는 반드시 날짜와 함께 식별한다. 과거 수집의 같은 번호와 섞지 않는다.

| 용도 | 날짜·세션 | 클래스별 세션 수 | 기록된 RX 배치 |
|---|---|---:|---|
| train | 20260919 / s1~s24 | 각 8개 | P1 |
| validation | 20260919 / s25~s30 | 각 2개 | P2 |
| test | 20260920 / s31~s60 | 각 10개 | P2·P3 |

이 배정은 위상 품질 제외 전 목록이다. 최종 사용 목록과 제외 이유를 별도 저장한다.
위상 처리 규칙·모델 설정은 train·validation에서 정하고 test는 확정된 실험의
최종 평가에만 쓴다. test를 본 뒤 규칙을 바꿨다면 그 결과는 탐색 결과로 표시하고
새 날짜의 데이터를 최종 평가용으로 확보한다.

**배치번호는 RX 위치를 나타낸다.** 같은 배치번호라도 가구, 의자, 휴대폰·이어폰,
사람의 위치나 행동 조건이 같았다는 뜻은 아니다. 세 클래스가 같은 가구 조건으로
짝지어 수집됐다고 가정하지 않는다. 메모·사진으로 확인 가능한 조건만 기록하고
알 수 없는 항목은 `unknown`으로 남긴다. 신뢰할 수 없다고 확인된 snapshot 환경
정보를 추정으로 채우지 않는다.

2026-09-24 사용자 확인: 각 세션의 `image/`는 해당 세션의 **RX 배치와 실험 환경
설정 기록**이다. 파일 목록·hash를 inventory에 연결하고 결과 해석의 근거로 사용한다.
사진 자체를 모델 입력이나 클래스 라벨 추정에 사용하지 않는다. 사진이 없는 세션도
CSI 품질 기준으로 판단하며, 사진에서 확인하지 않은 환경 조건은 사실로 기록하지 않는다.

같은 세션의 윈도우는 절대로 여러 split으로 나누지 않는다. 이번 결과는 두 날짜의
데이터에 대한 결과이며, 여러 방·여러 사람에 대한 일반화 성능으로 확대하지 않는다.
과거에 이 test 세션을 모델 선택에 이미 사용했다면 그 이력도 보고서에 명시한다.

### 6.2. 세션 예측과 측정 항목

세션의 모든 사용 윈도우에 대해 softmax 확률을 클래스별로 평균하고, 평균 확률이
가장 큰 클래스를 세션 예측으로 정한다. 윈도우 정답 개수의 과반수 투표가 아니다.

```text
세션의 클래스 c 평균 확률 = 해당 세션 모든 윈도우의 p(c)를 더한 값 / 윈도우 수
세션 예측 = 평균 확률이 가장 큰 클래스
```

| 항목 | 계산·해석 |
|---|---|
| 주 지표: session macro F1 | 세션을 1개 표본으로 보고 클래스별 F1을 구한 뒤 3개 평균 |
| session accuracy | 맞힌 세션 수 / 평가에 사용한 세션 수 |
| 클래스별 precision | 그 클래스로 예측한 세션 중 정답인 비율 |
| 클래스별 recall | 실제 그 클래스인 세션 중 맞힌 비율 |
| 클래스별 F1 | `2 × precision × recall / (precision + recall)`; 분모 0이면 0 |
| 혼동행렬 | 행=실제 클래스, 열=예측 클래스. 개수와 행 기준 비율을 함께 표시 |
| window macro F1 | 윈도우를 표본으로 계산한 3클래스 F1 평균, 보조 지표 |
| 위상 효과 | 같은 seed에서 `AP session macro F1 − A session macro F1` |

empty→static과 static→empty의 오분류 세션 수를 따로 보고한다. motion recall이
떨어져 얻은 개선인지도 확인한다. seed별 값과 평균·표준편차를 모두 적고 최고 seed만
고르지 않는다. 수많은 중첩 윈도우를 독립 실험 표본 수로 해석하지 않는다.

신뢰구간을 추가한다면 세션을 단위로 A·AP 결과를 함께 재표집한다. 3개 seed의
변동은 데이터 일반화 불확실성과 구분한다. 두 날짜로 날짜 간 일반화의 신뢰구간을
정밀하게 추정할 수 있다고 주장하지 않는다.

### 6.3. 후속 판단

- **개선 신호 있음**: AP의 session macro F1이 A보다 평균적으로 높고 최소 2/3 seed에서
  같은 방향이며, empty↔static 오분류도 평균적으로 줄어든다. motion recall은 별도
  비교한다. 이는 후속 확인 실험을 진행할 기준이며 통계적 유의성 판정이 아니다.
- **효과 불명확**: window 점수만 상승하거나 seed·배치에 따라 효과가 뒤집힌다.
  오차 보정과 환경 의존성을 다시 확인한다.
- **이번 방식에서 도움 없음**: AP가 일관되게 개선되지 않거나 위상 때문에 사용 가능한
  구간이 크게 줄어든다. 진폭 기준을 유지하고 실패 원인을 기록한다. 이를 ESP32 위상
  전체가 쓸모없다는 결론으로 확대하지 않는다.

## 7. 구현 경로와 산출물 — PLANNED

원본 `.csi`를 공용 reader로 읽는 별도 실험 전처리 경로를 만든다. 기존 진폭 JSONL에
위상을 끼워 넣거나 `csi_amp`의 의미를 바꾸지 않는다. 펌웨어 변경·재플래시는 이
실험의 선행 조건이 아니다.

```text
.csi + session.json
  → 원본 검증·정상 구간 선택
  → I/Q 순서 확인·51개 위치 선택
  → 관측 패킷별 진폭·보정 위상 계산
  → tx_seq 정렬·짧은 gap 보간
  → 공통 윈도우 및 split 고정
  → train 진폭 정규화 통계 저장
  → A / P / AP 구성
  → 같은 CNN·3 seed 학습 및 최종 평가
```

| 구현 대상 | 책임 |
|---|---|
| `scripts/csi_store.py` | 복소수 해석 순서와 공용 서브캐리어 매핑 검증 |
| 신규 위상 진단 도구 | 0·저진폭·위상 끊김·구간별 직선·보간 가능 비율 진단 |
| 신규 위상 전처리 모듈 | 현재 순번·구간 규칙 재사용, 위상 처리·공통 윈도우 생성 |
| 공통 학습 runner | 입력 차원을 manifest에서 검증, 기존 192개 계약과 새 실험 구분 |
| 모델 보고서 | 같은 세션·윈도우·seed의 A/P/AP 비교와 실패 세션 설명 |

이 표의 신규 도구는 아직 존재하지 않으므로 실행 명령을 제시하지 않는다. 공식
입력 계약으로 채택할 때는 [문서 정책](../../../doc/documentation-policy.md)에 따라
ADR과 전처리·모델 계약도 갱신한다.

실행 구현은 기존 192차원 CLI를 유지하는 실험용 adapter를 사용한다. 기존
`CNN1DClassifier`, 공통 학습·평가 함수와 정상 구간 선택 함수를 재사용하고,
459차원 계약 검증은 실험 runner가 담당한다. 중첩 윈도우 전체를 복제 저장하는 대신
세션별 정렬 배열과 시작 위치를 저장하고 학습 시 동일한 윈도우를 구성한다.

산출물은 기존 실행 결과를 덮어쓰지 않는 별도 run 디렉터리에 둔다.

- `inventory.json`: 날짜+세션 경로, 라벨 정본, RX별 원본 파일 hash, 수집 당시 코드 출처.
- `phase-quality.json`: RX·세션별 품질 수치와 제외 이유. 통계는 중첩 윈도우가 아니라
  선택 구간의 고유 프레임 기준으로 계산한다.
- `split.json`: train·validation·test 목록과 제외 내역.
- `manifest.json`: feature 버전, I/Q 순서, 원본 인덱스와 k, 구간별 보정법, 보간·정규화
  규칙, 코드 commit과 미커밋 변경 내역의 보존 위치, 설정 hash.
- `train/validation/test`별 feature 배열·라벨·`windows.jsonl`: 날짜+세션+구간+시작
  `tx_seq`로 윈도우를 식별하고 A/P/AP의 동일성을 검증할 수 있게 한다.
- train의 `normalization.npz`, seed별 학습 설정·checkpoint·예측 확률·지표, 최종 비교표.

## 8. 실행 순서와 확인 항목 — PLANNED

1. **원본 해석 검증**: 알려진 I/Q 값으로 위상 부호·순서를 확인하고, 기존 진폭이
   바뀌지 않는지 확인한다. 첫 두 위치 제외와 주파수 순서도 검사한다.
2. **train·validation 위상 진단**: 보정 전후의 주파수별 위상과 특정 위치의 시간 변화를
   함께 본다. 분산이 줄었다는 이유만으로 성공이라 하지 않는다. 진폭·gain 변화,
   재부팅 경계와 위상 불안정의 관계도 기록한다. test는 먼저 형식·파일 존재만 점검한다.
3. **보정·보간 검증**: 합성 위상에 더한 `a×k+b`가 제거되는지, 비선형 성분이 남는지,
   ±180° 경계·0진폭·긴 gap을 잘 처리하는지 확인한다. 구간별 직선 제거가 실제 정보도
   지운다는 한계를 실데이터 진단과 함께 남긴다.
4. **공통 데이터셋 생성**: 세션 분리, train 전용 통계, A/P/AP 윈도우 ID 일치,
   입력 차원·NaN·보간율을 검증한다. 규칙을 확정한 뒤 test에도 같은 처리를 적용한다.
5. **9회 학습과 최종 평가**: seed별 AP−A 차이, empty↔static 오분류, motion recall,
   위상 때문에 제외된 세션·윈도우를 함께 보고한다.
6. **채택 여부 결정**: 개선이 보이면 새로운 날짜와 가구·전자기기 조건을 통제한
   데이터에서 다시 확인한다. 위상으로 특정 움직임이 보였다는 사실만으로 호흡 감지나
   사람 위치 추정이 가능하다고 결론 내리지 않는다.

문서 작성 시점의 완료 항목은 데이터 목록·현재 코드 확인과 본 설계 작성이다.
**다음 착수 작업은 1~2번: 원본 해석 검증과 train·validation 위상 품질 진단이다.**
작업 이력은 [위상 분류 실험 작업 기록](../../../doc/sprint/2026-09-phase-classification.md)에 남긴다.
