## main과 window_accuracy는 무슨 뜻인가

### main: 모델을 가져온 GitHub 기본 브랜치

`main`은 이 프로젝트 GitHub 저장소의 **기본 브랜치 이름**이다. 여기서는 그 브랜치의
`01c9f19` 버전에 저장되어 있던 위상 모델과 평가 기록을 가리킨다.
“main의 결과를 재현했다”는 말은 **저장된 모델을 가져와 다시 평가했더니,
그곳에 기록되어 있던 결과와 같은 값이 나왔다**는 뜻이다.

### window_accuracy: 세션별 60초 구간 정답률의 평균

`window`는 모델이 한 번에 보는 **60초 구간(창)**이다. 이번 평가에서는 창을
**3초씩 이동**했다. 예를 들어 `0~60초`, `3~63초`, `6~66초`를 각각 분류한다.
입력 누락 때문에 사용할 수 없는 창은 정답률 계산에서 제외한다.

main의 `window_accuracy`는 다음 순서로 계산한다.

1. 한 세션에서 **맞힌 창 수 ÷ 평가한 유효 창 수**를 구한다.
   예를 들어 s33은 `24 ÷ 81`, s39는 `76 ÷ 81`이다.
2. 이렇게 구한 **15개 세션의 창 정답률을 모두 더하고 15로 나눈다.**
   세션마다 같은 비중을 준다.
3. main에 기록된 값은 소수점 네 자리로 표시한 **`0.8772 = 87.72%`**다.

세션마다 평가한 창 수가 다르다. 예를 들어 s44는 59개, s39는 81개지만,
이 평균에서는 각 세션의 정답률을 한 번씩 넣는다.
따라서 모든 창을 한꺼번에 세는 방식과 결과가 조금 다르다.

### 87.72%, 87.48%, 14/15는 서로 다른 계산이다

| 표시한 결과 | 계산 방법 | 무엇을 뜻하나 |
|---|---|---|
| **87.72%** (`window_accuracy=0.8772`) | 세션별 창 정답률 15개를 평균 | 세션마다 같은 비중으로 본 60초 구간 정답률 |
| **87.48%** (`1,041/1,190`) | 모든 세션의 맞힌 창 수를 합쳐 전체 유효 창 수로 나눔 | 창마다 같은 비중으로 본 60초 구간 정답률 |
| **93.33%** (`14/15세션`) | 세션 전체에 대한 판정이 맞은 세션 수를 셈 | 15세션 중 14세션의 상태를 맞혔다는 뜻 |

세션 전체 판정은 그 세션의 유효 창에서 나온 **빈 방·정지·움직임 점수를 각각 평균하고,
평균 점수가 가장 높은 상태 하나를 고르는 것**이다. 창 판정의 다수결은 아니다.
예를 들어 s37은 81개 창 중 42개만 정지를 맞혔지만, 점수를 평균한 세션 판정은 정지여서
14개 정답 세션에 포함된다.

창들이 서로 많이 겹치므로 1,190개를 독립적인 시험 1,190번으로 해석하지 않는다.
또한 이 숫자는 저장 자료의 평가 결과이며 실시간에서 매번 같은 비율로 맞힌다는 뜻은 아니다.

## 원본 품질과 제외한 창

15세션 모두 평가했다. 45개 `.csi`, 총 **1,311,258프레임**에서 CRC·헤더·RX 식별·RF 규격·
매니페스트 프레임 수 검사를 통과했다. RX 재부팅과 송신 순번 역행은 없었다.
가장 낮은 RX 관측률은 92.85%였다. 중복 순번은 기존 규칙대로 첫 프레임을 사용했다.

후보 1,213개 창 중 **23개를 입력 누락 때문에 제외**, 1,190개를 평가했다.

- 9/16 s31: 공통 구간 시작 기준 0~60초 창 1개 제외. 첫 유효 창은 3~63초다.
- 9/17 s44: 시작점 138~201초, 3초 간격의 창 22개 제외. 해당 60초 창에 보간되지 않은 누락이 포함된다.
- 나머지 세션: 후보 창 전부 사용했다. 파일 길이에 따라 후보는 80개 또는 81개다.

이것은 완성된 녹화 파일의 유효 창을 고른 결과다. 실시간 파일 도착 지연과 판단 정지 시간은
이번 단계에서 측정하지 않았다.

## 평가 규칙과 검증

- main `01c9f1929b170d21fe9a570bd37c821127521aeb`의 `model_60sessions.pt`를 고정한다.
- 9/19·20 학습 60세션과 9/16·17 평가 15세션의 날짜·키·원본 해시 중복을 확인한다.
- 정답은 세션 매니페스트를 기준으로 확인한다. 모델에는 정답을 전달하지 않는다.
- 원본 프레임 검사를 통과한 자료에서 가져온 `phase60/features.py`를 그대로 사용한다.
- 60초 창, 3초 이동, 20프레임 평균, seed 3개 점수 평균 후 창 점수 평균으로 세션을 분류한다.
- 캐시를 재사용하지 않고 원본에서 입력을 다시 만든다. CPU 추론을 사용한다.
- 세션 정답률, 전체 창 정답률, 세션별 창 정답률의 평균을 구분한다.
- main에 저장된 세션별 결과와 기존 진폭 12/15 결과를 비교한다.
- 모델 파라미터와 BatchNorm 통계, 원본·진폭 파일의 해시 불변을 확인한다.
- 전환 지연이나 실시간 안정성은 이번 평가에서 측정하지 않는다. 이전 파일럿에서 사용된 자료이므로 처음 보는 맹검 시험으로 부르지 않는다.

학습 날짜·세션 키 중복은 없었고, 평가 raw 파일과 학습 raw 파일의 해시 중복도 없었다.
학습 원본 180개는 9/24에 작성된 기존 학습 자료 목록의 해시와 일치했다.
다만 위상 체크포인트 자체에는 학습 raw 해시가 없으므로, 학습 당시에 사용한 캐시까지
해시로 증명한 것은 아니다. 이 검사는 현재 원본과 기존 목록을 기준으로 한다.

평가 전후 267개 파일의 해시가 같았고, seed 3개의 가중치와 BatchNorm 통계도 바뀌지 않았다.
개별 seed 점수 평균, main에서 가져온 예측 함수, 별도 저장 점수 집계가 일치했다.
15세션의 판정·소수점 4자리 창 정답률을 재현했으며, main의 반올림된 세션 점수와
최대 차이는 약 0.00004935였다. 소수점 4자리 반올림 오차 범위 안이다.

신규 검사 5개를 포함한 **전체 테스트 146개 통과**. 정답과 폴더 이름 불일치,
학습 세션 혼입, 잘못된 입력 규칙, 평균 방식과 분모 차이, 누락 창 제외를 검사했다.

NumPy 행렬곱에서 divide/overflow/invalid 경고가 발생했다. 투영 행렬 및 12,288개
합성 복소 신호의 위상 잔차를 비-BLAS `einsum` 계산과 비교해 절대 오차 1e-12 이내를 확인했다.
실제 평가 입력·점수의 유한성 검사도 통과했다. 경고를 전역으로 숨기거나 main의 수식을 바꾸지 않았다.
