# 10월 12일 방 자료로 기존 위상 모델 추가 학습·실시간 연결

> 상태: **EXPERIMENTAL** — 2026-10-13 학습·저장·GUI/CLI 연결 완료. 새 실시간 시험은 미실시.
> 목표: 기존 위상 3클래스 모델을 이번 녹화로 파인튜닝하고 바로 선택해 시험한다.

## 무엇을 학습했는가

기존 `model_60sessions.pt`의 seed 0·1·2 가중치에서 시작했다. 입력 변환과 CNN은 유지하고 **분류 부분 128→64→3만 추가 학습**했다. CNN의 가중치와 BatchNorm 내부 통계는 바뀌지 않았다. 출력은 empty/static/motion이며 2단계 모델은 구현하지 않았다.

새 방에는 [10/12 첫 녹화](20261012-room-adaptation-capture.md) 1회만 사용했다. 잠정 구간에서 60초 길이·3초 이동의 empty 36창, 침대 앉기 static 34창, 걷기 motion 35창을 만들었다. 휴대전화/Mac 시차 0초와 경계 양끝 10초 여유 가정은 그대로 기록했다.

기존 세 상태의 능력 유지용으로 9/19·20 학습 60세션의 겹치지 않는 유효 60초 창 290개도 사용했다. 정답은 `session.json`에서 읽고 원본·CRC·부팅·순번을 검사했다. 기존/새 방은 1:1 비중으로 추출하며 출처별 세 클래스 비중을 맞췄다.

### 실제 학습 설정

| 항목 | 값 |
|---|---|
| 출발 모델 | 기존 60세션 위상 모델, seed 0·1·2 |
| 조정 범위 | head 두 Linear 층, CNN·BatchNorm 동결 |
| 자료 | 기존 290창 + 새 방 105창 |
| optimizer | Adam |
| 학습률·epoch·배치 | 1e-3 · seed별 100 epoch · 32 |
| 창 선택 | 새 방 3초 이동, 기존 자료 60초 이동 |
| 학습 종료 | 고정 횟수, 검증 기반 조기 중단 없음 |

최초 1e-4·20 epoch 시도는 새 방 학습 창 정답률이 57.14%에서 33.33%로 악화됐다. 이 파일은 실시간 선택에 연결하지 않고 로컬 `model_train/phase60/runs/20261013-room-head/attempt1.pt`에 보존했다. 다음 시도도 이 실패 모델이 아닌 원래 가중치에서 시작했다. 학습 자료를 보고 설정을 조정했으므로 두 번째 설정을 독립 검증으로 선택했다고 해석하지 않는다.

고정 CNN 특징을 seed별로 미리 계산해 head 학습에 사용했다. 원래 전체 순전파와의 대조를 통과했다. epoch마다 전체 자료를 한 번씩 정확히 쓰는 방식이 아니라 균형 가중치로 중복 추출한다.

## 결과 — 학습 자료를 다시 넣었을 때

| 이번 방 자료 | 기존 모델 | 추가 학습 모델 |
|---|---:|---:|
| 빈 방 | 0/36 | 36/36 |
| 침대 앉기 | 25/34 | 34/34 |
| 걷기 | 35/35 | 35/35 |
| 전체 | 60/105, 57.14% | 105/105, 100% |

기존 자료 290창에서는 추가 학습 전후 모두 **289/290, 99.66%**였다.

**이 표의 두 자료는 모두 추가 학습에 사용했다.** 이번 방 100%는 독립 정확도가 아니라 학습 자료 재판정 결과다. 녹화 1회의 겹치는 창을 105개의 독립 시험으로 세지 않는다. 새 실제 측정에서 잘 되는지는 아직 확인하지 않았다. 기존 9/16·17 자료에 대한 이번 파인튜닝 모델 평가도 실행하지 않았다.

추가 테스트 6개 포함 전체 **190개 통과**. 클래스·출처별 추출 비중, CNN·BatchNorm 동결, 잘못된 정답 구간·해시·부팅 경계 거부, 원래 모델을 새 방 모델로 잘못 선택하는 경우, 전용 모델 종류 전달을 검사했다.

GUI의 유휴 상태를 확인하고 같은 주소에서 서버를 재시작했다. API에서 새 선택 항목과 파일 존재를 확인했다. 확인 시점에 연결 보드는 0대였으므로 실제 보드 수집·추론은 시작하지 않았다. 기존 NumPy matmul 경고는 남아 있지만 입력 유한성·순전파 대조·저장 복원 검사는 통과했다.

## 지금 실시간으로 시험하는 방법

1. SINK USB와 TX·RX 전원을 연결한다. GUI에서 보드 검색 후 SINK와 RX 3대를 확인한다.
2. [GUI](http://127.0.0.1:65031/)를 새로고침한다.
3. 실시간 탭에서 **위상 60초 · 내 방 추가 학습**을 선택한다.
4. **실시간 시작**을 누른다. 최초 60초 입력 준비 후 기본 0.3초 이동으로 결과를 표시한다.
5. 같은 배치에서 빈 방·걷기·침대 앉기를 수행하고 실제 행동 시각을 기록한다. 이 새 녹화로 학습 밖의 동작을 확인한다.

이 새 녹화는 이번 평가에만 사용하고 추가 학습에는 넣지 않는다. 저장된 동일 원본을 기존/추가 학습 위상 모델에 각각 넣어 실제 행동과 비교한다. 같은 날 바로 측정해도 되며, 10/12 학습 원본을 새 평가 자료로 다시 세지 않는다.

기존 위상 모델로 비교하려면 판단 정지 후 **위상 60초 (시험 후보)**를 선택해 새 실행을 시작한다.

CLI는 실제 SINK 포트로 바꿔 실행한다.

```bash
.venv/bin/python scripts/meshsense_cli.py --live --port <SINK포트> --model-kind phase60_room --plain
```

## 추가 학습 재현

아래 명령은 원래 모델에서 다시 시작한다. 같은 출력 파일이 이미 있으면 거부하므로 새 파일명을 사용한다. Desktop의 사진·메모를 포함해 기록된 입력 해시와 현재 파일이 같아야 한다.

```bash
.venv/bin/python model_train/phase60/finetune_room.py \
  --annotations model_train/docs/model-training/assets/20261012-room-capture/summary.json \
  --output model_train/phase60/model_room_reproduction.pt \
  --epochs 100 --lr 0.001 --batch 32
```

다음은 두 번째 학습 녹화를 선행 조건으로 요구하는 작업이 아니라, **이 모델을 새 실시간 자료에서 직접 시험하는 작업**이다. 2단계 설계와 반복 수집 계획은 후속 후보로 보존한다.

## 10/6 자료 후속 비교 — 완료

사용자 요청으로 학습에 쓰지 않은 10/6 원본을 원래/추가 학습 위상 모델에 넣어 비교한다.
기존 전환 재생과 동일한 60초 입력·0.3초 이동·prefix 순차 재생·행동 시간표를 사용한다.
정지 일치율뿐 아니라 빈 방·걷기·판단 불가·전환 지연을 함께 보고한다.
10/6은 이미 진단에 사용한 자료이므로 완전히 처음 보는 독립 시험이라고 부르지 않는다.

**결과:** 앉기 전체 정지 일치율은 0%→23.54%였지만, 첫 60초를 뺀 뒤에는 **0%→0.75%**로 거의 개선되지 않았다.
정지 상태 내부의 60초 창 34개도 두 모델 모두 빈 방으로 틀렸다. 걷기 일치율은 하락했고 전체 시간 일치율은 46.90%→49.66%였다.
[10/6 파인튜닝 전후 비교](20261013-room-finetuning-oct6-evaluation.md)에 수치·그림·검산을 기록했다.

**배치 정보 추가 확인 (2026-10-13):** 사용자가 10/6에는 각 RX 위치가 10/12와 달랐고 삼각대도 사용하지 않았다고 확인했다. 두 날짜 사진을 확인해 평가 문서에 반영했다. 따라서 위 수치는 다른 배치에 적용한 결과다. 이번 서비스 목표인 **짧게 측정·학습한 뒤 같은 배치에서 사용하는 성능**은 10/12 배치를 유지한 새 녹화로 확인해야 한다. 기존 결과 수치와 가중치는 변경하지 않았다.
