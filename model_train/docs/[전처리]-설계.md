> 대상 데이터: `mac_collector_output/raw/20260616/session_1` ~ `session_30`
> 공식 구현: [`preprocess_3rx.py`](../preprocessing/preprocess_3rx.py) · 테스트: [`test_preprocess_3rx.py`](../../tests/test_preprocess_3rx.py)
> 기존 실험 코드: [`Preprocessing.py`](../lstm/Preprocessing.py) (EXPERIMENTAL, 이 설계 미반영)
> 기존 LSTM 전처리 구현: [`전처리-현재-구현.md`](%5B전처리%5D-현재%20구현.md)
> 순번 판정 기준: [`seq`와 `tx_seq` 패턴](../../doc/sequence-patterns.md)

## 1. 목적

RX 101·102·103이 같은 TX frame을 수신한 부분만 모델 학습에 사용한다. 세 RX의
정렬 기준은 RX마다 따로 증가하는 `seq`가 아니라 TX가 frame마다 증가시키는
`tx_seq`다.

이 문서는 LSTM에 한정되지 않는다. RandomForest, 1D-CNN, GRU, BiLSTM 등 모든
후속 모델은 이 설계가 만든 동일한 전처리 산출물을 사용한다.

핵심은 다음과 같다.

```text
RX별 정상 구간 찾기
  → tx_seq로 세 RX 맞추기
  → 세 RX가 겹치는 구간 선택
  → 짧은 누락만 보간
  → 유효한 3초 window 생성
```

그래프를 사람이 보고 범위를 직접 입력하는 방식은 사용하지 않는다. 시각화와
전처리가 같은 범위 계산 함수를 사용하게 하여, 그림에서 확인한 결과와 실제 학습
입력이 다르게 선택되는 문제를 막는다.

## 2. 설계 기준

5분 세션을 100Hz로 수집하면 목표 길이는 약 30,000 frame이다. 전처리는 정확히
30,000개를 강제로 만들지 않고, 세 RX의 실제 공통 구간을 전부 사용한다.

현재 공식 기준은 다음과 같다.

| 항목 | 기준값 | 의미 |
|---|---:|---|
| 목표 세션 길이 | `30000 frame` | 5분 × 100Hz |
| 최소 공통 길이 | `27000 frame` | 목표 길이의 90% 미만이면 세션 제외 |
| 최소 RX 관측률 | `0.85` | 공통 grid 중 해당 RX가 실제 수신한 비율 |
| 최대 보간 gap | `5 frame` | 약 50ms 이하의 내부 누락만 보간 |
| window 길이 | `300 frame` | 3초 |
| stride | `30 frame` | 0.3초 |
| RX | `101, 102, 103` | 항상 세 대를 같은 순서로 결합 |
| RX당 feature | `64` | 현재 baseline에서는 `csi_amp` 64개 전부 사용 |

`30000`은 정상 수집 여부를 확인하는 목표값이다. 공통 구간이 `29963`이나
`30012`처럼 조금 다르더라도 끝 값을 채우거나 무조건 잘라서 정확히 30,000개로
만들지 않는다.

## 4. 전체 처리 순서

```text
1. RX별 JSONL을 파일 순서대로 읽기
2. 이전·현재·다음의 `seq`, `tx_seq`로 단일 손상 record 제거
3. `seq`로 RX 재부팅 segment 분리
4. 손상 제거 후 `tx_seq`의 지속 감소가 없는지 검증
5. 세 RX의 안정 segment 조합 만들기
6. 각 조합의 tx_seq 교집합 계산
7. 가장 긴 유효 교집합 선택
8. 최소 길이·관측률 검사
9. 공통 tx_seq grid와 실제 수신 mask 생성
10. 5 frame 이하의 내부 누락만 선형 보간
11. 긴 누락이 포함된 3초 window 제외
12. 세 RX의 64개 feature를 결합
13. session 단위 split에 window 저장
14. train 데이터 통계로만 normalization
```

## 5. 단계별 설계

### 5.1 RX별 JSONL을 파일 순서대로 읽기

각 JSONL은 파일에 기록된 순서대로 읽는다. 처음부터 모든 record를 `tx_seq`
오름차순으로 정렬하면 재부팅 전후의 같은 숫자가 섞이고, 원래 어느 시점에
발생한 record인지 알 수 없게 된다.

필수 입력값은 다음과 같다.

```text
device_id
seq
timestamp_us
tx_seq
csi_amp
```

JSONL의 `received_at_unix_us`는 삭제하지 않지만 전처리 필수 입력이나 판정값으로
사용하지 않는다. 수집 상태를 나중에 조사할 때만 참고할 수 있다.

한 줄이라도 JSON 형식이나 필수 field가 잘못되면 조용히 건너뛰지 않고 오류 위치를
manifest에 기록한다. 정상 record가 너무 적거나 공통 길이 기준을 충족하지 못하면
세션을 제외한다.

### 5.2 이전·현재·다음의 `seq`, `tx_seq`로 단일 손상 record 제거

5.1에서 읽은 순서를 유지한 채 `이전–현재–다음` 세 record를 비교한다. 가운데의
단일 손상 record를 먼저 제거해 손상된 `tx_seq`가 정상 세션을 둘로 자르는 일을
막는다.

예를 들어 다음과 같이 B만 정상 흐름에서 벗어날 수 있다.

```text
record    seq    tx_seq
A         17456  617288
B         3288334404  2411      <- 손상 record
C         17459  617291
```

`A → B`에서 `tx_seq`가 감소하지만 B를 건너뛴 `A → C`는 다시 앞으로 이어진다.
이 경우 B만 학습에서 제외하고 A와 C는 같은 RX segment에 유지한다.

```text
나쁜 결과:  segment 0 = A / segment 1 = B / segment 2 = C 이후
설계 결과: segment 0 = A, C, C 이후 / invalid record = B
```

가운데 record를 단일 이상 record로 판단하려면 다음 조건을 함께 확인한다.

1. 현재 record의 `seq` 또는 `tx_seq`가 이전·다음 흐름에서 벗어난다.
2. 현재 record를 제외하면 `이전 tx_seq < 다음 tx_seq`로 송신 흐름이 복구된다.
3. RX 재부팅이 아닌 구간에서는 `이전 seq < 다음 seq`도 만족한다.
4. RX 재부팅 경계에서는 다음 record의 `seq`가 0 근처이고, 이전보다 큰 정상
   `tx_seq` 흐름으로 복귀한다. 이 경우 다음 record에 `boot_start_after_corrupt`
   표시를 남겨 5.3에서 제외하지 않고 새 segment의 첫 record로 사용한다.

현재 데이터에서 확인된 직접적인 형태는 다음과 같다.

```text
previous.tx_seq > current.tx_seq
and
next.tx_seq > previous.tx_seq
```

즉 한 record만 아래로 튄 뒤 바로 기존 증가 범위로 돌아온다. 반대로 가운데 값이
비정상적으로 크게 튀는 경우도 `previous < next`인데 current가 그 사이에 없으면
같은 단일 손상 후보로 기록한다.

전체 판정 로직은 다음과 같다. 이전 record를 A, 검사할 가운데 record를 B, 다음
record를 C라고 부른다.

1. B를 제외했을 때 A의 `tx_seq`보다 C의 `tx_seq`가 커야 한다. 이 조건을
   만족하지 않으면 B 하나만 제거해서 기존 TX 흐름을 복구할 수 없으므로 자동
   제거하지 않는다.
2. A의 `seq`보다 C의 `seq`가 크면 같은 RX boot 구간이다. 이때 B의 `tx_seq`가
   A와 C 사이에 없거나 B의 `seq`가 A와 C 사이에 없으면 B를 단일 손상으로
   판정한다.
3. A의 `seq`보다 C의 `seq`가 작더라도 C의 `seq`가 10 이하라면 RX 재부팅
   경계일 수 있다. 이때 B의 `tx_seq`가 A와 C 사이에 없으면 B를 단일 손상으로
   제거하고 C를 새 RX segment의 시작으로 표시한다.
4. B의 `seq`와 `tx_seq`가 모두 정상적인 앞뒤 범위 안에 있으면 B를 제거하지
   않는다. A와 C만 봐도 TX 흐름이 복구되지 않거나 RX 경계가 불명확한 경우도
   자동 제거하지 않고 품질 오류 후보로 남긴다.

“사이에 있다”는 것은 A보다 크고 C보다 작은 경우만 뜻한다. A 또는 C와 같은
중복값은 정상 증가로 인정하지 않는다.

Mac 수신 시각인 `received_at_unix_us`는 이 판정에 사용하지 않는다. 이 값은
RX의 무선 수신 시각이 아니라 Mac reader가 USB 데이터를 읽은 시각이므로 USB
버퍼링, reader process와 macOS scheduling 지연의 영향을 받는다.

단일 이상 record로 확정하면 다음처럼 처리한다.

```text
해당 record의 CSI와 metadata를 모두 학습에서 제외
앞뒤 정상 record는 같은 segment로 연결
invalid_record_count와 제외 이유를 manifest에 기록
```

`tx_seq`만 이상하고 `csi_amp`가 정상처럼 보여도 올바른 TX frame 위치를 알 수
없으므로 해당 record는 사용하지 않는다.

가운데 record를 제외해도 `이전 → 다음`이 정상적으로 이어지지 않으면 자동
복구하지 않는다. 손상 record가 여러 개 연속이거나 판정이 모호한 경우에는 해당
세션을 품질 오류 후보로 남긴다.

첫 record와 마지막 record는 양쪽 이웃이 없으므로 이 규칙으로 자동 제거하지
않는다. 가장자리 이상은 뒤 단계의 RX segment 길이와 세 RX 교집합 검사에서
걸러낸다.

### 5.3 `seq`로 RX 재부팅 segment 분리

5.2에서 단일 손상 record를 제거한 뒤 `seq`만 사용해 RX 재부팅 경계를 찾는다.

```text
current_seq < previous_seq
and
(current_seq <= 10 or previous_seq - current_seq >= 100)
```

| RX 경계 | 판정 예 | 처리 |
|---|---|---|
| 일반 RX 재부팅 | `seq`가 큰 값에서 0 근처로 감소 | 경계 record 제외 후 새 segment |
| 손상 record 뒤 RX 재부팅 | 5.2가 다음 정상 record에 표시를 남김 | 표시된 record부터 새 segment |

일반적인 재부팅에서는 재부팅을 알린 `seq=0` 근처의 경계 record를 제외하고 그
다음 정상 record부터 새 segment를 시작한다. 단순 packet loss에서는 `seq`가
앞으로 건너뛰므로 재부팅과 구분된다.

재부팅 경계 record 자체가 깨져 `seq`가 수십억처럼 보이고 그 다음 record의
`seq`가 0 근처인 경우도 있다. 이때는 5.2에서 깨진 record를 이미 제외했으므로,
`boot_start_after_corrupt`로 표시한 다음 정상 record는 다시 제외하지 않고 새 RX
segment의 첫 record로 포함한다.

구체적인 판정 순서는 다음과 같다.

```text
1. 정리된 record를 파일 순서대로 비교
2. `boot_start_after_corrupt` 표시가 있으면 그 record부터 새 segment 시작
3. 그 외에는 위 `seq` 감소 조건으로 RX 재부팅 후보 판정
4. 일반 경계 record는 제외
5. 그 다음 정상 record부터 새 RX segment 시작
```

수집률 도구인 `measure_csi_hz.py`가 쓰는 "`seq`와 `timestamp_us`가 동시에
감소" 조건은 전처리에 재사용하지 않는다. 실데이터의 session 17과 26의 RX
102에서는 경계 record의 `timestamp_us`가 비정상적으로 큰 값이어서, 동시 감소
조건이 성립하지 않는 재부팅 경계가 실제로 존재했다. 따라서 전처리의 재부팅
판정은 `seq`만 사용한다.

RX마다 재부팅 시점과 횟수가 다를 수 있으므로 segment 번호가 같다는 이유만으로
세 RX의 같은 구간이라고 가정하지 않는다.

### 5.4 손상 제거 후 `tx_seq`의 지속 감소가 없는지 검증

현재 수집 운영에서는 TX를 session마다 재부팅하지 않는다. 따라서 단일 손상
record를 모두 제거한 뒤에도 다음처럼 감소한 값이 계속되면 여러 TX epoch로
분리해 일부만 사용하지 않는다.

```text
50000 -> 0 -> 1 -> 2 -> 3
```

이는 예상 밖 TX 재부팅 또는 복구할 수 없는 데이터 혼합으로 보고 해당 session
전체를 제외하며 이유를 manifest에 기록한다. 20260616 데이터에는 이런 지속 감소가
0건이다.

단일 손상과 지속 감소의 차이는 다음과 같다.

```text
617288 → 2411 → 617291 → 617292
  → 한 record 뒤 기존 증가 흐름 복귀
  → 2411 record만 제외

50000 → 0 → 1 → 2 → 3
  → 감소한 흐름이 지속됨
  → session 전체 제외
```

`received_at_unix_us`는 이 검증에 사용하지 않는다. 검증을 통과한 각 RX
segment는 내부에서 `tx_seq`가 계속 증가해야 한다.

### 5.5 세 RX의 안정 segment 조합 만들기

무조건 마지막 segment만 선택하지 않는다. 세 RX에서 실제로 긴 공통 구간을 만들
수 있는 안정 segment 조합을 비교한다. 이렇게 하면 파일 앞이나 뒤에 짧은 이상
구간이 붙어 있어도 정상적인 약 30,000 frame 구간을 선택할 수 있다.

예를 들어 다음과 같이 RX마다 segment 수가 다를 수 있다.

```text
RX101: A0, A1
RX102: B0, B1, B2
RX103: C0, C1
```

가능한 `(A, B, C)` 조합별로 다음 단계의 교집합을 계산한다. 단일 손상 제거 후
`tx_seq`가 계속 증가하는 segment만 조합 후보에 넣는다. 같은 번호끼리만 묶지
않는다.

### 5.6 각 조합의 `tx_seq` 교집합 계산

안정 segment 조합 하나에 대해 다음처럼 계산한다.

```python
common_start = max(rx101_start, rx102_start, rx103_start)
common_end = min(rx101_end, rx102_end, rx103_end)
common_length = common_end - common_start + 1
```

예:

```text
RX101: 113500 ~ 143536
RX102: 113480 ~ 143536
RX103: 113510 ~ 143536

공통:  113510 ~ 143536
길이:  30027 frame
```

세 RX 중 가장 늦게 시작한 값이 공통 시작이고, 가장 먼저 끝난 값이 공통 끝이다.
공통 범위 밖의 값은 보간하거나 끝 값으로 채우지 않는다.

### 5.7 가장 긴 유효 교집합 선택

공통 범위가 있는 조합이 여러 개라면 다음 순서로 고른다.

1. 단일 손상 제거 후 `tx_seq`가 계속 증가하는 RX segment만 사용한다.
2. `common_length >= 27000`인 조합을 우선한다.
3. 조건을 만족하는 조합 중 공통 길이가 가장 긴 것을 선택한다.
4. 길이까지 같으면 파일에서 먼저 나온 segment 조합을 선택해 결과를 항상
   동일하게 한다.

선택 결과로 RX별 segment 번호, `common_start`, `common_end`, `common_length`를
manifest에 기록한다. 사람이 그래프를 보고 시작과 끝을 수동으로 입력하지 않는다.

### 5.8 최소 길이·관측률 검사

선택된 공통 범위에 대해 RX별 실제 수신률을 계산한다.

```python
observed_ratio = unique_received_tx_seq_count / common_length
```

다음 중 하나라도 해당하면 세션을 제외한다.

```text
RX 101·102·103 파일 중 하나가 없음
정상 안정 segment 조합이 없음
단일 손상 record 제거 후에도 tx_seq 감소가 지속됨
common_length < 27000
RX 하나라도 observed_ratio < 0.85
```

최대 gap이 5 frame을 넘는다는 이유만으로 세션 전체를 제외하지는 않는다. 해당
gap과 겹치는 window만 뒤 단계에서 제외한다.

### 5.9 공통 `tx_seq` grid와 실제 수신 mask 생성

선택된 교집합으로 정수 grid를 만든다.

```python
tx_grid = np.arange(common_start, common_end + 1)
```

같은 `tx_seq`의 세 RX record를 같은 위치에 배치한다.

```text
tx_seq       RX101       RX102       RX103
113510       CSI         CSI         CSI
113511       CSI         누락        CSI
113512       CSI         CSI         CSI
```

배열 shape는 다음과 같다.

```text
aligned:      (3, T, 64), float
present_mask: (3, T),     bool
```

- `3`: RX 101·102·103
- `T`: 선택한 공통 `tx_seq` 개수, 정상 세션은 약 30,000
- `64`: RX 하나의 `csi_amp` feature 수
- `present_mask=False`: 해당 RX가 그 `tx_seq`를 실제 수신하지 못함

중복 `tx_seq`가 있으면 같은 segment에서 파일 순서상 첫 record만 사용하고 중복
개수를 manifest에 남긴다.

### 5.10 5 frame 이하의 내부 누락만 선형 보간

공통 범위 안의 연속 누락 길이를 RX별로 계산한다.

```text
1~5 frame 누락  → 앞뒤 실제 CSI를 사용해 subcarrier별 선형 보간
6 frame 이상    → invalid 상태 유지
공통 범위 바깥  → 보간 금지
```

보간한 값은 계산에 사용할 수 있지만 실제 수신한 record로 세지 않는다.
`present_mask`는 원본 수신 여부를 그대로 유지하고, 필요하면 별도의
`interpolated_mask`를 저장한다.

### 5.11 긴 누락이 포함된 3초 window 제외

300 frame 길이의 window 후보를 30 frame씩 이동하며 만든다. 아직 feature를
결합하지 않아도 `invalid_mask`를 이용해 각 시작 위치의 사용 가능 여부를 먼저
판정할 수 있다.

```text
window 0: index   0 ~ 299
window 1: index  30 ~ 329
window 2: index  60 ~ 359
```

세 RX 중 하나라도 6 frame 이상의 긴 누락이 window 안에 있으면 해당 window를
제외한다. 서로 다른 session이나 RX segment의 끝과 시작을 이어서 window를 만들지
않는다.

세션마다 공통 길이가 조금 달라 window 수가 한두 개 다른 것은 허용한다. 모델에
전달하는 단위는 고정 길이 300 frame window이므로 전체 세션을 정확히 30,000
frame으로 맞출 필요가 없다.

### 5.12 세 RX의 64개 feature 결합

세 RX feature를 다음처럼 합친다.

```text
(3, T, 64)
  → (T, 3, 64)
  → (T, 192)
```

5.11에서 통과한 시작 위치만 300 frame씩 꺼내 최종 Tensor를 만든다.

```text
window 하나: (300, 192)
X:           (N, 300, 192), float32
y:           (N,),          int64
```

`tx_seq`, `seq`, `timestamp_us`는 모델 feature에 포함하지 않는다. `tx_seq`는
window 시작 위치와 세 RX 정렬을 재현하는 metadata로만 저장한다.

### 5.13 Session 단위 split에 window 저장

train·validation·test는 session 단위로 먼저 고정한다. 한 session에서 만들어진
모든 window는 같은 split 파일에만 저장한다. Window를 모두 만든 뒤 무작위로
나누면 같은 session의 겹치는 window가 train과 test 양쪽에 들어갈 수 있으므로
금지한다. 20260616 데이터의 split 초안은 session 22를 제외하고 train 17개,
validation 6개, test 6개다.

초안의 구체적인 세션 배정은 다음과 같다. 각 class 안에서 세션 번호 순서대로
train → validation → test를 배정한다.

| split | empty | static | motion | 세션 수 |
|---|---|---|---|---:|
| train | 1~6 | 11~16 | 21, 23~26 | 17 |
| validation | 7, 8 | 17, 18 | 27, 28 | 6 |
| test | 9, 10 | 19, 20 | 29, 30 | 6 |

session 22는 품질 gate가 제외하는 세션이므로 어느 split에도 배정하지 않고
manifest에 제외 이유만 남긴다. 만약 split에 배정되지 않은 세션이 품질 gate를
통과하면 전처리는 조용히 버리지 않고 오류로 중단해, 배정표를 먼저 갱신하게
한다.

Label 이름과 번호는 dataset metadata를 기준으로 고정한다.

```text
empty  = 0
static = 1
motion = 2
```

현재 코드의 `action=2` 표기는 같은 뜻인 `motion=2`로 수정한다.

각 window에는 최소한 다음 출처 metadata를 함께 저장한다.

```text
session_id
label
window_start_tx_seq
RX order = [101, 102, 103]
observed_ratio
```

### 5.14 Train 데이터 통계로만 normalization

여기서 feature는 모델에 입력하는 숫자 한 칸을 뜻한다. TX frame 하나를 수신하면
RX 하나에서 `csi_amp` 64개가 나오고, 세 RX의 값을 고정된 순서로 이어 붙이면 한
시점에 192개 feature가 만들어진다.

```text
RX101 amplitude 64개 | RX102 amplitude 64개 | RX103 amplitude 64개
                              ↓
                    한 시점의 feature: (192,)

300개 시점을 묶은 window 하나: (300, 192)
```

따라서 feature 하나는 단순히 서브캐리어 번호 하나가 아니라 **특정 RX에서 측정한
특정 서브캐리어의 amplitude**다. 같은 서브캐리어 번호라도 측정한 RX가 다르면
서로 다른 feature로 취급한다.

```text
feature 0~63    = RX101의 서브캐리어 0~63 amplitude
feature 64~127  = RX102의 서브캐리어 0~63 amplitude
feature 128~191 = RX103의 서브캐리어 0~63 amplitude
```

Normalization은 이 192개 feature 열을 각각 비슷한 값 범위로 맞추는 과정이다.
각 feature 위치마다 모든 train window와 시점에서 평균과 표준편차를 계산하고,
다음 공식으로 값을 변환한다.

Train 배열이 `X_train.shape = (N_train, 300, 192)`라면 feature `k`의 통계는
`X_train[:, :, k]`에 들어 있는 모든 값을 대상으로 계산한다. 즉 window 번호 축과
300개 시점 축은 모두 평균 계산에 포함하고, feature 축은 서로 섞지 않는다.

```python
mean[k] = X_train[:, :, k].mean()
std[k] = X_train[:, :, k].std()
```

```text
정규화된 값 = (원래 amplitude - train 평균) / train 표준편차
```

예를 들어 특정 feature의 train 평균이 `100`, 표준편차가 `20`이면 원래 값 `140`은
`(140 - 100) / 20 = 2.0`이 된다. 이런 평균과 표준편차를 192개 feature마다 하나씩
만들기 때문에 두 배열의 shape은 모두 `(192,)`이다.

```text
mean.shape = (192,)
std.shape  = (192,)
```

Validation과 test에는 해당 데이터에서 새로 계산한 평균·표준편차를 사용하지
않는다. Train에서 확정한 같은 평균과 표준편차를 그대로 사용한다.

```text
train      → train 평균·표준편차 계산 및 적용
validation → train 평균·표준편차 적용
test       → train 평균·표준편차 적용
```

이는 train record를 validation·test에 복사한다는 의미가 아니다. 변환 기준인
192개의 평균과 표준편차만 공유한다는 의미다. Validation·test 값을 통계 계산에
포함하면 평가할 데이터의 분포를 미리 본 상태로 입력을 변환하는 data leakage가
발생한다.

현재 전처리 코드는 `train`, `validation`, `test`의 `X.npy`에 정규화 전 raw
amplitude를 저장한다. Train에서 계산한 `mean`과 `std_safe`는
`normalization.npz`와 manifest에 저장하며, 학습 코드가 세 split을 읽을 때 같은
공식으로 정규화한다. 표준편차가 0에 가깝다면 나눗셈 오류를 막기 위해 안전한
값으로 바꾼 `std_safe`를 사용한다.

## 6. Manifest에 남길 값

전처리가 어떤 데이터를 선택하고 제외했는지 다시 확인할 수 있도록 세션별 처리
결과를 manifest에 기록한다.

파일 형식과 모든 최상위·세션·RX·normalization 필드의 상세 의미는
[`manifest.json` 필드 설명](%5B전처리%5D-매니페스트%20필드.md)을 따른다.

```text
session_id
label
split
RX별 입력 파일
RX별 record 수
RX별 재부팅 경계 수
선택한 segment 번호
common_start
common_end
common_length
RX별 observed_ratio
RX별 duplicate 수
RX별 단일 이상 record 수와 제외 이유
손상 제거 후 남은 tx_seq 감소 수
RX별 보간 frame 수
긴 gap 때문에 제외된 window 수
최종 window 수
세션 사용·제외 여부
제외 이유
label 규칙 (이름과 번호 매핑)
feature별 normalization 통계
```

Manifest는 모델 입력값이 아니라 전처리 결과의 검사·재현용 기록이다. Test 결과를
확인한 뒤 유리하도록 제외 기준이나 보간 기준을 바꾸는 것을 막기 위해, 사용한
임계값도 함께 저장한다.

## 9. 구현하지 않는 것

이 설계에서는 다음 항목을 결정하지 않는다.

- 64개 중 null/DC/guard subcarrier 제외
- 위상 feature 추가
- `first_word_invalid` 처리
- 모델 구조 변경

첫 baseline은 세 RX의 amplitude 64개를 사용한다. 위 항목은 전처리 정렬과 품질
검사가 안정적으로 구현된 뒤 train·validation 비교를 통해 별도로 결정한다.
