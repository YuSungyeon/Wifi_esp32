# 학습 모델 비교와 선정 권고

> 상태: **PLANNED** — 모델 후보 비교·선정 근거 문서.
> 이 문서의 성능 수치는 **외부 공개 벤치마크(SenseFi)** 결과이며, 이 프로젝트 데이터로 측정한 값이 아니다.

## 1. 무엇이 모델 선택을 좌우하는가 (이 프로젝트의 조건)

| 조건 | 값 | 모델 선택에 주는 의미 |
|---|---|---|
| 입력 | `(300, 192)` — 3초×100Hz, 3 RX×64 amplitude | 시계열 모델(RNN 계열·1D-CNN)과 2D 처리(CNN) 모두 가능 |
| feature 종류 | **amplitude만** (위상 없음) | 위상 기반 기법(Doppler, AoA)은 후보에서 제외 |
| class | 3개 — empty / static / motion | 거친 분류라 대형 모델이 필요할 근거가 약함 |
| 데이터 규모 | 29 session, window 약 28,585개 | window는 90% 겹치므로 **독립 표본은 사실상 session 29개 수준** — 소용량 모델이 유리 |
| 환경 | 단일 방(3×3m), 고정 배치 | in-domain 성능은 낙관적으로 나옴. 일반화는 별도 검증 필요 |
| 실행 환경 | Mac에서 offline 학습·평가 | 추론 지연 제약 없음 → 양방향(Bi) 모델도 무방 |

과제의 난이도 구조도 중요하다. **motion은 시간축 분산만으로도 구분이 쉽다**(움직임이 amplitude를 크게 흔든다). 진짜 난제는 **empty vs static** — 정지한 사람이 만드는 미세한 다중경로 변화를 잡아야 한다. 이 구분에는 시간 패턴보다 **3-RX 공간 배치가 주는 채널 형태 차이**가 결정적일 수 있어, 시간 모델링 능력만으로 모델을 고르면 안 된다.

## 2. 외부 벤치마크가 말해주는 것 (SenseFi, Patterns 2023)

SenseFi는 WiFi CSI 인식용 딥러닝 모델 11종을 같은 조건에서 비교한 공개 벤치마크다. 두 데이터셋 모두 **amplitude 전용·소규모 학습 데이터**라는 점에서 이 프로젝트와 조건이 비슷하다 (UT-HAR: 7행동·train 3,977개 / NTU-Fi HAR: 6행동·train 936개).

| 모델 | UT-HAR 정확도 | NTU-Fi HAR 정확도 | 파라미터 수 |
|---|---:|---:|---:|
| MLP | 92.00% | **99.69%** | 큼 (수십M, 입력 크기에 비례) |
| CNN-5 (얕은 CNN) | 97.61% | 98.70% | 0.30~0.48M |
| ResNet18 | **98.11%** | 95.31% | 11.2M |
| ResNet101 | 94.99% | 95.31% | 42.6M |
| RNN | 83.53% | 84.64% | 0.01~0.03M |
| GRU | 94.18% | 97.66% | 0.03~0.08M |
| **LSTM (현 baseline 구조)** | 87.18% | 97.14% | 0.04~0.11M |
| BiLSTM | 90.19% | **99.69%** | 0.08~0.21M |
| CNN+GRU | 96.72% | 93.75% | 0.06~1.43M |
| ViT (Transformer) | 96.53% | 93.75% | 1.1~10.6M |

읽는 법 — **절대값이 아니라 경향**을 본다 (행동 종류·하드웨어·class 수가 우리와 다르다):

1. **얕은 CNN·GRU·BiLSTM이 비용 대비 가장 안정적** — SenseFi 저자들의 공식 권고도 "CNN, GRU, BiLSTM (높은 성능 + 낮은 비용 + 적은 파라미터)"다.
2. **단방향 LSTM은 중위권** — 특히 UT-HAR에서 GRU(94.2%)·BiLSTM(90.2%)보다 낮은 87.2%. 현 baseline이 최선의 선택이 아닐 수 있다는 근거.
3. **Transformer(ViT)는 소규모 데이터에서 이점이 없다** — 파라미터·연산량은 최대급인데 정확도는 얕은 CNN 이하. 저자들도 "학습 데이터가 충분치 않으면 만족스럽게 동작하지 않는다"고 명시.
4. **깊은 모델(ResNet-101급)은 과적합으로 오히려 하락** — "얕은 모델이 CSI feature 추출에 이미 충분하다"가 벤치마크 결론.

## 3. 후보별 적합성 평가

위 근거를 이 프로젝트 조건(1절)에 대입한 평가다.

| 후보 | 장점 | 약점/위험 | 판정 |
|---|---|---|---|
| 통계 feature + RF/SVM | 구현 몇 시간, 해석 가능, 하한선 제공 | 표현력 한계 (empty vs static에서 한계 예상) | **0순위 — 하한 baseline으로 필수** |
| 1D-CNN (시간축 conv) | 파라미터 적음, 빠름, 소규모 데이터에 강함 | 긴 시간 의존성 포착 약함 (3초 window라 영향 적음) | **1순위 채택** |
| GRU | LSTM보다 파라미터 25% 적고 벤치마크 성능은 더 높음 | — | **1순위 채택** |
| BiLSTM | NTU-Fi 공동 1위, offline이라 양방향 비용 무관 | 연산 2배 | **2순위 채택** |
| LSTM (현재 구현) | 코드·문서 이미 존재, 비교 대조군 | 벤치마크에서 GRU·BiLSTM에 열세 | **유지 — 대조군** |
| CNN+GRU 하이브리드 | UT-HAR 상위권 | 두 데이터셋 간 순위 불안정 (96.7% vs 93.8%) | 보류 — 1~2순위 결과 본 뒤 |
| MLP | NTU-Fi 공동 1위 | 파라미터가 입력 크기에 비례해 폭증 (우리 입력 300×192=57,600 → 수십M) | 보류 |
| Transformer (ViT/THAT) | 대규모 데이터에서 상한 높음 | 29 session 규모에서 근거 없음, 비용 최대 | **현 단계 제외** |
| ResNet 등 깊은 CNN | — | 소규모 데이터 과적합, 벤치마크에서도 이득 없음 | **현 단계 제외** |

## 4. 권고 결론

```text
0순위  통계 baseline (window별 분산·평균 등 → RandomForest)
        → "이 정확도 밑이면 딥러닝이 무의미"라는 하한 확립
1순위  1D-CNN, GRU
        → 소규모 데이터에서 가장 안정적, 파라미터 최소
2순위  BiLSTM
        → offline이므로 비용 부담 없음, 벤치마크 최상위
대조군  LSTM (공식 3-RX 구현 유지)
제외    Transformer 계열, 깊은 ResNet — 데이터 규모 근거 부족
```

핵심 판단 이유 세 가지:

1. **독립 표본이 session 29개뿐**이므로 파라미터 0.1M 이하의 소형 모델부터 시험하는 것이 과적합 위험 대비 합리적이다.
2. 공식 LSTM은 이미 구현·문서화되어 있으며, "복잡한 모델이 정말 더 나은가"를 판정할 대조군으로 사용한다.
3. **승부처는 평균 정확도가 아니라 static class recall** (empty vs static 구분)과 **session-level 성능**이다. window가 90% 겹치므로 window-level 수치는 부풀려진다.

## 5. 자체 성능 비교 프로토콜 (실행 계획)

외부 벤치마크는 후보 선정까지만 쓰고, 최종 선택은 **우리 데이터에서 같은 조건으로 비교**해 결정한다.

공정 비교 조건 — 모든 모델에 동일 적용:

```text
전처리      : 공식 3-RX 전처리 설계 — 모델별로 다르게 만들지 않음
데이터      : 20260616, train 17 / validation 6 / test 6 session (manifest 고정)
입력        : (300, 192) float32, train 통계로만 normalization
학습        : Adam 1e-3, batch 32, 최대 50 epoch
            : validation macro-F1 기준 early stopping·best checkpoint
seed        : 고정 3개(예: 0, 1, 2)로 각 모델 3회 학습 → 평균±표준편차 보고
모델 선택   : validation만 사용. test는 전 모델 확정 후 각 1회
```

판정 기준 (우선순위 순):

1. test **macro-F1** — 특히 **static class recall** (최난이도 구분)
2. **session-level 정확도** — 같은 session의 window softmax 확률을 class별로 평균한 뒤 예측
3. 파라미터 수·학습 시간 — 동률이면 단순한 모델 채택
4. seed 간 편차 — 편차가 크면 불안정한 모델로 감점

통계 baseline(0순위)은 window별 RX·서브캐리어 평균/표준편차/시간분산 등 고정 feature를 만들어 RandomForest로 같은 split에서 평가한다. 이 값이 곧 "딥러닝이 넘어야 할 하한"이다.

## 7. 이 문서가 결정하지 않는 것

- subcarrier 유효 톤 선별·위상 feature 추가 (전처리 레포트의 미결정 항목과 동일)
- 데이터 증강(augmentation) 적용 여부
- on-device(ESP32) 추론 — 현재 요구사항 아님. 필요해지면 파라미터 제약이 바뀌므로 재평가
- hyperparameter 세부 탐색 범위 — 1차 비교 결과를 본 뒤 train·validation만 사용해 좁힌다
