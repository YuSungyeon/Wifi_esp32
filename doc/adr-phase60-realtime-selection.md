# 실시간 위상 60초 모델 선택 연결

> 상태: **ACCEPTED — 선택 연결 구현·검증 완료**, 2026-10-10. 위상 실제 보드 시험은 별도.

## 배경

기존 진폭 엔진의 모델 파일 경로만 위상으로 바꾸면 톤·창 길이·입력 변환이 어긋난다.
가중치와 기존 기본값을 보존하면서 같은 GUI·CLI에서 후보를 시험할 별도 입력 경로가 필요하다.

## 결정

GUI·CLI의 모델 선택은 `amplitude`(진폭 30초, 기본값)와 `phase60`(위상 60초)다.
각 실행은 한 모델 종류를 고정하며, 변경하려면 정지 후 새 실행을 시작한다.
위상 기본 파일은 `model_train/phase60/model_60sessions.pt`다. 현재 성능상 시험 후보로 제공한다.

| 항목 | 진폭 | 위상 |
|---|---|---|
| RX 순서 | 101, 102, 103 | 101, 102, 103 |
| raw 톤 | `[38..63, 2..26]` | `[38..63, 1..26]` |
| 창 | 3,000프레임/30초 | 6,000프레임/60초 |
| 스트림 보관 | 진폭 153열 | 복소 I/Q 156열 |
| 보간 | 진폭, 최대 5프레임 내부 공백 | 실수·허수 각각, 최대 5프레임 내부 공백 |
| 입력 변환 | 기존 `amplitude_input()` | `phase60/features.py`의 위상 잔차와 `windows()` |
| 시간 줄이기 | 10프레임 평균 | 20프레임 평균 |
| 출력 | seed 3개 softmax 평균 | seed 3개 softmax 평균 |
| 실행 이동 | 기본 30프레임/0.3초 | 기본 30프레임/0.3초 |

위상은 학습 코드와 같은 주파수축 unwrap·직선 제거 후 창 평균을 뺀다.
오프라인 세션 변환의 기본 최소 27,000프레임은 유지하며 실시간·재생은 별도 6,000프레임 경로다.
CRC·RF·식별·재부팅·역행·파일 축소 검사를 양쪽 스트림에 적용한다.
실시간 보간은 공통 창 끝까지 도착한 프레임만 사용한다. 재생에서는 완성 파일의 경계 문맥을 사용할 수 있다.

체크포인트의 형식·특징 버전·모드·100Hz·창·RX/톤·클래스·seed 수를 검사한다.
위상은 downsample=20·seed 목록도 검사한다. 진폭 다운샘플은 기존 입력 변환의 10프레임 고정 규칙이다.
위상 선택에 진폭 체크포인트를 넣거나 반대로 넣으면 실행을 거부한다.
가중치를 평가 모드로 로드하며 확신 기준이나 추가 유지 시간은 적용하지 않는다.

## 기록·표시

모델 이름·파일 해시·창 길이·준비 남은 시간·재생/실시간 구분을 상태에 기록한다.
모든 판단·준비·유지·정지 기록은 `realtime_predictions.jsonl`에 append하며,
입력 순번 범위·클래스 점수·원인·벽시각·단조 시각을 포함한다.
링버퍼·화면 이력은 제한하고 디스크 기록은 실행 길이에 비례한다.
기존 상태·이벤트·전환 표시 파일과 새 raw capture 경로를 유지한다.

`inferred=false`의 대기 행은 새 예측이 아니며 이전 점수가 남을 수 있다.
준비 중 입력 범위는 부분 입력이다. supervisor 종료 행은 입력 범위가 없을 수 있다.

GUI 300ms 폴링, 실시간 reader 0.1초 flush, 일반 수집 1초 flush는 각각 유지한다.
0.3초는 새 공통 입력 30프레임 기준 이동 설정이며 실제 표시 지연 보장이 아니다.
긴 공백은 창 밖으로 빠질 때까지 위상 60초 동안 영향을 줄 수 있다.

## 영향과 한계

2026-10-13 추가 학습 후보 `phase60_room`을 별도 선택으로 연결했다.
입력 종류는 기존 `phase60`을 재사용하고 체크포인트의 추가 학습 이력을 검사한다.
기존 모델 선택과 기본 진폭은 유지한다. 실제 설정·결과는 [새 방 추가 학습 결과](../model_train/docs/model-training/20261013-phase60-room-finetuning.md)에 있다.

같은 원본의 유효 창에서 오프라인·스트림 입력·점수를 대조하고,
모델 종류 전달·60초 준비·입력 누락·복구·종료·진폭 회귀를 검사한다.
전체 테스트 184개 통과. 실제 10/6 원본의 전체 파일/순차 prefix 24건에서 위상 입력 오차 0,
유효 22건의 점수 오차 0, 나머지 2건은 동일한 긴 공백으로 판단 불가였다.
GUI·CLI 자식 프로세스 재생·파일 append를 확인했으며 실제 무선 시험과 구분한다.
상시 위상 링버퍼 배열은 약 28.6MiB이고 임시 변환·파일 읽기는 추가 메모리를 쓴다.
새 매 판단 JSONL은 디스크 사용량을 늘리며 실행자가 여유 공간을 확인해야 한다.
현재 위상은 [앉기 오판](../model_train/docs/model-training/20261008-phase60-static-diagnosis.md)이 있어
연결 자체를 성능 개선으로 해석하지 않는다. 새 실제 시험은 작업 목록의 4번이다.
