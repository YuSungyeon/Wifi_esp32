# 호스트 도구 오류 (리더·CLI·GUI)

## 2026-08-25 — reader 가 보드가 죽어도 영원히 대기

- **증상**: `ser.timeout=1` 을 설정해놓고 타임아웃을 `continue` 로 삼킴. 보드가 죽거나 USB 가
  빠져도 빈 파일을 만들며 정상처럼 보였다. flush 도 500프레임(≈5초)에 한 번.
- **해결**: 종료 코드 분리(0 정상 / 2 IDENT 미수신 / 3 스트림 정지 / 4 파일 충돌),
  `--stall-timeout` 3초, flush 1초. pty 로 4경로 재현.
- `find_magic` 의 1바이트 read 루프 → 청크 read + `bytes.find`. 진폭 계산의 서브캐리어당
  `struct.unpack_from` 루프(12,800/s) → numpy 벡터화(`csi_store`).

## 2026-08-25 — pty 가 커스텀 baud·DTR ioctl 을 거부

- **증상**: `IOSSIOSPEED`(921600), `TIOCMBIC`(DTR) 에서 `Errno 25 Inappropriate ioctl`.
- **대응**: 테스트는 115200, DTR/RTS 는 `try/except`.
- **후일담**: 실보드에서 그 DTR 설정 자체가 리셋 원인으로 판명 ([03](03-board-reset-usb.md)).
  지금은 감싸는 게 아니라 아예 건드리지 않는다.

## 2026-08-26 — TX 포트가 rc=3(스트림 정지)로 오분류

- **원인**: TX 는 USB 로 아무것도 안 보내는데 stall timeout(3초)이 ident timeout(6초)보다 먼저.
- **해결**: 식별 전에는 stall 검사를 하지 않음 → rc=2(RX 아님).

## 2026-08-26 — GUI: 1.2초 폴링이 입력 중인 폼을 통째로 지움

- **원인**: 폴링마다 화면 전체 `innerHTML` 재렌더.
- **해결**: 섹션별 데이터 지문을 비교해 바뀐 섹션만 재렌더. 폼 섹션은 한 번만.
- **같은 원인**: 워터폴 이미지가 폴링에 지워짐 → 선택 상태를 변수로 들고 섹션 안에서 그림.
  보드 태그 `RX101 RX101` 중복(`board_name` 에 접두어 있음).

## 2026-08-26 — 워터폴 PNG 라벨·여백

- colorbar 가 `Amplitude (on-device norm)` — USB 경로는 온디바이스 정규화를 안 한다
  (deprecated AP 경로 얘기). `sqrt(I²+Q²)` 로 정정.
- RX 1대일 때 제목 겹침·x축 라벨 잘림 — 여백을 비율이 아니라 인치 기준으로.
- matplotlib 한글 두부(□) — AppleGothic 등 자동 탐색.

## 2026-09-02 — 병합 중 `measure_csi_hz.py` 를 덮어썼다가 되돌림

- **증상**: 저쪽 테스트 `test_measure_csi_hz.py` 가 `analyze_jsonl`, `result_headers` 를
  import 못 함.
- **판단**: 저쪽 구현이 재부팅·중복·순서이상까지 잡아 더 낫다. 저쪽 것을 되살리고 `.csi`
  지원(`analyze_csi`)만 얹음. 테스트 40개 통과.

## 2026-09-02 — reader 재작성 중 `--device-id` 충돌 검출 회귀

- **증상**: 다중 RX demux 로 재구성하면서 `--device-id` override 가 프레임이 와야 파일을
  열게 됨 → 파일 충돌 테스트가 rc 4 대신 rc 2.
- **해결**: 명시적 override 는 시작 즉시 연다. 실패 경로 rc 2/3/4 회귀 테스트로 확인.

## 2026-10-02 — 실시간 판단 연결과 종료 누락

- **증상**: GUI에는 상태 조회만 있고 판단 시작 버튼이 없었다. 수집 CLI에도 모델 실행
  진입점이 없었다. 기존 24,000프레임 링버퍼로 5분 녹화를 한꺼번에 읽으면 앞부분이 사라졌다.
  RX 수신 중단 후에도 유효한 이전 창을 다시 추론할 수 있었다.
- **원인**: 판단 프로세스의 실행 관리가 GUI·CLI에 없었고 재생·실시간 입력 수명이
  구분되지 않았다. 수신 대수 대신 이전 창의 대수를 조회했다.
- **시도/해결**: 원본과 분리한 실행 폴더, GUI 독립 판단 작업·시작/정지,
  `.venv` 공통 실행기를 추가했다. 재생은 정식 raw loader의 전체 구간을 사용하고,
  실시간은 세 RX의 공통 끝과 최근 수신 시각을 함께 검사한다. 새 창이 없으면 재추론하지 않는다.
- **종료 문제**: 파일 추가 시험에서 CLI 부모만 SIGTERM하면 판단 자식이 남았다.
  해당 임시 테스트 자식을 식별해 종료했고, CLI의 SIGTERM/Ctrl+C 처리에 자식 정리와
  타임아웃을 추가했다. 재시험에서 **0.3초 내 종료**, 출력 pipe EOF까지 확인했다.
- **재발 방지**: 전체 122개 테스트, CRC/부분 프레임/순번/보간/긴 재생/입력·확률 일치,
  수신 중단·별도 판단 정지·CLI 자식 종료 회귀 검사를 포함한다. 실제 보드는 연결되지
  않아 수집 중 지연·상태 전환 성능을 확인한 것처럼 보고하지 않는다.

## 2026-10-02 — 실시간 시작이 옛 녹화를 따라 읽어 판단 정지

- **증상**: 보드가 연결돼 있어도 시작 3초 후 `RX 0대 — 판단 정지`.
- **원인**: GUI의 실시간 시작은 선택한 파일을 읽는 `--follow`만 실행했다.
  실제 실행은 완료된 9/20 s60이고 수집 reader는 없었다. RX 0은 새 파일 입력이
  없다는 뜻이지 USB 보드 검색 결과가 아니었다.
- **해결**: 현재 보드용 버튼은 SINK를 새로 식별해 수집·판단을 함께 관리한다.
  옛 녹화와 외부 수집 파일 tail은 별도 고급 기능으로 분리했다. 무라벨 capture는
  `realtime/<실행>/capture`, 판단은 `prediction`에 두고 학습 세션을 건드리지 않는다.
- **추가 발견**: 정상 입력 복구 뒤에도 확정 유지 시간 동안 `suspended`가 남았다.
  유효 입력이면 `deciding`으로 복귀하고 확신·유지 시간은 그대로 적용한다.
- **실보드 확인**: 약 149초, RX101/102/103 각각 14,290/14,538/12,991프레임.
  전체 CRC·잘못된 헤더·RX 재부팅·TX 순번 역행 0, 무선 송신 실패 0,
  SINK 세션 구간 drop·USB timeout 0. 이 확인은 현재 상태의 정답률 평가가 아니다.
  정지 API 응답 0.2초, 자식 reader·판단 종료와 SINK 포트 해제 확인.
- **재발 방지**: 중복 실행·다른 수집 중 기동·포트 재검색을 막고, 자식 기동/실행
  오류 시 같은 실행의 자식을 정리한다. 포트 이름은 재연결 때 달라져 새 식별을 사용한다.

## 2026-10-02 — 0.3초 예측인데 화면은 확정을 기다림

- **증상**: 0.3초 stride인데 `판단 중`으로 오래 남고 매 창의 분류를 볼 수 없다.
- **원인**: 모델 뒤의 확신 70%·유지 1/15/60초 규칙과 GUI 1.2초 전체 폴링,
  reader 기본 파일 flush 1초가 각각 별도로 적용됐다.
- **해결**: 현재 배포 엔진은 최대 확률 클래스를 즉시 표시한다. 현재 보드 수집만
  flush 0.1초, 판단 영역만 300ms 경량 API 폴링으로 분리했다. 30초 입력 자체와
  데이터 누락 때의 안전 정지는 제거하지 않았다.
- **재발 방지**: 저확률 첫 클래스, 0.3초 클래스 전환, 입력 복구·부분 RX 거부,
  fast API가 세션·포트를 검색하지 않는 회귀 테스트. 과거 규칙은 HISTORICAL로 명시한다.

## 2026-10-06 — 첫 전환 시험의 짧은 판단 정지와 30초 판단 정지

- **증상**: 평가한 620초에서 판단 정지 74회·56.682초. 가장 긴 정지는
  00:12:43.725~00:13:13.849의 30.124초였다. 전체 수집은 정상 종료했다.
- **원인 확인**: RX103에 `tx_seq=120768 → 120775`의 6프레임 내부 누락이 있었다.
  보간 한도 5프레임을 넘으므로 공백이 최근 30초 창에서 빠질 때까지 완전한 입력이 아니다.
  긴 정지와 일관되지만, 다른 짧은 정지의 세부 원인까지 확정하지 않았다.
- **시도**: 원본 전체 286,393프레임을 검증했다. CRC/헤더 오류·재부팅·TX 순번 역행은
  없었다. 안전 정지 시간은 빈 방·정지 오분류 시간과 분리했다.
- **해결 상태**: 입력 누락은 미해결. 보간 한도나 안전 정지 규칙을 변경하지 않았다.
- **재발 방지**: 이벤트에는 모든 창의 `note`·확률이 남지 않아 사후 원인 분석에 한계가 있다.
  짧은 정지를 숨기거나 남은 구간만으로 안정성을 주장하지 않는다.
