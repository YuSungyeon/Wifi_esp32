# 보드 리셋·USB-Serial-JTAG 특성

> ESP32-S3 dev 보드의 USB-C 는 외부 UART 브리지가 아니라 **네이티브 USB-Serial-JTAG** 다. 브리지 칩(CP210x/CH340) 관례가 여기서는 거꾸로 작동한다.

## 2026-08-25 — 수집 직전 esptool 프로브가 보드(TX 포함)를 리셋

- **증상**(코드 검토): CLI `_detect_rx_boards` 가 포트마다 `esptool read_mac` 을 돌린다.
  esptool 은 DTR/RTS 로 칩을 부트로더에 넣었다 hard reset 한다.
- **영향**: TX 가 꽂혀 있으면 TX 까지 리셋 → `tx_seq` 가 0으로 되감김 → cross-RX 정렬 키가
  세션 중간에 끊긴다. 보드마다 수 초 지연, 시작 시점 어긋남.
- **해결**: RX 가 2초마다 **IDENT 프레임**(eFuse base MAC)을 송출. 호스트가 registry 조회로
  `device_id` 결정. CLI/GUI 는 포트를 프로브하지 않는다 (`csi_serial_reader.py --identify`).
- **함정**: MAC 은 `esp_efuse_mac_get_default()` 여야 한다. `esp_wifi_set_mac` 으로 STA MAC 을
  `1a:00:00:00:00:00` 으로 덮어쓰므로 `esp_read_mac(ESP_MAC_WIFI_STA)` 은 모든 보드가 같다.
- **재발 방지**: `CLAUDE.md` — 수집 시작 시 esptool 로 포트 프로브 금지. 플래시 경로에서만 사용.

## 2026-08-26 — DTR/RTS 를 눌러두는 것이 오히려 리셋을 유발

- **증상**: 첫 실보드 수집에서 `boot_changes=1`. frame #93 에서 `boot_id` 5720→903,
  uptime 2.01s→0.33s. 수집 중 RX 재부팅.
- **실험**: 같은 포트를 12초씩 두 조건으로.
  | 조건 | 재부팅 |
  |---|---|
  | `dtr=False, rts=False` (기존 코드) | **2회** |
  | 손대지 않음 | **0회** |
- **원인**: 기존 코드 주석 "포트 열 때 토글이 리셋시키는 것을 회피"는 **브리지 칩** 얘기다.
  USB-Serial-JTAG 는 ESP-IDF 드라이버가 이 선들을 직접 해석해서, 명시적으로 눌러두는
  행위 자체가 리셋 조건이 된다. 회피책이 원인이었다.
- **해결**: reader 는 DTR/RTS 를 건드리지 않는다. 브리지 칩 보드용 `--force-lines`.
- **복선**: pty 검증 때 `TIOCMBIC` ioctl 이 거부됐었다 ([07](07-host-tools.md)). 가상 환경이
  거부한 동작이 실제로도 하면 안 되는 동작이었다.
- **재발 방지**: `CLAUDE.md` — 시리얼 포트의 DTR/RTS 를 건드리지 말 것.

## 2026-08-26 — 호스트 없는 동안 쌓인 묵은 프레임이 수집 앞부분을 오염

- **증상**: `boot_changes=0` 이 됐는데 `seq_gap=4134`, 60초 수집인데 보드 타임스탬프 span 106초.
- **원인**: 보드는 호스트가 없어도 CSI 를 링버퍼에 쌓는다. 기본 ringbuf 는 가득 차면 **새 것**을
  버리므로 방치 중 버퍼가 옛 프레임으로 고정되고, 붙는 순간 그것부터 흘러나온다.
- **시도 1** — 펌웨어 keep-newest(가득 차면 가장 오래된 것 버림) + reader 가 "새 바이트 200ms
  끊길 때까지" 버림. **부분 실패**: 살아 있는 100Hz 스트림은 200ms 를 절대 쉬지 않아 매번
  상한 3초를 꽉 채워 버렸다 (백로그 없어도 328프레임/3.01초 폐기).
- **시도 2** — 도착 속도로 판별. **실패**: `ser.read()` 가 청크 단위라 한 청크의 20여 프레임이
  같은 벽시계 값을 가져 순간 속도가 무한대.
- **시도 3** — 보드 시계/벽시계 진행 비율. **부분 실패**: 기준점 고정 시 누적 비율이 천천히
  떨어져 3초를 채움.
- **최종**: 0.3초 **슬라이딩 윈도**로 현재 비율만 본다.
  | 상황 | 폐기 | 소요 |
  |---|---|---|
  | 25초 방치 후 | 472프레임 | 0.53s |
  | 곧바로 재수집 | 48프레임 | 0.38s |
- **부수**: 비우다 IDENT 를 같이 버리면 식별이 2초 미뤄진다 — IDENT 는 붙잡아 둔다.
- **재발 방지**: `CLAUDE.md` — 포트를 열자마자 기록하지 말 것. 애드혹 스크립트도 같다
  ([06](06-measurement-pitfalls.md)).

## 2026-08-26 — 펌웨어 카운터 기준점을 백로그 IDENT 에서 잡음

- **증상**: 세션 델타에 `ringbuf_drop=40~85` 가 섞여 들어옴 (실제 수집 중 드롭은 0).
- **원인**: 백로그를 비우다 건진 IDENT 를 카운터 기준점으로 썼다. 최대 링버퍼 깊이(~4초)만큼
  과거 스냅샷.
- **해결**: 식별에는 쓰되 기준점은 본 수집 시작 후 첫 IDENT. 수정 후 `ringbuf_drop=0`.

## 2026-08-26 — TX 재부팅 감지 (`tx_back`)

- **계기**: TX 를 외부 전원(보조배터리 등)에 두면 재부팅을 알아챌 방법이 필요하다.
- **문제**: `tx_seq` 역행 감지가 어디에도 없었고, 전처리가 `tx_seq` 로 **정렬**해서 재부팅
  이후 프레임이 세션 앞쪽으로 끌려가 시간이 뒤집혔다. 재현: 5000..5199 → 0..199 를 넣으니
  정렬 후 첫 프레임이 원래 200번째. 4800스텝(48초)이 선형 보간으로 채워지는데 경고 없음.
- **해결**: reader(`tx_back` + 경고), `measure_csi_hz`(`tx_back`, `tx_cov` 무효화),
  전처리(정렬 대신 **거부**). 정상 세션 오탐 없음.
- **재발 방지**: `CLAUDE.md` — `tx_seq` 를 정렬로 정리하지 말 것.

## 2026-08-26 — RX 는 호스트 연결이 필수 (TX 는 전원만)

- **측정**: 포트를 15초 닫고 재개 — `Δcsi_cb=1192  Δseq=1195  Δringbuf_drop=670`.
  보드는 계속 받지만 링버퍼(64KB≈4초)를 넘는 것은 버려진다. SD·플래시·무선 없음.
- TX 펌웨어는 호스트 입출력 코드가 없어 전원만 있으면 된다.
- **결론**: RX 를 원격에 두려면 무선 업링크가 필요 → [08](08-wireless-uplink.md).

## 2026-09-03 — 업링크 모드 RX 는 USB 로 IDENT 를 내지 않아 `--identify` 가 빈 값

- **증상**: 보드 두 개를 USB 에 꽂았는데 `csi_serial_reader.py --identify` 가 두 포트 모두
  `role=null`. 어느 포트가 어느 보드인지 알 수 없었다.
- **원인**: 업링크 모드 RX 는 IDENT 를 **ESP-NOW 로 싱크에** 보낸다. USB 로는 ESP_LOG 텍스트만
  나온다 (`5s: cb=… uplink_ok=… fail=…`). 싱크가 빠져 있으면 어느 포트에서도 프레임이 없다.
- **판별법**: (1) 포트에서 6초 읽어 텍스트에 `csi_recv: 5s:` 가 있으면 업링크 RX, v4 magic 프레임이
  있으면 싱크. (2) 어느 RX 인지는 부트 로그의 `base_mac=` 뿐이라, **수집 중이 아닐 때만**
  `esptool.py read_mac` 으로 확인한다 (리셋되지만 TX 가 USB 에 없으면 무해). 이날 `101` = RX102,
  `1101` = RX103 으로 확정 후 RX102 를 rx_id=2 로 플래시했다.
- **개선 여지**: 업링크 RX 도 부팅 후 IDENT 한 장을 USB 로 내보내면 `--identify` 가 잡는다.
  `fail` 이 계속 오르면 싱크가 없거나 꺼진 것이다 (ACK 없음) — 고장이 아니다.
