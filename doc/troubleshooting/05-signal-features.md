# 신호 처리·특징

## 2026-08-25 — `csi_amp[:52]` 가 상시 0 서브캐리어 12개를 포함

- **증상**: 실측 평균 진폭 — 인덱스 0 과 27~37 이 0.0~0.1, 나머지는 9~16.
  ```
   0- 7:   0.1  15.7  15.3  14.7  14.9  14.1  13.6  13.2
  24-31:   9.5   9.2   8.7   0.0   0.1   0.1   0.1   0.1
  32-39:   0.0   0.1   0.1   0.1   0.1   0.0  12.3  12.5
  ```
- **원인**: HT20 LLTF 64 SC 중 0(DC)·27~37(가드)은 상시 0. `[:52]` 는 이 12개를 넣고 실제
  데이터인 52~63 을 버린다 → feature 23% 상수 0, 유효 톤 23% 유실.
- **해결**: `csi_store.LLTF_DATA_IDX = [1..26] + [38..63]` (52개). 동일 데이터에서 상수 컬럼
  12/52 → **0/52**. 실보드에서도 상시 0 인덱스가 정확히 `[0, 27..37]`.
- **미결**: 모델 레포의 `preprocess_3rx.py` 는 `features_per_rx=64` — 3-RX 192 중 36개(19%)
  상수 0. 52 vs 64 결정은 모델 담당과 합의 필요 (제안: 기본 52, 64 는 ablation).

## 2026-08-26 — gain 보정 — 되돌림

- **문제**: AGC 가 게인을 바꾸면 raw 진폭이 계단식으로 뛸 것이라 예상. 실측상 45초에 AGC 483회,
  FFT gain 8~23단계 변동.
- **시도 1** — 근사식 `2^-((fft-fft0)+(agc-agc0)/4)`: 시간축 std 0.636 → **8.355**, 13배 악화. 즉시 폐기.
- **시도 2** — 벤더 `esp_csi_gain_ctrl`: 소스 없이 `.a` 로만 배포되어 호스트 이식 불가.
  보드에서 계산해 `gain_comp`(f32)를 헤더에 싣도록 v3→**v4**(44B).
  | 지표 | 보정 전 | 보정 후 |
  |---|---|---|
  | 시간축 std | 0.636 | 1.280 |
  | AGC 변화 483곳 진폭 점프 | 0.58 | 0.59 |
- **해석**: AGC 변화 지점 점프 0.58 은 평균 진폭 13 의 4% — 프레임간 변동과 구분 안 됨.
  **보정할 계단이 애초에 없다** (`manu_scale=false` 로 HW 가 이미 스케일링하는 것으로 보임).
- **결정**: `amplitude(compensate=False)` 기본. 필드는 계속 저장 — 수신기 이동·RSSI 급변
  조건에서 재검토하려면 데이터가 남아 있어야 한다.

## 2026-09-02 — 위상 ablation 이 재수집 없이 가능해짐

- `.csi` 가 raw I/Q 를 보존하므로 `ablation.py --features amp52+phase`. 위상 특징은 인접
  서브캐리어 위상차(CFO 상쇄)의 시간축 변동 — 조악한 베이스라인용. 정식 sanitization 은 모델 과제.

## 2026-09-24 — NumPy 행렬곱 경고와 실측 모델 개선

- **증상**: 3초 절대 입력 CNN은 날짜가 바뀌면 AP session F1 0.377에 머물렀다.
  후속 통계 모델 적합 중 정상 범위 입력에도 `matmul` divide/overflow/invalid 경고가 발생했다.
- **원인 확인**: 행렬곱과 비-BLAS `einsum` 계산은 정확히 일치했다. Apple ARM NumPy의
  부동소수점 경고 문제와 같은 증상이며, 실제 Inf/NaN 발생으로 단정하지 않았다.
- **시도·해결**: 윈도 상대 진폭·공유 시간 인코더·30초 문맥을 별도 실험했다. 표준화
  평균·분산 및 선형 모델 확률을 독립 계산하고, 경고는 적합 결과에 저장했다.
- **결과**: 고정 30초 A 모델의 날짜별 window F1 0.9729/0.9551, session F1 각각 1.000.
  설정 선택을 분리한 중첩 검증도 5조건 모두 사전 기준을 통과했다.
- **재발 방지**: 수치 경고를 전역으로 무시하지 않는다. 새 날짜의 독립 검증과 상태 전환
  검증 전에는 기존 두 날짜의 높은 점수를 실사용 보장으로 해석하지 않는다.
  [결과와 재현 절차](../../model_train/docs/model-training/robust-three-class-report.md)

## 2026-10-06 — 실제 전환 시험에서 빈 방을 정지로 오판

- **증상**: 사용자 방의 첫 빈 방과 마지막 빈 방에서 판단 가능한 시간 중 빈 방 표시는
  20.20%, 13.01%였다. 첫 30초를 제외해도 정지 표시가 대부분이었다.
- **원인**: 빈 방·정지 혼동을 실측했다. 구체적인 배치·환경·전처리 원인은 미확정이며,
  30초 전환 지연만으로 설명되지 않는다.
- **시도**: 사용자 실제 행동 시각과 호스트 상태 변경 이벤트를 비교하고, 두 방식으로
  유지 시간을 재계산했다. 입력 누락에 의한 판단 정지는 오분류와 별도 집계했다.
- **해결 상태**: 미해결. 이번에는 모델·가중치·보드 배치를 변경하지 않았다.
- **재발 방지**: 단일 상태 녹화의 높은 정확도를 실시간 상태 전환 성능으로 주장하지 않는다.
  수정에 이번 자료를 사용하면 개발 자료로 구분하고, 새 날짜의 시험 자료를 따로 둔다.
  [첫 전환 시험 결과](../../model_train/docs/model-training/20261006-live-transition-evaluation.md)

## 2026-10-08 — 위상 60초 재평가의 행렬곱 경고

- **증상**: NumPy 2.0.2 / macOS ARM에서 위상 투영 행렬·위상 잔차의 `matmul` 계산 중
  divide by zero, overflow, invalid 경고가 발생했다.
- **원인 확인**: 이전 9/24와 유사한 증상이다. 경고 자체의 런타임 원인은 이번에 확정하지 않았다.
- **시도**: 투영 행렬과 12,288개 합성 신호의 잔차를 `einsum(optimize=False)`로 독립 계산해
  절대 오차 1e-12 이내를 확인했다. 실제 평가에서는 창의 유한성과 점수 합을 검사했다.
- **해결 상태**: 실제 수치 이상은 검사에서 발견되지 않았고, main의 15세션 판정과 반올림된
  창 정답률을 재현했다. 경고 자체는 남아 있다. 코드·수식·가중치는 main 원본을 보존했다.
- **재발 방지**: 전역 경고 무시를 추가하지 않는다. 새 입력에도 유한성·독립 계산 검사를 유지한다.
  [위상 재평가 결과](../../model_train/docs/model-training/20260916-17-phase60-evaluation.md)

## 2026-10-08 — 위상 모델이 실제 앉기 구간을 빈 방으로 오판

- **증상**: 9/16·17에서 14/15를 맞힌 위상 모델을 10/6 실제 전환 raw에 재생하자,
  앉기/정지로 간주한 181초 동안 정지 표시는 0초였다. 152.19초는 빈 방, 28.81초는 움직임이다.
- **원인 확인**: 구체적인 환경·위상 신호 원인은 미확정이다. 전환 후 첫 60초를 제외한
  121초에도 정지 오판이 남아 창에 이전 걷기가 섞인 것만으로 설명되지 않는다.
- **시도**: 전체 파일·원본 prefix 두 재생, 공식 입력 변환 대조, 원본 prefix 직접 입력 검사를 수행했다.
  입력 불일치나 가중치 변화는 발견하지 않았으며 같은 원본 진폭은 정지 일치율 87.73%였다.
- **해결 상태**: 미해결. 위상 기본 교체를 보류하고 선택형 시험 후보로 남겼다.
- **재발 방지**: 세션 전체 평균 정확도와 실제 전환의 시간 기준 일치율을 구분한다.
  이 자료로 조정한 개선은 별도 새 전환 시험으로 확인한다.
  [전환 재생 비교](../../model_train/docs/model-training/20261006-phase60-transition-replay.md)

## 2026-10-08 — 정지 오판 후속 진단: 시간 패턴 의존성

- **증상**: 위상 모델이 이번 앉기 구간을 빈 방으로 분류하지만 과거 정지 자료는 구분한다.
- **원인 확인**: 학습·평가 75세션을 대조했다. 학습 정지의 0.2초 연속성 중앙값 0.754에 비해
  이번 앉기는 0.124로 빈 방에 가까웠다. 크기가 비슷한 과거 정지는 구분하므로 변화량만의 문제는 아니다.
- **시도**: 정지를 맞힌 과거 14창의 시간 순서를 섞고 신호별 평균·표준편차를 유지하자 14창 모두 빈 방이 됐다.
  이번 입력을 부드럽게 만들고 원래 변화량으로 맞추면 앉기 3창과 빈 방 4창 모두 정지가 됐다.
- **해결 상태**: 모델이 의존하는 시간 패턴과 이번 입력의 불일치를 확인했다. 물리적 환경 원인은 미확정이다.
  평활화는 빈 방 오탐을 만들므로 해결책으로 적용하지 않았다. 원본·가중치·실시간 경로는 그대로다.
- **재발 방지**: 학습 메모에는 서기·의자·바닥 앉기가 모두 있어 자세 하나만 원인으로 단정하지 않는다.
  같은 방에서 위치·자세를 교차한 반복 시험으로 세부 원인을 분리한다.
  [정지 오판 원인 분석](../../model_train/docs/model-training/20261008-phase60-static-diagnosis.md)
