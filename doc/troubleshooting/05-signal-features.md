# 신호 처리·특징

## 2026-08-25 — `csi_amp[:52]` 가 상시 0 서브캐리어 12개를 포함

- **증상**: 실측 평균 진폭 — 인덱스 0 과 27~37 이 0.0~0.1, 나머지는 9~16.
  ```
   0- 7:   0.1  15.7  15.3  14.7  14.9  14.1  13.6  13.2
  24-31:   9.5   9.2   8.7   0.0   0.1   0.1   0.1   0.1
  32-39:   0.0   0.1   0.1   0.1   0.1   0.0  12.3  12.5
  ```
- **원인**: HT20 LLTF 64 SC 중 0(DC)·27~37(가드)은 상시 0. `[:52]` 는 이 12개를 넣고 실제
  데이터인 52~63 을 버린다 → feature 23% 상수 0, 유효 톤 23% 유실.
- **해결**: `csi_store.LLTF_DATA_IDX = [1..26] + [38..63]` (52개). 동일 데이터에서 상수 컬럼
  12/52 → **0/52**. 실보드에서도 상시 0 인덱스가 정확히 `[0, 27..37]`.
- **미결**: 모델 레포의 `preprocess_3rx.py` 는 `features_per_rx=64` — 3-RX 192 중 36개(19%)
  상수 0. 52 vs 64 결정은 모델 담당과 합의 필요 (제안: 기본 52, 64 는 ablation).

## 2026-08-26 — gain 보정 — 되돌림

- **문제**: AGC 가 게인을 바꾸면 raw 진폭이 계단식으로 뛸 것이라 예상. 실측상 45초에 AGC 483회,
  FFT gain 8~23단계 변동.
- **시도 1** — 근사식 `2^-((fft-fft0)+(agc-agc0)/4)`: 시간축 std 0.636 → **8.355**, 13배 악화. 즉시 폐기.
- **시도 2** — 벤더 `esp_csi_gain_ctrl`: 소스 없이 `.a` 로만 배포되어 호스트 이식 불가.
  보드에서 계산해 `gain_comp`(f32)를 헤더에 싣도록 v3→**v4**(44B).
  | 지표 | 보정 전 | 보정 후 |
  |---|---|---|
  | 시간축 std | 0.636 | 1.280 |
  | AGC 변화 483곳 진폭 점프 | 0.58 | 0.59 |
- **해석**: AGC 변화 지점 점프 0.58 은 평균 진폭 13 의 4% — 프레임간 변동과 구분 안 됨.
  **보정할 계단이 애초에 없다** (`manu_scale=false` 로 HW 가 이미 스케일링하는 것으로 보임).
- **결정**: `amplitude(compensate=False)` 기본. 필드는 계속 저장 — 수신기 이동·RSSI 급변
  조건에서 재검토하려면 데이터가 남아 있어야 한다.

## 2026-09-24 — NumPy 행렬곱 경고와 실측 모델 개선

- **증상**: 3초 절대 입력 CNN은 날짜가 바뀌면 AP session F1 0.377에 머물렀다.
  후속 통계 모델 적합 중 정상 범위 입력에도 `matmul` divide/overflow/invalid 경고가 발생했다.
- **원인 확인**: 행렬곱과 비-BLAS `einsum` 계산은 정확히 일치했다. Apple ARM NumPy의
  부동소수점 경고 문제와 같은 증상이며, 실제 Inf/NaN 발생으로 단정하지 않았다.
- **시도·해결**: 윈도 상대 진폭·공유 시간 인코더·30초 문맥을 별도 실험했다. 표준화
  평균·분산 및 선형 모델 확률을 독립 계산하고, 경고는 적합 결과에 저장했다.
- **결과**: 고정 30초 A 모델의 날짜별 window F1 0.9729/0.9551, session F1 각각 1.000.
  설정 선택을 분리한 중첩 검증도 5조건 모두 사전 기준을 통과했다.
- **재발 방지**: 수치 경고를 전역으로 무시하지 않는다. 새 날짜의 독립 검증과 상태 전환
  검증 전에는 기존 두 날짜의 높은 점수를 실사용 보장으로 해석하지 않는다.
  [결과와 재현 절차](../../model_train/docs/model-training/robust-three-class-report.md)

## 2026-10-12 — 실시간 스트림의 진폭이 학습 때와 달랐다 (I/Q 보간)

- **증상**: 창 3초 1단계 모델이 raw 세션을 직접 읽으면 정지 세션에서 p_motion 평균 0.095 인데,
  실시간 경로(`realtime/stream.py`)를 거치면 **0.361** 이 나왔다. 합성 세션에서는 정지 구간의
  13% 가 "움직임"으로 보였다.
- **먼저 아닌 것을 지웠다**: 합성 세션의 RX 정렬(구간마다 오프셋 0, tx_seq 역행 0), 떠온
  토막 자체(원본에서 같은 구간을 직접 재면 0.101), 톤 순서·열 배치(두 경로 모두 `RAW_INDICES`
  와 `transpose(1,0,2)`). 전부 같았다.
- **원인**: 스트림이 짧은 공백을 **복소 성분(I·Q)별로 선형 보간**했다. CFO 때문에 I·Q 는
  프레임마다 빠르게 회전하므로 공백 양끝의 위상이 반대면 보간값이 상쇄되어 **진폭이 0 으로
  꺼진다**. 같은 구간에서 학습 경로의 최솟값이 1.41 인데 스트림은 **0.00**, 최대 차이 18.1 이었다.
- **왜 이제야 드러났나**: 공식 **위상** 경로(`phase60/features.session_phase`)는 성분별 보간이
  맞다 — 위상 잔차를 구하려면 복소값이 필요하다. 스트림은 그쪽을 따랐다. 공식 **진폭**
  경로(`robust/predict.load_raw_amplitude`)는 **크기(`np.abs`)를 보간한다.** 두 공식 경로가
  서로 다른데 스트림이 하나만 따라갔다.
- **해결**: 스트림이 진폭은 크기를 보간하고, 위상은 성분별 보간을 유지한다(두 공식 경로를
  각각 그대로). 고친 뒤 스트림 진폭과 학습 경로가 **1.9e-06** (float32 반올림)까지 일치한다.
- **영향 범위**: 창 30초 배포 모델은 3000 행 중 몇 줄이 평균에 희석돼 결과가 사실상 같았다 —
  문서의 다섯 세션 반응 시간(45·63·31·45·59초)이 그대로 재현됐고 확신도만 한 곳에서
  96%→95% 로 바뀌었다. **창이 짧을수록 치명적이다**: 3초 창에서는 꺼진 한 줄이 곧 움직임이다.
- **재발 방지**: `tests/test_realtime.py::StreamInputTest` 가 실시간 스트림의 진폭을 공식
  학습 경로와 같은 세션·같은 tx_seq 구간에서 직접 비교한다(허용 오차 1e-4). 또한 보간된
  칸의 진폭이 세션 최솟값의 절반 아래로 내려가지 않는지 본다 — 이 버그의 고유 증상이다.
  **일반 규칙: 실시간 경로가 모델에 넣는 입력은 학습 경로와 값으로 대조한다. 같은 함수를
  쓴다는 것만으로는 같은 값이 보장되지 않는다.**

## 2026-10-30 — 재생 전처리와 실시간 진폭의 미세한 수치 차이

- 증상: pilot75 재생 입력 검증에서 실시간 창과 오프라인 진폭의 완전 일치 검사 실패(최대 약 1.9e-6).
- 원인: `csi_store.complex_csi`는 complex128을 반환하며 오프라인은 float64로 크기를 구한다.
  실시간 스트림은 float32 I/Q를 보관하고 complex64 크기를 구한다.
- 시도·해결: 평가용 진폭을 실시간과 동일한 complex64 크기→짧은 공백 보간으로 계산했다.
  오프라인 참조와는 float32 반올림 허용오차로 대조하고, 현재 `CsiStream.latest`와는 진폭 완전 일치를 확인한다.
- 재발 방지: 3/15/30/60초의 유효/무효 경계 창 대조를 평가 실행 전에 수행한다.
  원본·기존 학습 코드·배포 가중치는 바꾸지 않는다. 첫 실패 해시는 실험 출력에 보존했다.
