# 수집 프로토콜

> 상태: **OFFICIAL DESIGN** — 파일럿 이후 본 수집 규모를 확정하며 갱신한다.
> 소비처: 수집 운영자, `scripts/meshsense_gui.py`, `model_train/preprocessing/preprocess_3rx.py`

무엇을 얼마나 어떤 순서로 찍을지 정한다. **수집 순서와 조건 배치는 사후에 고칠 수 없다** —
잘못 모으면 재수집 외에 방법이 없으므로 데이터를 모으기 전에 확정한다.

## 1. 왜 순서가 중요한가 — 세션 교란

가장 흔히 결과를 무너뜨리는 것은 모델이 행동이 아니라 **세션 자체를 학습**하는 경우다.
`empty` 를 오전에, `motion` 을 오후에 몰아 찍으면 두 클래스는 시간대의 채널 상태로도
완벽히 갈린다. 세션 단위 교차검증도 이것을 막지 못한다 — 같은 클래스의 세션들이
시간·배치상 뭉쳐 있으면 세션 하나를 빼도 그 덩어리가 그대로 남는다.

`scripts/check_separability.py` 의 **세션지문** 지표가 이 현상을 수치로 드러낸다:

```text
세션지문 = (같은 클래스 안 세션 간 흩어짐) / (클래스 간 흩어짐)
```

1 을 넘는 특징은 클래스보다 세션을 더 잘 구분한다는 뜻이다. 합성 데이터 검증에서 세
클래스가 **통계적으로 완전히 동일한데도** 세션 혼합 AUC 가 1.000 까지 나왔다.

따라서 아래 두 규칙을 지킨다.

- **라운드로빈**: 한 블록 안에서 세 클래스를 연이어 찍는다. 클래스별로 몰아 찍지 않는다.
- **조건 교차**: 각 조건(날짜·배치·피험자)에서 세 클래스를 모두 찍는다.

## 2. 클래스 정의

| 라벨 | 정의 | 운영 지침 |
|---|---|---|
| `empty` | 공간에 사람 없음 | 운영자도 방 밖으로 나간다. 문·창문 상태를 기록한다 |
| `static` | 사람이 있으나 움직이지 않음 | 지정 위치에 서거나 앉아 정지. 호흡 외 움직임 없음 |
| `motion` | 사람이 움직이는 중 | **자유 보행** — 방 안을 자유롭게 걷는다. 경로를 지정하지 않는다 |

`motion` 을 자유 보행으로 둔 이유: 경로를 고정하면 모델이 그 경로를 외울 수 있고,
목표가 "사람이 움직이는가"이지 "어떤 경로로 움직이는가"가 아니다.

## 3. 세션 길이 — 최소 5분

공식 전처리가 `min_common_length = 27000` 샘플을 요구한다. 100Hz 기준 **270초**이고,
이것은 **3-RX 공통 구간** 길이다. 손실·정렬로 앞뒤가 잘리므로 여유를 두어 **한 세션
5분(30000 샘플)** 으로 찍는다. 5분 미만 세션은 전처리에서 통째로 제외된다.

## 4. 블록 구조

**블록** = 한 조건에서 세 클래스를 한 번씩. 블록 하나에 약 20분 (5분 × 3 + 전환).

```text
블록 = { empty, static, motion }  ← 순서는 블록마다 무작위로 섞는다
조건 = (날짜, 보드 배치, 피험자)
```

블록 안에서 순서를 섞는 이유: 항상 `empty → static → motion` 이면 순서 자체가
클래스와 상관되어 시간에 따른 채널 변화가 라벨과 얽힌다.

## 5. 파일럿 (먼저 할 것)

**목적**: 이 배치로 3-class 가 갈리기는 하는지. 특히 `empty` vs `static`.
`action` 은 시간축 진폭 변동이 커서 잘 갈리지만, 정지한 사람은 다중경로를 바꿀 뿐
시간에 따라 흔들지 않아 훨씬 어렵다.

| 항목 | 값 |
|---|---|
| 블록 | **2개** — 서로 다른 조건에서 (예: 다른 날, 또는 다른 배치) |
| 세션 | 6개 (블록 2 × 클래스 3) |
| 세션당 | 5분 |
| 총 소요 | 약 45분 |

**조건을 2개 이상으로 나누는 것이 핵심이다.** 한 조건에서 6세션을 찍으면 세션 단위
교차검증이 클래스와 세션을 구분할 수 없어 파일럿의 목적이 사라진다.

수집 후:

```bash
python scripts/check_separability.py --out separability.png
```

판정 기준 (쌍별 2-class 세션 단위 LOSO, 무작위 = 0.500):

| LOSO 정확도 | 해석 | 다음 조치 |
|---|---|---|
| ≥ 0.85 | 잘 갈림 | 본 수집 진행 |
| 0.70 ~ 0.85 | 약하게 갈림 | 배치를 조정하고 파일럿 재실행 |
| < 0.70 | 사실상 구분 불가 | **본 수집 금지.** 배치·RX 대수부터 재검토 |

`세션지문 > 1` 인 특징이 판정을 좌우하면 조건 교차가 부족한 것이다.

## 6. 본 수집 (파일럿 통과 후 확정)

변화시킬 조건 — 파일럿 결과를 보고 블록 수를 정한다.

| 조건 | 계획 | 일반화 주장 |
|---|---|---|
| 날짜 | 여러 날에 걸쳐 | "다른 날에도 동작한다" |
| 보드 배치 | 몇 가지 배치로 변경 | "배치가 바뀌어도 동작한다" |
| 피험자 | 여러 명 | "다른 사람에게도 동작한다" |
| 공간 | 단일 방 (이번 범위 밖) | 방 일반화는 주장하지 않는다 |

**배치를 바꾸면 `device_registry.csv` 의 좌표(`room_x_m`, `room_y_m`, `height_m`,
`orientation_deg`)를 반드시 갱신한다.** 지금은 전부 0이라 논문 배치도를 그릴 수 없다.

### 분할 — 무작위가 아니라 조건 단위

```text
train      : 대부분의 조건
validation : 남은 조건 중 일부
test       : 학습에 한 번도 안 쓴 조건 (다른 날 + 다른 피험자)
```

**test 를 무작위 세션으로 뽑지 않는다.** 그러면 "본 적 있는 날·사람"에서만 평가하게 되어
일반화 주장이 성립하지 않는다. 조건 단위로 떼야 논문에서 방어할 수 있다.

## 7. 세션 하나 찍는 절차

1. 제어판 **실험 정보** 탭에 이번 조건(날짜·배치·피험자·메모)을 기록
   (`python scripts/meshsense_gui.py`)
2. **보드** 탭에서 RX 인식 확인. TX 는 외부 전원, 전원만 들어오면 된다
3. 시나리오를 준비하고(`empty` 면 방을 비운다) **수집** 탭에서 라벨 선택 → 5분
4. **세션** 탭에서 품질 확인. 아래 중 하나라도 걸리면 **그 세션은 버리고 다시 찍는다**

| 지표 | 기준 | 어긋나면 |
|---|---|---|
| `hz` | 100 ± 3 | 배치·간섭 확인 |
| `crc_fail` / `invalid` / `resync` | 0 | 스트림 손상 |
| `seq_gap` | 0 | 시리얼 구간 손실 |
| `boot_changes` | 0 | 수집 중 RX 재부팅 |
| `tx_back` | 0 | **수집 중 TX 재부팅 — 시간 격자 파손** |
| `tx_cov` | > 0.99 | 공중 손실 과다 |
| cross-RX 공통 `tx_seq` | > 98% | RX 간 정렬 불량 |
| `rssi_med` | −25 ~ −40 | 너무 강하면 TX–RX 거리를 벌린다 |

5. 다음 클래스로 전환. 블록이 끝나면 조건을 바꾼다

## 8. 평가 프로토콜 — 데이터를 보기 전에 고정한다

수집 후에 지표나 분할을 바꾸면 결과를 신뢰할 수 없다. 아래를 미리 못 박는다.

- **분할**: 조건 단위 (§6). 윈도 단위 무작위 분할 금지 — 윈도가 3초/0.3초 stride 라
  이웃끼리 90% 겹쳐 같은 구간이 train·test 양쪽에 들어간다
- **주 지표**: 3-class 정확도 + 클래스별 recall + 혼동행렬. 클래스 불균형이 있으면
  macro-F1 을 함께 보고한다
- **베이스라인**: `check_separability.py` 의 최근접 중심 LOSO. 모델이 이보다 못하면
  복잡도가 정당화되지 않는다
- **ablation**: RX 대수(1/2/3) · 윈도 길이 · 서브캐리어 52 vs 64 ·
  **진폭 단독 vs 진폭+위상**

마지막 항목은 `.csi` 가 raw I/Q 를 보존하기 때문에 **재수집 없이** 가능하다
([data-schema.md](data-schema.md)). 진폭만 쓰기로 한 초기 결정을 사후에 검증할 수 있다.

## 9. 기록해야 할 것

세션마다 자동으로 남는 것 (`session.json`): 라벨, 시각, RX별 품질 통계, 펌웨어 카운터,
`session_meta.yaml` 스냅샷.

**사람이 기록해야 하는 것** — 제어판 실험 정보 탭:

- 조건 식별자 (날짜 / 배치 번호 / 피험자 식별자)
- 보드 배치: `device_registry.csv` 의 좌표를 실측값으로 갱신
- 방 상태: 문·창문, 가구 이동, 다른 사람의 유무
- `motion` 세션의 보행 범위, `static` 세션의 피험자 위치

피험자 식별자는 개인정보가 아니라 `S1`, `S2` 같은 익명 코드로 적는다.
