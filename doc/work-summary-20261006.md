# 10월 6일까지 작업과 결과 요약

> 상태: **CURRENT — 2026-10-06 기준 구현·평가 현황**

## 결론

**3분류 모델 학습과 GUI·CLI 실시간 연결은 완료했다. 안정적인 실사용 성능은 아직 확보하지 못했다.**
빈 방과 정지한 사람의 구분이 약하고, 실시간 입력 누락에 따른 판단 정지도 남았다.
구현 완료와 성능 검증 완료를 구분한다.

## 완료한 작업

- 9/19·20의 60세션, 1,124개 구간으로 최종 30초 상대 진폭 모델을 학습했다.
  공유 CNN을 서로 다른 시작값으로 3번 학습한 뒤 예측 확률을 평균한다.
- 날짜·배치별로 세션 전체를 분리해 평가하고, 후보 선택 자료까지 분리하는 절차도 검사했다.
  마지막 전체 학습 파일과 각 분할의 평가용 모델은 서로 다른 파일이다.
- 저장한 최종 모델을 그대로 9/16·17의 15세션에 적용해 품질·성능을 확인했다.
- GUI의 실시간 시작과 CLI `--live --port`가 현재 SINK 수집·모델 판단을 함께 실행한다.
  중복 포트 사용을 막고 자신이 시작한 수집·판단만 함께 종료한다.
- RX 3대의 공통 입력을 검사하고, 최초 30초 이후 0.3초 간격의 새 입력으로 판단한다.
  확률 70% 기준이나 추가 확정 대기 없이 최대 확률 클래스를 바로 표시한다.
- 판단 영역은 300ms 폴링, 실시간 reader는 0.1초 파일 flush를 사용한다.
  일반 수집 기본 flush·원본 형식·모델 가중치는 변경하지 않았다.
- 한 사람이 방에서 빈 방→걷기→앉기/정지→걷기→빈 방 순서로 실제 전환 시험을 했다.
  사용자 행동 시각과 상태 변경 로그를 비교하고 준비·마지막 재입실 구간은 제외했다.
- 회귀 테스트·쉬운 설명·실행 안내·작업 기록·트러블슈팅·전환 시험 보고서를 정리했다.

### 10/6 첫 실시간 전환 시험

- 평가 구간: 자정 이후 00:05:05~00:15:25, 총 620초.
- 판단 가능한 시간 중 정답 표시 비율: 첫 빈 방 **20.20%**, 첫 걷기 74.39%,
  앉기/정지 86.32%, 두 번째 걷기 64.74%, 마지막 빈 방 **13.01%**.
- 걷기 첫 반응은 약 16·24초. 마지막 퇴실 뒤 빈 방은 약 86초 후 처음 표시됐지만
  10초 연속 유지되지 않았다. 앉기 시작과 완전 정지 시각은 구분해 기록하지 못했다.
- 판단 정지: 74회·56.682초. RX103의 6프레임 누락과 일관된 약 30초 정지가 있었다.
- 첫 30초를 제외해도 빈 방을 주로 정지로 오판했다. 단순 전환 지연만의 문제는 아니다.

이 비율은 **시간 기준 표시 일치율**이다. 녹화 자료의 구간 정확도와 같은 지표가 아니며,
한 사람·한 방·한 번의 시험으로 일반 정확도나 지연 상한을 주장하지 않는다.
근거: [첫 실시간 상태 전환 시험](../model_train/docs/model-training/20261006-live-transition-evaluation.md).

## 실행 방법

```bash
.venv/bin/python scripts/meshsense_gui.py
```

제어판의 **실시간 → 실시간 시작**을 누른다. TX·RX 3대 전원과 SINK USB 연결이 필요하다.
CLI로 실행하려면 아래 `<SINK 포트>`를 현재 식별된 실제 포트로 바꾼다.

```bash
.venv/bin/python scripts/meshsense_cli.py --live --port <SINK 포트>
```

상세: [실시간 판단의 현재 동작](realtime-inference.md).
