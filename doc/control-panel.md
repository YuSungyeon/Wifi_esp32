# 제어판·CLI 흐름 설계

> 상태: **CURRENT** (2026-10-18 설계·구현)
> 범위: `scripts/meshsense_gui.py`(제어판), `scripts/meshsense_cli.py`(터미널 메뉴),
> `scripts/csi_session.py`(품질 문장)
>
> **2026-10-12 판을 대체한다.** 그 판은 탭 7개를 두고 위에 **단계 띠**를 얹어 흐름을
> 드러내려 했다. 구현 전에 다시 보니 "수집 따로, 실험 정보 따로라 복잡하다" 는 문제가
> 남아 있었고, 원인이 드러났다 — **실험 정보 12칸 중 블록마다 바뀌는 것은 3칸뿐인데
> 나머지 9칸 때문에 탭을 하나 통째로 쓰고 있었다.** 그래서 **더하는 대신 덜어내는** 쪽으로
> 바꾼다. 바뀐 항목 대조는 §8.

## 1. 누가 쓰는가

| 화면 | 1순위 사용자 | 목표 |
|---|---|---|
| 제어판 (GUI) | 비개발자 수집 담당자 | 문서를 보지 않고도 수집 → 세션 확인 → 학습 → 실시간까지 혼자 끝낸다 |
| CLI | 개발자 | 번호 메뉴는 유지한다. 빠진 단계(세션 보기·실시간)만 추가한다 |

둘의 기능을 1:1 로 맞추지 않는다. 터미널로 나가야 끝나는 작업은 비개발자 제어판에서 뺀다.

## 2. 탭은 네 개 — 할 일이 네 가지다

```text
수집 · 세션 · 학습 · 실시간 (· 연동 — 2026-10-25, §6b)
```

기본 탭은 **수집**이다 — 담당자가 하루에 가장 자주 여는 탭이다.

탭 이름이 곧 할 일이고, 순서가 곧 작업 순서다. 7개였을 때는 "보드"·"실험 정보"·"진단·
데이터셋" 처럼 **할 일이 아니라 물건 이름**인 탭이 섞여 있어, 처음 보는 사람이 무엇을
눌러야 할지 고르는 데 시간을 썼다.

| 없앤 탭 | 어디로 | 왜 |
|---|---|---|
| 보드 | 수집 탭 맨 위 **준비 줄** | 보드는 수집의 전제 조건이지 따로 하는 일이 아니다. 평소엔 한 줄, 막혔을 때만 펼친다 |
| 실험 정보 | 수집 탭 **접힌 설정** | 12칸 중 3칸만 블록마다 바뀐다(§3) |
| 진단·데이터셋 | 세션 탭 아래 **글자 링크** | 모아 둔 세션에 하는 일이고, 1년에 몇 번 쓴다 |

### 공통 규칙 세 가지

이 문서의 화면 결정은 모두 아래에서 나온다.

1. **버튼은 자기가 무엇을 할지 말한다.** `수집 시작` 이 아니라 `static 수집 시작`,
   `학습 시작` 이 아니라 `15세션으로 학습 시작 — 약 27분`. 누르기 전에 결과를 알 수 있다.
   못 누르는 버튼은 **왜 못 누르는지**를 자기 라벨에 적는다(`수집 시작 — RX 3대가 필요합니다`).
2. **거의 안 바뀌는 값은 글자 한 줄로 내린다.** 입력칸으로 두면 매번 읽고 지나가야 한다.
   글자로 두고 `바꾸기` 를 누르면 입력칸이 나온다.
3. **문제는 막힌 자리에서 푼다.** 보드가 안 보이면 수집 화면에서 바로 해결한다. 다른 탭으로
   보내지 않는다.

## 3. 수집 탭

위에서 아래로 읽으면 그게 작업 순서다.

```text
✓ 준비됐습니다   RX 3대 · 99.8Hz · 좌표 기록됨            자세히 ▸

다음 세션
s48   2026-10-18 · 배치 P2 · 피험자 S1

블록 순서
[empty ✓] [static ←지금] [motion]   다시 뽑기
블록이 끝나면 새로 뽑습니다.

300초 녹화 · 10초 뒤 시작   바꾸기

[           static 수집 시작           ]

▸ 이번 실험 설정   P2 · S1 · 메모 없음
```

### 3.1 준비 줄 — 옛 보드 탭

한 줄로 접혀 있고, `level ∈ ok | warn | block` 이다. `block` 이면 수집 버튼이 잠긴다.

| 점검 | ok 조건 | block 인가 |
|---|---|---|
| RX 보드 | 등록된 RX 3대가 모두 보임 | **block** (3대 미만) |
| 미등록 RX | 미등록 보드 없음 | warn — 펼침에 `RX<다음 id> 로 등록` 버튼 |
| 보드 좌표 | `device_registry.csv` 의 `room_x_m`/`room_y_m` 이 0 이 아님 | warn |
| 코드 출처 | 커밋되지 않은 변경 없음 | warn |
| 실행 환경 | `pyserial` import 가능 | **block** |
| 학습 환경 | `.venv` 에 numpy·matplotlib·torch | warn — 수집은 막지 않는다 |
| ESP-IDF | `esp-idf/export.sh` 존재 | 점검하지 않는다 ↓ |

펼치면 RX별 한 줄(연결 상태·Hz·좌표)과 위 경고의 해결 버튼이 나온다. 펌웨어 플래시도
여기서 한다.

**수집에 필요한 것만 막는다.** 수집은 `pyserial` 만 있으면 된다. torch·matplotlib 은 학습과
파형 그림에만 쓰이므로 없어도 수집은 돌아가야 한다 — 수집용 노트북에 torch 가 없다고 수집을
막으면 안 된다. 학습 탭에서는 같은 경고가 **block** 이 된다.

**Hz 는 실측하지 않는다.** 보드 Hz 를 실시간으로 알려면 포트를 열어 IDENT 카운터를 두 번
읽어야 하는데, 시리얼 포트는 배타적이고 **수집 중 포트를 건드리는 것은 금지**다(CLAUDE.md).
준비 줄의 Hz 는 **그 보드의 마지막 세션 매니페스트 값**이고 `지난 세션 99.8Hz` 처럼 출처를
함께 적는다. 보드가 처음이면 칸을 비운다.

**갱신 시점**: 서버 시작 시 1회, `다시 찾기` 버튼, 그리고 수집 JOB 이 끝난 직후. **`JOB`
이 도는 동안에는 다시 찾지 않는다** — 수집기와 포트를 두고 다툰다. 그 동안 준비 줄은
`수집 중` 으로 바뀌고 점검을 멈춘다.

**ESP-IDF 는 준비 줄에 넣지 않는다** — 플래시할 때만 필요하고 수집 담당자는 대개 플래시된
보드를 받는다. 펼친 뒤 플래시를 누를 때만 확인하고, 없으면 `scripts/idf_bootstrap.py -y` 를
`JOB` 으로 돌리는 **준비하기** 버튼을 보인다.

**포트를 프로브하지 않는다** — MAC 은 IDENT 로 이미 안다 (CLAUDE.md 재발 방지).
등록 이름은 브라우저 `prompt()` 로 묻고 기본값은 `RX<id>`.

### 3.2 블록 순서는 진행 상태가 된다

지금은 순서를 뽑아 주기만 하고 어디까지 찍었는지는 사람이 기억한다. 세 칸을
`끝남 / 지금 / 남음` 으로 보이고, **다음 라벨은 순서가 정한다** — 버튼이
`static 수집 시작` 이 되는 근거다. 라벨 선택 상자는 없앤다. 순서를 벗어나 찍고 싶으면
칸을 직접 눌러 `지금` 을 옮긴다.

블록 세 칸이 모두 끝나면 자동으로 새로 뽑는다. 순서를 섞는 이유는
[수집 프로토콜](collection-protocol.md) §4 에 있다.

**진행 상태는 서버가 들고 있다.** 지금 순서는 브라우저 `localStorage`(제어판)와 CLI 의
메모리(`_draw_block_order`)에 따로 있어 서로 모른다. 진행까지 거기 두면 브라우저를 새로
고치면 사라지고 CLI 로 찍은 세션이 반영되지 않는다. `mac_collector/block_order.json`
(registry 와 같은 자리, 실험 데이터 아님) 한 파일에 `{뽑은 순서, 끝난 라벨, 뽑은 시각}` 을
두고 제어판·CLI 가 함께 읽는다.

**칸이 `끝남` 이 되는 조건**: 수집 JOB 이 `rc=0` 으로 끝나고 그 세션의
`quality()` level 이 `recollect` 가 **아닐** 때. `recollect` 면 칸을 되돌린다 — §4.2 의 문장이
이미 "같은 라벨로 다시 찍으세요" 라고 말하고 있으므로 화면도 같은 말을 해야 한다.
`check` 는 끝난 것으로 센다(학습에 쓸 수 있다).

**초기화**: 세 칸이 다 끝나면 새로 뽑는다. 날짜가 바뀌어도 새로 뽑는다 — 블록은 하루를
넘기지 않는다. `배치 번호`·`피험자 코드` 가 바뀌면 조건이 바뀐 것이므로 역시 새로 뽑는다
([수집 프로토콜](collection-protocol.md) §4 의 "조건 = (날짜, 보드 배치, 피험자)").
새로 뽑을 때 화면에 이유를 한 줄로 적는다(`배치가 바뀌어 새 블록을 뽑았습니다`).

전이는 순수 함수로 뺀다(`scripts/block_order.py`) — §10 에서 테스트로 고정한다.

### 3.3 실험 정보는 3 + 7 로 나눈다

| 묶음 | 칸 | 어디에 |
|---|---|---|
| 블록마다 바뀜 | 배치 번호 · 피험자 코드 · 메모(`operator.notes`) | `▸ 이번 실험 설정` 한 겹 안 |
| 한 번 적고 끝 | 실험일 · 방 가로/세로 · 공간 설명 · 실험 목표 · 분할 방식 · 참여 RX · 운영자 | `▸ 프로젝트 설정` 두 겹 안 |
| 이미 화면에 있음 | 다음 수집 라벨 | 블록 순서가 대신한다(§3.2) — 칸을 없앤다 |

**접힌 줄에 값을 미리 적는다** (`▸ 이번 실험 설정   P2 · S1 · 메모 없음`). 펼치지 않고도
맞는지 확인되는 것이 접기의 조건이다. 배치·피험자는 `s48` 바로 옆에도 다시 보인다 —
틀린 채로 찍는 것이 가장 비싼 실수이기 때문이다.

**메모는 두 가지가 있다. 여기 있는 것은 `operator.notes`** — `session_meta.yaml` 의 실험
정보이고 수집할 때마다 세션 폴더로 복사된다. 세션 탭의 `메모` 버튼이 쓰는 것은 다른 것이다
(`csi_session.set_session_note()`, 이미 찍은 세션에 나중에 붙이는 한 줄). 접힌 줄의
`메모 없음` 은 전자를 가리킨다.

저장 시점은 지금과 같다: 수집을 시작하면 세션 폴더에 `session_meta_snapshot.yaml` 로 복사된다.

## 4. 세션 탭

### 4.1 날짜로 접는다

세션이 80개를 넘었다. 평소 궁금한 것은 "어느 날 몇 개를 찍었나" 이지 세션 하나하나가 아니다.

```text
[전체 80] [빈 방 31] [정지 24] [움직임 25]  [품질 확인 1]

▾ 2026-09-20   30세션 · 배치 P3        empty 10 · static 10 · motion 10
    [motion] s31  300초 · RX3 · 99.8Hz           파형 · 메모 · 삭제
    …
▸ 2026-09-19   29세션 · 배치 P2        empty 10 · static 9 · motion 10  ⚠1
▸ 2026-09-17    8세션 · 배치 C·D·E     empty 3 · static 2 · motion 3

이 데이터로   분리 가능성 진단 · JSONL 내보내기
```

접힌 줄에 **라벨 개수와 배치**를 적어 다음에 무엇을 더 찍어야 할지 보이게 한다.
**품질 경고는 접힌 줄까지 올라온다**(`⚠1`) — 지금은 펼쳐서 찾아야 한다.

제외된 세션(`train_sessions.EXCLUDED_SESSIONS`)은 목록에 **보이되** 회색으로 두고 이유를
덧붙인다. 숨기면 "세션 수가 왜 줄었나" 를 추적할 수 없다.

- **배치 번호**는 각 세션의 `session_meta_snapshot.yaml` 의 `condition.placement_id` 에서
  읽는다. 한 날짜에 여러 배치가 섞이면 `배치 C·D·E` 처럼 모두 적는다. 값이 없으면 생략한다.
- **`live` 세션도 목록에 보인다.** 실시간 측정으로 찍은 세션이고 삭제·메모·파형이 똑같이
  필요하다. 다만 **라벨 칩(빈 방·정지·움직임)에는 세지 않는다** — `live` 는 여러 상태가
  섞여 있어 클래스가 아니다. `전체` 에는 센다. 날짜 줄에는 `live 2` 를 따로 적는다.

### 4.2 품질 문장은 한 곳에서 나온다

`csi_session.quality(devices) -> (level, text)` 하나가 정본이다. `level ∈ ok | check | recollect`.
GUI 세션 목록과 CLI 수집 직후 판정이 같은 함수를 쓴다. 여러 조건이 겹치면 가장 센 level
하나와 문장들을 ` / ` 로 잇는다.

| 조건 (RX 하나라도) | level | 문장 |
|---|---|---|
| `tx_back > 0` | recollect | `TX 가 수집 중 재부팅했습니다 — 시간 격자가 깨져 같은 라벨로 다시 찍으세요` |
| `boot_changes > 0` | recollect | `RX<id> 가 수집 중 재부팅했습니다 — 전원·케이블 확인 후 같은 라벨로 다시 찍으세요` |
| `crc_fail > 0` | check | `RX<id> CRC 실패 <n>건 — 케이블 확인` |
| `seq_gap > frames × 1%` | check | `RX<id> 손실 <x>% — 학습엔 쓸 수 있으나 무선 경합 의심` |
| RX 가 3대가 아님 | recollect | `RX <n>대만 기록됐습니다 — 3대가 필요합니다` |

기준값은 지금 `session_rows()` 가 쓰는 것과 같다(바꾸지 않는다). 태그는 `정상 | 확인 | 재수집`.

**이 함수가 품질의 유일한 정의다.** 지금은 두 벌이 있다 — `session_rows()` 의 규칙과,
`train_sessions.list_sessions()` 의 `ok`(crc·boot·tx_back **에 더해 RX 3대**, `seq_gap` 없음).
후자가 학습 탭의 ⚠ 와 선택 검사를 움직인다. 마지막 줄(RX 3대)을 위 표에 넣어 둘을 합치고,
`list_sessions()` 는 `quality()` 를 불러 쓴다. 지금 세션은 전부 RX 3대라 합쳐도 결과는 같다.

입력은 **매니페스트의 device dict 그대로** 받는다(`seq_gap`·`frames` 포함). `session_rows()`
가 깎아 둔 모양이 아니라 `read_manifest()` 가 주는 모양이 정본이다. 옛 매니페스트에 없는
키는 `KeyError` 없이 `ok` 로 본다.

### 4.3 진단과 내보내기

맨 아래 글자 링크 둘. 카드도 탭도 아니다 — 1년에 몇 번 쓰는 일에 자리를 내주지 않는다.
누르면 그 자리에서 펼쳐져 실행 버튼과 결과(진단 PNG)를 보인다.

**JSONL 내보내기는 남긴다.** 2026-10-12 판은 "제어판 학습은 `.csi` 를 직접 읽으니 비개발자
흐름에 불필요" 하다며 삭제하기로 했는데, 그 판단은 유효하지만 **공식 3-RX 전처리로 가는
유일한 GUI 경로**이기도 하다. 글자 링크 한 줄이면 비용이 거의 없으므로 지우지 않는다.


**단계 번호를 없앤다.** `1. 세션 → 2. 평가 날짜 → 3. 설정 → 4. 이름` 네 카드였지만 실제로
고민하는 것은 **어떤 데이터로** 와 **어떤 설정으로** 둘뿐이다.

- **처음 열면 아무것도 선택돼 있지 않다.** 위 그림은 고른 뒤의 모습이다. 미리 골라 두면
  평가 날짜 기본값(학습에 안 쓴 날짜 중 가장 최근)이 갈 곳이 없어진다.
- **평가 날짜 기본값**: 학습에 안 쓴 날짜 중 가장 최근. 없으면 `평가 없이 학습만`.
- **모델 이름 기본값**: 지금과 같은 자동 생성(`YYYYMMDD-HHMM-<프리셋>`).
- 둘 다 `바꾸기` 로 펼친다.
- **날짜 묶음은 왜 못 고르는지 적는다** — `평가에 쓰입니다` / `봉인`. 지금은 그냥 회색이라
  이유를 알 수 없다. 날짜 잠금 규칙 자체는 `train_sessions.check_selection()` 그대로다.
- 시작 버튼은 **세션 수와 예상 시간**을 말한다. `_train_run.estimate_seconds()` 는 창 수를
  받는데 그 값은 학습기가 데이터를 읽어야 나온다. 버튼에 쓰려면 **세션 메타에서 미리
  추정**해야 한다 — `Σ(span_s × 100) ÷ train_stride × ...`. 어긋날 수 있으므로 `약` 을 붙이고,
  **첫 epoch 이 끝나면 지금처럼 실측으로 갈아탄다**. 추정이 2배 이상 빗나가면 버튼에서
  시간을 빼고 세션 수만 남긴다.

### 봉인 날짜는 더 이상 없다 (2026-10-18 확인)

시안 단계에서는 9/20 을 `봉인` 으로 적었으나, 체크포인트를 열어 보니 **네 날짜 모두 이미
학습에 쓰였다** (9/16·17 각 12개 모델, 9/19·20 각 10개 — `amp1500_all74` 가 74세션 전부를
학습했다). 남은 봉인 날짜가 없다.

그래서 화면에 **`봉인` 이라는 말을 쓰지 않는다.** 대신 날짜마다 **사실만** 적는다 —
`이 날짜로 학습한 모델이 N개 있습니다`. 체크포인트의 `training_dates` 를 세어 만들므로
학습할 때마다 저절로 맞고, 새 정책 상수를 만들 필요가 없다.

이것은 **잠금이 아니라 정보다.** 날짜 잠금은 지금처럼 `train_sessions.check_selection()` 의
학습·평가 겹침 금지 하나뿐이다. "이 날짜는 이제 시험지가 아니다" 는 판단은 사람이 한다
([realtime-inference.md](realtime-inference.md) §6 의 holdout 봉인 원칙).

## 6. 실시간 탭

[실시간 상태 판단](realtime-inference.md) §8 이 화면 내용의 정본이다. 이 문서는 **껍데기만**
정한다.

- 카드 4장(상태 · 최근 기록 · 상태 변화 · 상태줄)을 **2장**으로 합친다. 지금은 카드 테두리가
  네 번 나와 화면이 끊긴다.
- **색 범례를 뺀다.** 띠 아래 상태 변화 목록에 같은 색 점이 이름과 함께 나오므로 중복이다.
- 상태줄(RX·Hz·창·모델)과 버튼은 맨 아래 **한 줄**로 내린다.
- 버튼은 `실시간 측정`(측정 중이면 `종료`) · `판단 정지` · `전환 표시` 셋.
- **`판단 정지` 는 `RT_JOB` 만 멈춘다.** 수집은 계속 돈다 — 화면만 끄고 데이터는 계속 받고
  싶을 때 쓴다. 다시 켜면 같은 세션에 판단을 다시 붙인다(수집을 다시 시작하지 않는다).
  `종료` 는 둘 다 멈춘다.
- **운영자가 멈춘 것과 RX 가 끊겨 멈춘 것을 같은 말로 쓰지 않는다.** 전자는
  `운영자가 판단을 멈췄습니다`, 후자는 상태 기계의 `suspended` 와 그 사유문이다. 색도 다르다
  — 전자는 회색(정상), 후자는 빨강(이상).
- **`전환 표시` 는 장식이 아니다.** 이 버튼이 전환 반응 지연의 유일한 정답 입력이다
  (realtime-inference.md §6). 누르지 않고 찍은 세션은 나중에 지연을 잴 수 없다 —
  10/14 세션 2건이 그렇게 남았다. 버튼 옆에 마지막으로 누른 시각을 보여 준다.

**문자 알림 카드 — 2026-10-27 제거(HISTORICAL).** 알림은 집 상태 서비스 클라우드가 보낸다
([계획](plans/2026-10-23-home-service.md) §3.3·§3.5, 설정은 홈페이지 설정 화면). 둘 다 켜 두면 같은
상황에 문자가 두 통 갔다. 아래는 당시 기록이다.

(당시) 2026-10-21 추가. 세 번째 카드로 맨 아래 붙는다. 꺼져 있으면 한 줄이다 —
실시간 탭에 이미 카드가 둘이라 기본값이 조용해야 한다. 내용의 정본은
[realtime-inference.md §10](realtime-inference.md). 껍데기만 적으면:

- 규칙 한 줄이 **한 문장**으로 읽힌다(`움직임 없음 30분`). 체크박스로 켜고 끄고, 오른쪽에
  `수정`·`삭제`.
- **조건은 여기서 재지 않는다.** 제어판은 `mac_collector/solapi.json` 을 고치고 기록을
  보여 줄 뿐이고, 재는 것은 판단 엔진이다 — 이 창을 닫아도 문자는 가야 한다.
- **API 시크릿은 화면으로 내려보내지 않는다.** 저장돼 있는지(`has_key`)만 알려 주고,
  입력칸이 비어 있으면 기존 값을 덮어쓰지 않는다.
- 끊김 규칙이 없으면 카드가 경고한다. 없으면 보드가 죽어도 조용하고, 조용한 것이 정상으로
  보인다.

`JOB`(플래시·수집·학습·진단·IDF)과 `RT_JOB`(실시간)을 나눈 구조는 이미 구현돼 있고 그대로 둔다.

## 6b. 연동 탭 (2026-10-25 추가)

집 상태 서비스([계획](plans/2026-10-23-home-service.md) §4.3)의 클라우드에 이 컴퓨터를 연결한다.
§2 의 "탭은 할 일" 규칙과 어긋나지 않는다 — 연결하는 것이 할 일이다. 사용자 요청으로 실시간
탭 안이 아니라 **다섯 번째 탭**으로 둔다(실시간 탭은 이미 카드가 셋이다).

- **연결 전**: 연동 코드(6자리) · 이 기기 이름 → `연결`. 실패 사유(`코드가 틀렸거나
  만료되었습니다`·`서버에 닿지 않습니다`)를 카드 안에 그대로 적는다.
- **연결됨**: 기기 이름 · 마지막 전송(몇 초 전 · 상태 · 성공/실패) · 받은 설정(수면 시간 ·
  조명 기준 · 외출 모드) · `연결 해제`(이 컴퓨터의 토큰만 지운다 — 홈페이지 기기 목록에서도
  해제해야 완전히 끊긴다).
- **서버 주소는 보이지 않는다** — 코드 상수다(`realtime/home.py:CLOUD_URL`).
- 전송은 판단 엔진이 한다. 실시간 판단이 꺼져 있으면 "실시간 판단이 꺼져 있어 보내지 않습니다
  — 홈페이지에는 3분 뒤 끊김으로 보입니다" 를 적는다.

## 7. CLI (개발자)

번호 메뉴를 유지하고 두 항목을 넣는다. **제어판 개편과 무관하게 지금 그대로 유효하다.**

```text
[1] 보드 플래시            [5] 모델 학습 (세션 선택)
[2] 수집                   [6] 실시간 (모델·세션 고르기)   ← 추가
[3] 블록 순서 뽑기         [7] 세션 메타 편집
[4] 세션 보기              [8] 보드 관리
    (날짜별 · 품질 원인)   [9] 돌아가기
    ← 추가
```

- **세션 보기**: `train_sessions.list_sessions()` 를 날짜별로 출력하고 §4.2 의 문장을 붙인다.
- **실시간**: `realtime.engine.available_models()` 와 최근 세션 12개에서 고른 뒤
  `realtime/ui.py` 를 `--follow` 또는 `--speed 2` 로 실행한다.
- 수집 직후 판정 출력에 §4.2 의 문장을 쓴다.
- `scripts/README.md` 러너 표에 `_train_run.py`·`realtime/ui.py`·`export_jsonl.py` 를
  "제어판 없이 직접 부를 수 있는 명령" 으로 적는다. 서브커맨드 CLI 는 만들지 않는다.

### 단계 띠를 없애는 이유 — 이것은 작성자 판단이다

10-12 판의 단계 띠(`env · boards · collect · train · realtime` 5칸)와 탭 합치기는 **같은
문제를 반대 방향으로 푼다.** 띠는 탭 7개 위에 안내를 더하고, 이번 판은 탭을 덜어낸다.
둘 다 하면 4칸 탭 위에 거의 같은 뜻의 5칸 띠가 얹힌다.

띠가 하던 일은 이렇게 나뉜다.

| 띠의 칸 | 이번 판에서 |
|---|---|
| `env` | 수집 준비 줄에 흡수 (§3.1) |
| `boards` | 수집 준비 줄에 흡수 (§3.1) |
| `collect` | 수집 탭 자신 — `다음 세션 s48` |
| `train` | 학습 탭 자신 — `학습한 모델 (7)` |
| `realtime` | 실시간 탭 자신 — 상태 글자 |

남는 것은 **"내가 지금 어느 단계인가"** 를 한눈에 보는 기능뿐인데, 탭 네 개가 이미 작업
순서라 그 값이 크지 않다고 본다.

**이 결정은 작성자 판단이고, 되돌리기 쉽다.** 띠는 다른 화면에 의존하지 않는 독립 요소라
나중에 `/api/state` 에 `steps` 를 더하고 헤더에 한 줄 넣으면 된다. 쓰다가 "어디서부터
해야 하는지 모르겠다" 는 말이 나오면 그때 넣는다.

## 9. 하지 않는 것

- 수집 경로(`csi_serial_reader.py`·펌웨어·`.csi`)와 registry·실험 데이터는 수정하지 않는다.
- 위저드("다음" 버튼 선형 흐름), TX IDENT 펌웨어, 모델 "배포" 버튼, CLI 서브커맨드 — 기각.
  담당자는 같은 수집 탭을 반복하므로 위저드는 2회차부터 방해이고, 나머지는 지금 방식이
  이미 동작한다.
- **새 색·서체는 만들지 않는다.** 이번 개편은 **무엇을 어디에 두는가**만 바꾼다. 기존
  CSS 변수와 상태색 체계를 그대로 쓴다.
- 탭을 더 줄이지 않는다. 넷 아래로 내려가면 한 화면이 두 가지 일을 하게 된다.
