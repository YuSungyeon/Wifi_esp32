# 실시간 상태 판단 — 2단계 모델 + 판정 규칙

> 상태: **PLANNED** — 설계만 있고 구현 코드는 없다 (2026-09-21 작성)
>
> 근거 실험: [1D-CNN 파일럿 교차검증 보고서](../model_train/docs/model-training/cnn1d-pilot-cv-report.md)
> (사이클 12·13) / 전송 경로: [실시간 경로](realtime-uplink.md)

## 1. 목적과 범위

방 안의 상태를 `empty` / `static` / `motion` 중 하나로 **실시간 표시하고 기록한다.**
1차 목표는 논문 발표용 시연이지만, 설계 기준은 **상시 모니터링 서비스**다 — 몇 초 빠른
반응보다 **오탐이 적고 장시간 안정적인 것**을 우선한다.

| 항목 | 결정 |
|---|---|
| 실행 위치 | Mac 호스트 (SINK → USB 경로 그대로). 소형 PC 이식은 나중 과제 |
| 출력 상태 | `empty` / `static` / `motion` + **`deciding`(판단 보류)** |
| 기록 단위 | 상태가 바뀔 때만 이벤트 한 줄 |
| 범위 밖 | 사람 수 세기, 위치 추정, 보드 위 추론, 여러 방 동시 감시 |

## 2. 왜 2단계인가

파일럿 실험에서 두 질문은 **잘 되는 시간척도와 입력이 서로 반대**였다.

| 질문 | 잘 되는 입력 | 잘 되는 윈도 | 근거 |
|---|---|---|---|
| 움직이는가? | **진폭** | **3초** | 사이클 12: macro-F1 0.987, 세션 13/13, 오판 0.55% |
| 빈 방인가 정지인가? | **위상** | **30~60초** | 사이클 9·11: 빈 방·정지 창 정답률 0.80 → 0.88 |

한 모델에 둘을 섞으면 나빠진다 — 진폭이 배치 지문(보드 위치에 따른 신호 특성)을 다시
들여와 처음 보는 배치에서 틀린다(사이클 8: 0.754 → 0.691). 윈도를 60초로 늘리면 정지
판정은 좋아지지만 움직임을 놓친다(사이클 11: 움직임 recall 0.99 → 0.77).

따라서 **두 모델을 각자 잘하는 자리에 쓰고, 판정 규칙이 둘을 합친다.**

## 3. 데이터 흐름

```text
보드 → SINK → USB → ① csi_serial_reader.py (현행 그대로, .csi 저장)
                        │
                        ▼
                     ② 실시간 판단 프로그램 (신규)
                        · 저장 중인 .csi 를 tail 로 따라 읽는다
                        · 3-RX 를 tx_seq 격자로 정렬 (공식 전처리와 같은 규칙)
                        · 최근 W초 링버퍼 유지
                        · 0.3초마다 1단계 → 조건 충족 시 2단계 → 판정 규칙
                        ▼
                     ③ 출력: 상태 전환 이벤트 파일 + 제어판(GUI) 현재 상태 표시
```

**수집 코드는 고치지 않는다.** 판단 프로그램이 `.csi` 를 뒤따라 읽는 이유:

1. **원본이 남는다** — 오탐이 난 순간의 원시 데이터를 다시 볼 수 있다.
2. **재생(replay)이 곧 시험대다** — 같은 코드에 녹화 파일을 넣으면 오프라인 평가가 된다.
   반응 지연·오탐률 측정과 규칙 조정을 보드 없이, 발열 없이 반복할 수 있다.
3. 수집 경로는 "손대면 안 되는 것"(CLAUDE.md)이 많아 변경 비용이 크다.

대가는 파일을 거치는 1초 미만의 추가 지연이다. 수십 초 단위 판단에서는 무시할 수 있다.

**입력 계약**: 판단 프로그램은 `.csi` 의 raw I/Q 를 직접 읽는다(위상이 필요하므로).
JSONL(`csi_amp`, 진폭만)과 공식 전처리 계약은 바꾸지 않는다.

### 윈도는 거의 전부 겹친다

윈도 길이와 무관하게 **0.3초(30 frame)마다** 새 윈도를 만든다. 30초 윈도는 이웃과 99%,
60초 윈도는 99.5% 겹친다. 이웃 판단이 서로 비슷하므로 규칙에서 몇 개를 모아 흔들림을
거르기 쉽다. 반대로 **창 개수는 독립 표본이 아니다** — 평가는 세션·이벤트 단위로 한다.

## 4. 판정 규칙 (상태 기계)

설계의 뼈대는 물리적 제약이다: **빈 방 ↔ 정지 전환은 반드시 움직임을 거친다.** 사람이
들어오거나 나가려면 움직여야 하기 때문이다. 그래서 빈 방·정지 판정은 움직임이 끝난 뒤
한 번 내리고, 다음 움직임 전까지 쉽게 뒤집지 않는다. 이것이 장시간 오탐을 막는 핵심이다.

```text
        움직임 감지
   ┌──────────────────────────────────────────┐
   ▼                                          │
[motion] ──조용해짐──▶ [deciding] ──W초 동안 움직임 없음──┐
   ▲                        ▲                             │
   │                        └── 확신도 < 기준 ─────────────┤
   │                                                       ▼
   └──────── 움직임 감지 ◀──────────────── [empty] 또는 [static]
```

| 규칙 | 조건 | 초기값 (재생 실험으로 조정) |
|---|---|---|
| ① motion 진입 | 1단계 최근 판단 3개 중 2개가 motion | 약 1초 |
| ② motion 종료 | 1단계가 연속으로 motion 아님 → `deciding` | 3초 |
| ③ empty/static 결정 | 마지막 motion 이후 2단계 윈도가 **전부** 움직임 없는 구간으로 차면, 최근 몇 초 확률 평균으로 결정 | W초 (§5에서 결정) |
| ④ 확신 기준 | 평균 확률이 기준 미만이면 `deciding` 유지 | 0.7 |
| ⑤ empty↔static 직접 전환 | 움직임 없이는 금지. 오판 교정용으로 2단계가 반대 판단을 오래 유지할 때만 허용 | 2W 이상 |

**예상 반응 지연** (설계값이며 실측은 §6-②):

| 전환 | 지연 |
|---|---|
| 정지·빈 방 → 움직임 | 약 1초 |
| 움직임 → 정지/빈 방 확정 | 약 3초 + W초 |

**이벤트 기록**: 상태가 바뀔 때마다 `{시각, 이전 상태, 새 상태, 확신도, 근거 윈도 구간}`
한 줄. 이 기록이 반응 지연·오탐률 계산의 유일한 입력이다.

## 5. 2단계 윈도 길이(W) 선택 절차

| 항목 | 내용 |
|---|---|
| 후보 | 20 · 30 · 45 · 60 · 90 · 120초 |
| 모델 | 3-class 위상 모델(사이클 11 구성)의 empty/static 확률을 사용 |
| 실행 | 전 후보 seed 1개 → 상위 2개만 seed 3개 재확인 (발열 고려) |
| 비교값 | empty·static 창 정답률과 **대기 시간(3초 + W)** 을 함께 본다 |

**선택 규칙을 결과를 보기 전에 고정한다**: *최고 정답률과 0.02 이내인 후보 중 가장 짧은 W*.
사후에 좋아 보이는 값을 고르면 점수가 부풀기 때문이다.

전용 2-class 모델(사이클 13, 0.843/8세션)은 3-class 모델(사이클 11, 0.877/9세션)보다
나아지지 않았다. motion 세션이 빠져 학습량이 2/3로 줄어든 것으로 본다 — **2단계는
3-class 모델의 확률을 읽어 쓴다.**

**한계**: 현재 세션이 5분이라 90·120초 후보는 세션당 유효 구간이 적어 불안정할 수 있다.
그 경우 표에 표시하고, 긴 윈도는 §7의 긴 세션으로 다시 확인한다.

**진폭 추가는 기본 계획에서 제외한다.** 사이클 8(진폭+위상 0.691)과 사이클 10(위상 분산
추가 0.770)에서 두 번 모두 개선이 없었다. 확인이 필요하면 확정된 W 하나에서만 1회 재확인.

## 6. 검증 계획

| # | 검증 | 방법 | 측정값 |
|---|---|---|---|
| ① | 새 날짜 holdout | 모델·W·규칙을 **전부 고정한 뒤** 새 날·새 배치 세션으로 1회만 평가 | 상태별 정답률, 세션 정답 |
| ② | 전환 반응 지연 | 대본대로 상태를 바꾸고(§7) 운영자가 전환 시점을 표시 | 전환 종류별 지연 중앙값·최대, 전환 중 오상태 시간 |
| ③ | 장시간 오탐 | 빈 방 수 시간 + 책상 정지 1시간 | 시간당 거짓 `사람 있음` / 거짓 `empty` 이벤트 수 |
| ④ | 다른 피험자 | 최소 2명 추가, 사람마다 기본 세션 | ①과 같은 지표를 사람별로 |

**holdout 봉인 원칙**: 평가용 데이터는 W 선택·규칙 조정·모델 학습 어디에도 쓰지 않는다.
한 번 결과를 본 데이터는 더 이상 시험지가 아니다.

**전환 시점 기준 시각**: `.csi` 프레임에는 호스트 시각이 없다. 세션 매니페스트의
`started_at_unix_us` 와 100Hz `tx_seq` 로 환산하며 오차는 ±0.1초 수준이다 — 초 단위
지연 측정에는 충분하다.

## 7. 다음 수집 계획

1. **전환 세션 대본** (10분 예시): `empty` 2분 → 입실·보행 1분 → 착석 정지 3분 →
   기립·보행 1분 → 퇴실 후 `empty` 3분. 전환 시점마다 제어판의 전환 버튼을 누른다.
2. **전환 세션은 두 묶음**: 첫 묶음은 규칙 ①~⑤ 조정용, 다른 날 묶음은 봉인 평가용.
3. **기본 세션**: 클래스 3종 × 배치 2개 — holdout 평가용.
4. **장시간**: 빈 방 야간 녹화(3-RX 기준 약 190MB/시간) + 주간 책상 작업 1시간.
5. **다른 피험자**: 섭외되는 대로 추가.

수집 절차·품질 판정은 [수집 프로토콜](collection-protocol.md) §7 을 따른다.

## 8. 구현 순서

| 단계 | 내용 | 보드 필요 |
|---|---|---|
| 1 | W 선택 실험 (§5) | 불필요 (파일럿 데이터) |
| 2 | 1·2단계 모델 학습·저장 (seed 3개 앙상블) | 불필요 |
| 3 | 재생 엔진 + 판정 규칙 + 이벤트 기록 | 불필요 |
| 4 | 실시간 모드(`.csi` tail) + 제어판 상태 표시·전환 버튼 | 필요 |
| 5 | 수집 → 규칙 조정 → 고정 → 봉인 데이터로 최종 평가 | 필요 |

## 9. 전제와 미해결

- **파일럿 점수는 낙관 편향이 있다.** 같은 15세션으로 13개 설정을 비교했다. §6-① 전까지
  어떤 수치도 실사용 성능으로 인용하지 않는다.
- **전환 구간 데이터가 아직 없다.** 현재 세션은 하나의 상태만 담고 있어 규칙 ①~⑤의
  초기값은 설계 추정치이며, §7-1 수집 전에는 검증할 수 없다.
- **피험자 1명·단일 방**이다. 방 일반화는 주장하지 않는다.
- 모델 담당과의 경계: 공식 전처리·JSONL 계약은 그대로 두고, 위상 입력은 실시간 판단
  프로그램 안에서만 사용한다. 위상을 공식 pipeline 에 넣으려면 `data-schema.md` 변경이
  선행되어야 한다.
