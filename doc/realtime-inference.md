## 1. 목적과 범위

### 위상 60초 선택 연결 (2026-10-10 완료)

GUI·CLI에서 진폭 30초(기본) / 위상 60초(시험 후보)를 선택할 수 있다.
입력 계약과 실행 기록은 [실시간 모델 선택 결정](adr-phase60-realtime-selection.md)을 따른다.
위상은 60초 준비와 156열 위상 입력, 기본 0.3초 이동을 사용한다.
모델 이름·창 길이·준비 남은 시간도 선택에 맞게 표시한다. 실행 중 모델을 바꾸려면
판단 정지 후 새 실행을 시작한다. 연결은 성능 개선이나 실제 보드 시험 완료를 뜻하지 않는다.

### GUI·CLI에서 모델 실행

**추가 완료 (2026-10-13):** `phase60_room`은 **위상 60초 · 내 방 추가 학습**을 선택한다.
파일은 `model_train/phase60/model_room_20261012.pt`, 입력은 기존 위상 60초 경로다.
이번 방 녹화로 추가 학습했으며 독립 성능 확인 전의 실시간 시험 후보다.
GUI에서 선택 후 실시간 시작, CLI는 `--model-kind phase60_room`을 사용한다.
학습·연결 확인 범위는 [추가 학습 결과](../model_train/docs/model-training/20261013-phase60-room-finetuning.md)에 있다.

GUI·CLI는 선택한 모델 파일과 입력 규칙을 공통 실행기로 전달한다. 가중치는
바꾸거나 재학습하지 않는다. 프로젝트 `.venv`가 있으면 판단 프로세스는 그 Python을
사용한다. 의존성이 없으면 `pip install -r requirements-robust.txt` 실행 방법을 안내한다.

- GUI: `python3 scripts/meshsense_gui.py` → **실시간** 탭 → **사용할 모델** 선택 → **실시간 시작**.
  SINK를 확인하고 현재 보드 신호 수집과 모델 판단을 함께 시작한다. 과거 세션을
  고를 필요가 없다. **판단 정지**는 이 실행에서 시작한 수집과 판단을 함께 끝낸다.
  다른 수집·플래시가 포트를 사용 중이면 새 수집을 시작하지 않는다.
- 저장 자료는 세션을 고르고 **녹화 재생**한다. 고급 기능인 **수집 파일 따라 읽기**는
  다른 수집 프로세스가 현재 저장 중인 동일 세션을 읽기만 한다. 이 모드의 판단 정지는
  외부 수집을 멈추지 않는다. 완료된 옛 세션은 현재 보드 신호가 아니다.
- CLI 메뉴: `python3 scripts/meshsense_cli.py` → **모델 판단 (재생·실시간)** → 모델 선택 → 판단 방식 선택.
- CLI 현재 보드: `.venv/bin/python scripts/meshsense_cli.py --live --port <SINK 포트>`.
  Ctrl+C로 자신이 시작한 수집·판단을 함께 종료한다. 펌웨어와 DTR/RTS는 바꾸지 않는다.
- CLI 직접 실행: `.venv/bin/python scripts/meshsense_cli.py --realtime <세션 경로>`.
  `--follow`를 붙이면 저장 중인 `.csi`를 따라 읽고, 없으면 처음부터 끝까지 재생한다.
  `--plain`은 한 줄 출력이다. `--model-kind phase60`은 위상 선택이며 생략하면 진폭이다.
  `--model`은 선택한 종류의 입력 계약과 일치하는 체크포인트만 지정할 수 있다.

```bash
# 현재 SINK로 위상 60초 모델 실행 (포트는 실제 연결된 SINK 포트로 바꾼다)
.venv/bin/python scripts/meshsense_cli.py --live --port <SINK포트> --model-kind phase60 --plain
# 기존 녹화 자료를 위상 모델로 재생 (보드 불필요)
.venv/bin/python scripts/meshsense_cli.py --realtime <세션경로> --model-kind phase60 --plain
```

입력은 RX 101/102/103의 공통 `tx_seq` 구간이다. 진폭은 30초·3,000프레임을 채워
기존 `amplitude_input()` 상대 진폭 변환을 사용한다. 위상은 60초·6,000프레임을 채워
`phase60/features.py`의 주파수축 unwrap·직선 제거·20시점 평균·창 평균 차감으로
`(1,300,156)` 입력을 만든다. GUI·CLI 이동 간격 기본값은 **0.3초(새 공통 입력 30프레임)**다.
오프라인 정확도 평가의 진폭 **15초**, 위상 **3초** 간격을 변경한다는 뜻은 아니다.

재생은 전체 공통 구간을 보관하므로 링버퍼 크기 때문에 앞부분을 버리지 않는다.
진폭 재생은 기존 raw 로더의 구간 선택과 최소 3,000프레임 경로를 사용한다.
위상 재생은 스트림 검사를 재사용하는 별도 최소 6,000프레임 경로다.
기존 학습·오프라인 세션 변환의 최소 27,000프레임 검사나 진폭 평가의 관측률 기준은
바꾸지 않았다. 실시간은 완성된 프레임만 읽으며 CRC·RF·수신기 식별을
확인한다. 파일 축소, 재부팅 또는 송신 순번 역행을 정렬로 숨기지 않고 오류로 중지한다.
5프레임 이하 내부 공백만 보간하며 긴 공백·수신 중단 때는 판단을 보류/정지한다.
배포 모델은 완전한 3-RX 입력 계약이므로 RX를 잃었다고 0으로 채워 추론하지 않는다.
현재 GUI·CLI는 **모델 분류 즉시 표시**다. 유효한 새 창마다 3-seed 평균 확률이 가장
큰 클래스를 바로 표시한다. 확률 70% 기준과 1/15/60초 유지 시간은 적용하지 않는다.
정지 후 유효 입력이 복구되면 그 창의 클래스가 바로 표시된다. 최초 30초/60초 준비와
입력 누락 때의 안전 정지는 유지한다. 확률이 낮아도 분류를 표시하므로 깜빡일 수 있다.
GUI 판단 영역은 경량 상태 API를 **300ms 간격**으로 조회한다. 전체 제어판 조회는
기존 1.2초다. 현재 보드 reader는 `--flush-interval 0.1`로 파일 입력을 자주 공개한다.
일반 수집의 기본 flush 1초와 원본 프레임 형식은 바꾸지 않는다. 이 간격은 폴링/이동
설정이며 운영체제 지연·입력 누락까지 포함한 300ms 하드 실시간 보장은 아니다.

실행별 상태·이벤트·로그·전환 표시는 `mac_collector_output/realtime/`의 별도
실행 폴더에 기록한다. 기존 원본 `.csi`와 `session.json`은 바꾸지 않는다.
현재 보드 모드의 새 실행은 `<실행>/capture/`에 raw I/Q와 `session.json`,
`<실행>/prediction/`에 판단 기록을 만든다. 정답을 알 수 없으므로 라벨은 `null`,
목적은 `realtime_monitor`다. 학습용 `raw/`에 넣거나 정답 라벨을 임의로 붙이지 않는다.
정지할 때 새 capture 매니페스트에 종료 시각·reader 품질 통계를 남긴다.
수집·판단 중 하나가 오류로 종료하면 같은 실행의 다른 프로세스도 종료한다.
원시 데이터는 실행 시간에 비례해 디스크를 쓰며 정지 후에도 남는다(자동 삭제하지 않음).
하위 `realtime/ui.py`·`engine.py`에도 `--model-kind`·`--model`·`--output-dir`를 제공한다.
화면에 모델 이름·경로, 재생/실시간 구분, 선택한 창의 준비 진행률, 판단 횟수·오류를 표시한다.
GUI 종료는 판단 프로세스도 종료하며, 이전 재생 결과는 현재 실행 중인 판단과 구분한다.
GUI에서 시작한 실행이 없으면 CLI의 기본 실행 폴더도 조회한다. 외부 CLI의 종료는
해당 터미널에서 Ctrl+C로 하며, GUI 판단 정지는 GUI에서 시작한 판단만 멈춘다.

현재 보드 연결이 없을 때의 검증은 저장 세션 재생·파일 추가 모의 실시간·API·단위
테스트다. 실제 보드 수집 중 지연과 상태 전환 정확도를 확인한 것처럼 보고하지 않는다.

방 안의 상태를 `empty` / `static` / `motion` 중 하나로 **실시간 표시하고 기록한다.**
1차 목표는 논문 발표용 시연이지만, 설계 기준은 **상시 모니터링 서비스**다 — 몇 초 빠른
반응보다 오탐이 적고 장시간 안정적인 것을 우선하는 이전 설계가 있었다.
현재 사용자 요청은 모델 분류를 그대로 즉시 표시하는 것이므로 표시 지연 규칙은 제외했다.

| 항목 | 결정 |
|---|---|
| 실행 위치 | Mac 호스트 (SINK → USB 경로 그대로). 소형 PC 이식은 나중 과제 |
| 출력 상태 | `empty` / `static` / `motion` 즉시 표시 + `deciding`(최초 준비), `suspended`(입력 오류) |
| 기록 단위 | 매 판단/준비/대기/정지의 점수 기록 + 상태 변화 이벤트 |
| 범위 밖 | 사람 수 세기, 위치 추정, 보드 위 추론, 여러 방 동시 감시 |

## 2. 선택할 수 있는 고정 모델

실행마다 아래 중 하나를 선택한다. 기존 진폭이 기본이며 위상은 시험 후보다.
두 모델 모두 저장된 seed 3개의 softmax를 평균해 3분류한다. 새 학습이나 가중치 변경은 없다.

| 항목 | 진폭 (기본) | 위상 (시험 후보) |
|---|---|---|
| 파일 | `model_train/robust/model.pt` | `model_train/phase60/model_60sessions.pt` |
| 선택 키 | `amplitude` | `phase60` |
| raw 입력 | 진폭 153열, RX별 `[38..63,2..26]` | 복소 I/Q 156열, RX별 `[38..63,1..26]` |
| 창 | 3,000프레임 / 30초 | 6,000프레임 / 60초 |
| 실시간 이동 | 기본 30프레임 / 0.3초 | 기본 30프레임 / 0.3초 |
| 출력 | `empty` / `static` / `motion` 점수 | 동일 |

로더는 모델 형식·특징 버전·모드·샘플링·창·RX/톤·클래스 순서·3-seed를 검사한다.
위상은 downsample=20과 seed 목록도 검사한다. 서로 다른 종류의 가중치를 잘못 지정하면 실행을 거부한다.

### 2단계(진폭 3초 + 위상 60초) 는 왜 쓰지 않았나

파일럿 15세션에서는 두 질문의 잘 되는 조건이 반대로 나왔고(사이클 12 움직임 0.987 /
사이클 11 위상 60초 정지 판정 우세), 그래서 2단계 구성을 설계했다. 이후 60세션이 확보되며
전제가 바뀌었다.

| 비교 (서로의 날짜로 교차 평가) | 세션 정답 |
|---|---:|
| 진폭 30초 단일 모델 — 60세션 학습 → 15세션 평가 | 12/15 |
| 위상 60초 — 15세션 학습 → 60세션 평가 | 58/60 |
| 위상 60초 — 60세션 학습 → 15세션 평가 | 14/15 |

위상 쪽이 조금 낫지만 시험 세션이 15개라 2개 차이는 우연과 구분되지 않는다. 반면 진폭
모델은 입력 계약·테스트·실시간 추론 진입점이 갖춰진 배포 산출물이다.
**2026-10-08 현재 위상 모델도 별도 `model_train/phase60/`에 코드와 가중치가 있으며,
원본 9/16·17의 14/15 결과를 재현했다.** 2026-10-10에는 GUI·CLI에 선택형으로 연결했다.
다음 절차는 [위상 모델 도입 작업 목록](plans/2026-10-08-phase60-introduction.md)에 있다.
이후 [10/6 전환 원본 재생](../model_train/docs/model-training/20261006-phase60-transition-replay.md)에서는
위상이 빈 방 구분은 개선했지만 앉기 구간 정지 일치율이 0%여서 기본 모델 교체를 보류했다.
2단계 구성의 실험 기록은 위 보고서에 있다.

## 3. 데이터 흐름

```text
보드 → SINK → USB → ① csi_serial_reader.py (현행 그대로, .csi 저장)
                        │
                        ▼
                     ② 실시간 판단 프로그램 (신규)
                        · 저장 중인 .csi 를 tail 로 따라 읽는다
                        · 3-RX 를 tx_seq 격자로 정렬 (공식 전처리와 같은 규칙)
                        · 최근 W초 링버퍼 유지
                        · 0.3초마다 배포 3-class 모델 → 판정 규칙
                        ▼
                     ③ 출력: 상태 전환 이벤트 파일 + 제어판(GUI) 현재 상태 표시
```

**수집 코드는 고치지 않는다.** 판단 프로그램이 `.csi` 를 뒤따라 읽는 이유:

1. **원본이 남는다** — 오탐이 난 순간의 원시 데이터를 다시 볼 수 있다.
2. **재생(replay)이 곧 시험대다** — 같은 코드에 녹화 파일을 넣으면 오프라인 평가가 된다.
   반응 지연·오탐률 측정과 규칙 조정을 보드 없이, 발열 없이 반복할 수 있다.
3. 수집 경로는 "손대면 안 되는 것"(CLAUDE.md)이 많아 변경 비용이 크다.

파일 flush·폴링·추론·화면 갱신 지연이 더해진다. flush 설정만으로 실제 추가 지연의 상한을 보장하지 않는다.

**입력 계약**: 판단 프로그램은 `.csi`의 raw I/Q에서 선택한 모델의 진폭 또는 위상 잔차를 계산한다.
JSONL(`csi_amp`, 진폭만)과 공식 전처리 계약은 바꾸지 않는다.

### 윈도는 거의 전부 겹친다

윈도 길이와 무관하게 **0.3초(30 frame)마다** 새 윈도를 만든다. 30초 윈도는 이웃과 99%,
60초 윈도는 99.5% 겹친다. 표시를 늦추는 유지 시간 없이 매번 최대 확률 클래스를
쓴다. **창 개수는 독립 표본이 아니다** — 평가는 세션·이벤트 단위로 한다.

## 4. 판정 규칙 (상태 기계)

### 현재 — 매번 최대 확률 클래스 즉시 표시 (2026-10-02)

선택한 모델의 30초/60초 준비 후 0.3초 이동 간격의 유효한 창에서 `argmax(empty, static, motion)`를 표시한다.
예: `empty=0.40, static=0.35, motion=0.25`이면 70%를 기다리지 않고 바로 **빈 방 40%**다.
다음 창에서 `static`이 최대면 바로 **정지**로 바뀐다. 이 확률은 정답률이 아니다.
RX 3대·CRC·입력 완전성 검사는 유지하고, 입력이 유효하지 않으면 클래스를 추측하지 않는다.
클래스 전환은 이벤트로 남기고, 상태 파일의 확률·예측 횟수는 새 유효 창마다 갱신한다.

### 과거 — 확신 기준과 유지 시간 (HISTORICAL, 현재 화면에는 미적용)

설계의 뼈대는 물리적 제약이다: **빈 방 ↔ 정지 전환은 반드시 움직임을 거친다.** 사람이
들어오거나 나가려면 움직여야 하기 때문이다. 그래서 빈 방·정지 판정은 움직임이 끝난 뒤
한 번 내리고, 다음 움직임 전까지 쉽게 뒤집지 않는다. 이것이 장시간 오탐을 막는 핵심이다.

```text
        움직임 감지
   ┌──────────────────────────────────────────┐
   ▼                                          │
[motion] ──조용해짐──▶ [deciding] ──W초 동안 움직임 없음──┐
   ▲                        ▲                             │
   │                        └── 확신도 < 기준 ─────────────┤
   │                                                       ▼
   └──────── 움직임 감지 ◀──────────────── [empty] 또는 [static]
```

모델은 0.3초마다 3-class 확률을 낸다. 상태 기계는 그 위에서 두 가지만 건다 —
**확신 기준**과 **유지 시간**. (`realtime/state.py`)

| 규칙 | 조건 | 값 |
|---|---|---|
| ① 확신 기준 | 최대 확률이 기준 미만이면 상태를 바꾸지 않고 `deciding` | 0.70 |
| ② motion 유지 | 후보가 `motion` 이면 짧게 본다 — 입실·활동에 바로 반응 | 1초 |
| ③ empty·static 유지 | 후보가 `empty`/`static` 이면 오래 본다 — 깜빡임·오탐 억제 | 15초 |
| ④ empty↔static 직접 전환 | 움직임을 거치지 않은 전환은 특히 더 오래. 사람이 들고 나려면 반드시 움직인다 | 60초 |
| ⑤ RX 저하 | 배포 모델은 RX 3대 필수. 수신 중단·채워지지 않은 공백이면 `suspended`로 멈춤 | 3대 |

**측정한 반응 시간** (녹화 세션 재생, 세션 시작부터 확정까지 — 창 30초가 차는 시간 포함):

| 세션 | 실제 | 판단 | 확정까지 |
|---|---|---|---:|
| 9/19 s1 | 빈 방 | 빈 방 (93%) | 45초 |
| 9/19 s10 | 정지 | 정지 (93%) | 63초 |
| 9/19 s5 | 움직임 | 움직임 (96%) | 31초 |
| 9/20 s42 | 정지(서 있음) | 정지 (100%) | 45초 |
| 9/17 s43 | 빈 방(다른 날·무선) | 빈 방 (72%) | 59초 |

다섯 세션 모두 정답이며 확정 후 상태가 흔들리지 않았다. **단 이것은 상태가 하나뿐인 세션의
수치다** — 사람이 걷다 멈추는 전환 지연은 §7-1 수집 전에는 측정할 수 없다.

**이벤트 기록**: 상태가 바뀔 때마다 `{시각, 이전 상태, 새 상태, 확신도, 근거 윈도 구간}`
한 줄. 현재는 별도 매 판단 기록과 실제 행동 시각도 함께 사용한다(§9).

## 5. 기본 진폭 모델의 윈도 길이 — 왜 30초인가

기본 진폭 모델이 30초로 고정돼 있다. 그 값은 모델 담당이 development 자료에서 창 길이를 비교해 고른 것이다.
위상 후보의 창은 별도 60초다. 아래 비교를 위상 모델에도 그대로 적용하지 않는다.

| 창 | 창 F1 (9/19 development, 같은 특징·같은 선형 모델) |
|---|---:|
| 3초 | 0.914 |
| 10초 | 0.977 |
| 30초 | **0.997** |

우리 파일럿 실험도 독립적으로 같은 방향이었다 — 10초 → 30초에서 macro-F1 0.754 → 0.833,
60초에서 정지 판정이 더 올랐다(사이클 7·9·11). 창이 길수록 정지 상태 판정이 좋아지고
움직임 반응이 느려지는 교환이 있다. 현재 화면은 추가 유지 시간을 쓰지 않지만
입력이 최근 30초라는 특성 자체는 남는다.

같은 모델의 창을 임의로 바꾸지 않는다. 엔진은 선택한 모델의 입력 계약에 맞춰 창을 읽고,
진폭 30초/위상 60초와 다른 계약이면 실행을 거부한다.

## 6. 검증 계획

| # | 검증 | 방법 | 측정값 |
|---|---|---|---|
| ① | 새 날짜 holdout | 모델·규칙을 **전부 고정한 뒤** 새 날·새 배치 세션으로 1회만 평가 | 상태별 정답률, 세션 정답 |
| ② | 전환 반응 지연 | 대본대로 상태를 바꾸고(§7) 운영자가 전환 시점을 표시 | 전환 종류별 지연 중앙값·최대, 전환 중 오상태 시간 |
| ③ | 장시간 오탐 | 빈 방 수 시간 + 책상 정지 1시간 | 시간당 거짓 `사람 있음` / 거짓 `empty` 이벤트 수 |
| ④ | 다른 피험자 | 최소 2명 추가, 사람마다 기본 세션 | ①과 같은 지표를 사람별로 |
| ⑤ | RX 한 대 손실 | 기존 데이터에서 RX 를 한 대씩 빼고 재평가(3가지) — 보드 불필요 | 저하 폭, 특히 취약한 보드 위치 |

모델 자체의 교차 날짜 평가는 끝났다(§2). ①~⑤ 는 **실시간 경로 전체**(정렬 → 창 → 상태 기계)를
사람이 상태를 바꾸는 상황에서 재는 것이며, 단일 상태 5분 세션으로는 대신할 수 없다.

**holdout 봉인 원칙**: 평가용 데이터는 규칙 조정·모델 학습 어디에도 쓰지 않는다.
한 번 결과를 본 데이터는 더 이상 시험지가 아니다.

**전환 시점 기준 시각**: `.csi` 프레임에는 프레임별 호스트 수신 시각이 없다.
첫 전환 시험은 사용자가 알려준 실제 행동의 호스트 시각과 이벤트의 `wall`을 직접
비교했다. 매니페스트 시작 시각은 reader의 첫 프레임 시각과 같다고 보장되지 않으므로
`started_at_unix_us`와 100Hz `tx_seq`만으로 ±0.1초 정확도를 주장하지 않는다.
수동 행동 기록의 오차와 앉기 시작·완전 정지의 차이는 별도로 주의한다.

## 8. 현재 화면 구성

공통 원칙: **지금 상태가 가장 잘 보이고, 나머지는 문제가 생겼을 때만 찾게 한다.**
CLI 는 화면 공간 배분으로, GUI 는 글자 크기로 서열을 만든다. 상태 전환 이벤트는 화면과
무관하게 항상 파일에 기록된다 — 화면은 사람용이고, 지연·오탐률 계산은 파일로 한다.

### CLI (`--plain` 이면 한 줄 갱신 모드)

24행 기준 배분: 제목 1행 · **상태 블록 9행(40%)** · 이력 4행 · 상태줄 1행. 상태 블록은
왼쪽 위에 상태 한 단어만 두고 나머지를 비운다 — 여백이 강조 장치다. 아스키 큰 글자는 쓰지 않는다.

```text
┌─ MeshSense 실시간 ──────────────────────── 14:23:51 ─┐
│                                                      │
│      움직임                                          │
│                                                      │
│      2분 14초째                                      │
│      확신  ████████████████████░░░░░  87%            │
│                                                      │
├──────────────────────────────────────────────────────┤
│  14:21:37   빈 방  → 움직임     1.2초만에            │
├──────────────────────────────────────────────────────┤
│  99.8Hz  RX3  정상  s47 18분        [m]전환 [q]종료  │
└──────────────────────────────────────────────────────┘
```

- `deciding`은 최초 준비 단계이며 선택한 모델의 30초/60초 입력 준비와 남은 시간을 보인다.
- `--plain`은 한 줄 갱신 모드다. CLI 상태줄에도 선택한 모델을 표시한다.

### GUI — 새 **실시간** 탭 (탭 순서 맨 앞)

| 크기 | 요소 |
|---|---|
| 3.6rem 굵게·상태색 | 상태 단어 |
| 1.05rem | 현재 상태 유지 시간 또는 입력 준비 남은 시간 |
| 막대 + 숫자 | 준비 진행률 또는 선택한 클래스의 모델 점수. 확신 기준선 없음 |
| 보통 카드 | **최근 60분** 상태 띠, 상태 변화 목록 |
| 0.8rem 흐리게 | 선택 모델·실시간/재생 구분·품질·수집률·RX 대수·창 길이 |

- **사용할 모델** 선택, **실시간 시작**, **판단 정지**, **전환 표시**를 제공한다.
  저장 자료용 **녹화 재생/수집 파일 따라 읽기**는 별도 접이식 영역에 있다.
  실행 중 선택은 잠그며 새로고침해도 현재 실행의 모델을 표시한다.
- 제외: 모델 확률 전체, RX별 상세 수집률, 서브캐리어 파형, 하루 요약 — 다른 탭이나
  기록 파일에 있다.

**색 체계**: 빈 방 회색 · 정지 파랑 · 움직임 주황 · 판단 중 황토(빗금). 이 색이 상태 글자,
카드 왼쪽 6px 띠, 60분 띠, 변화 목록의 점에 **같은 뜻으로** 쓰인다. 카드 배경 전체를 칠하지
않는다 — 상태가 바뀔 때마다 화면이 통째로 뒤집히면 오래 켜 두기 어렵다. 빈 방일 때 화면이
가장 조용한 것이 의도다. 다크 모드는 상태색을 밝은 계열로 따로 둔다. 갱신되는 숫자에는
고정폭(tabular) 숫자를 쓴다.

**최근 60분 띠**: 상태 하나가 수십 분 이어지는 것이 정상이라 10분 창에는 변화가 거의 담기지
않는다. 60분을 기본으로 하고, 폭이 좁아 1분 미만 구간이 뭉개지면 최소 2px 로 그려 존재만
드러낸다.

### 신호 저하 시 동작

2-RX 추론은 배포 입력 계약과 성능 검증을 갖추지 않았다. 배포 엔진은 **RX 3대의
유효한 선택 모델의 30초/60초 입력이 없으면 추론하지 않는다.** 상태 기계의 별도 2-RX 확신 기준은
실험용 로직이며, 현재 엔진에 적용하지 않는다. RX의 새 순번이 3초 이상 들어오지 않으면
기존 창이 남아 있어도 판단을 멈춘다. 보간되지 않는 공백은 창에서 빠질 때까지 영향을 줄 수 있다.

| 상황 | 동작 | 표시 |
|---|---|---|
| RX 3대 | 정상 판단 | 평소 화면 |
| RX 2대 | 판단 정지; 누락 입력을 0으로 대체하지 않음 | 수신 중단 원인 표시 |
| RX 1대 이하 또는 TX 끊김 | 판단 정지 | 원인 + **마지막 판단과 그 시각** |

```bash
python realtime/ui.py --session mac_collector_output/raw/<날짜>/<세션> --speed 2
# 수집 중 실시간

python scripts/meshsense_gui.py
```

실행별 출력 디렉터리에 남는 파일: `realtime_status.json`(현재 상태, 원자적 교체),
`realtime_events.jsonl`(상태 전환), `realtime_marks.jsonl`(운영자 전환 표시),
`realtime_predictions.jsonl`(매 판단·준비·대기·안전 정지·종료 기록).

매 판단 기록은 `inferred`로 실제 새 추론 여부를 구분한다. `probs` 순서는 빈 방·정지·움직임이며,
대기 중에는 이전 점수가 남을 수 있으므로 이를 새 추론으로 세지 않는다.
`input_start_tx_seq`부터 `input_end_tx_seq_exclusive` 직전까지가 입력 범위다.
`inferred=true`일 때 위상은 정확히 6,000프레임이다. 준비 단계 범위는 부분 입력이며,
supervisor 종료 기록은 범위를 알 수 없으면 `null`이다.
`reason`은 `warmup`, `inference`, `waiting_for_new_common_frames`, `rx_missing`,
`unfilled_gap`, `error`, `stopped`, `supervisor_error`/`supervisor_stopped` 등을 기록한다.
모델 종류·SHA-256·벽시각(`wall`)·단조 시각(`monotonic`)을 함께 남긴다.
벽시계 변경에 영향을 받지 않는 경과 시간과 실제 행동 기록 시각을 대조할 수 있다.
단, 과거 raw 프레임의 개별 호스트 도착 시각이 새로 생기는 것은 아니다.

실시간 위상 링버퍼의 상시 배열은 30,024,000바이트(약 28.6MiB)이며,
창 변환 임시 배열·모델·파일 읽기 메모리는 별도다. 전체 파일 재생은 파일 길이에 비례한다.
화면 이력은 제한하지만 원본·JSONL은 실행 시간에 비례해 커진다. 자동 삭제하지 않으며 디스크 여유를 확인한다.

10/10 검증: 전체 테스트 **184개 통과**, GUI·CLI 저장 자료 재생을 실제 자식 프로세스로 확인했다.
10/6 원본의 12지점씩 전체 파일/원본 prefix를 대조한 위상 **24건**에서 입력 최대 오차 **0**,
유효 22건의 점수 최대 오차 **0**이었다. 나머지 2건은 같은 긴 공백으로 양쪽 모두 판단 불가였다.
진폭 12지점도 유효 11건의 점수 오차 **0**이다. 자세한 결과는 [작업 목록 3번](plans/2026-10-08-phase60-introduction.md)에 있다.

## 10. 전제와 미해결

- **첫 실제 전환 시험은 1회만 분석했다.** [10/6 시험 결과](../model_train/docs/model-training/20261006-live-transition-evaluation.md)는
  걷기 첫 반응 약 16·24초, 빈 방 표시 실패, 입력 누락에 따른 판단 정지를 보여준다.
  반복 검증·장시간 오탐·다른 환경의 지연은 아직 미검증이다. §4의 과거 유지 규칙은
  이번 시험에 적용하지 않았다.
- **배포 모델은 9/16·17 추가 평가에서 빈 방·정지 혼동이 남았다.** 15세션 중 12개
  정답이며 [추가 평가 보고서](../model_train/docs/model-training/20260916-17-model-evaluation.md)를
  참고한다. 체크포인트의 이전 상태 문자열은 가중치를 보존해 그대로 두었다.
  연결 자체는 성능 개선을 뜻하지 않으며, 이후 첫 전환 시험에서도 빈 방 혼동이 남았다.
- **피험자 1명·단일 방**이다. 방 일반화는 주장하지 않는다.
- **모델은 모델 담당이 유지한다.** 실시간 경로는 체크포인트의 입력 계약(창·톤 순서·클래스)을
  읽어 검사하며, 전처리나 모델 구조를 자체적으로 바꾸지 않는다.
- **위상 모델의 새 실제 무선 시험은 남아 있다.** 과거 전환 재생에서 앉기 정지 일치율이 0%였다.
  선택 연결을 이유로 기본값을 바꾸거나 안정성 확보를 주장하지 않는다.
